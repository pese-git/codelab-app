# Один запрос без диалога

Режим `-p` (headless) нужен для скриптов и CI: `codelab` отправляет один запрос, печатает ответ и завершается. Глава объясняет, откуда взять запрос, что попадает в stdout и stderr, как задать правило разрешений `--approve`, какие бывают коды выхода и как вызвать `codelab` из скрипта. Оглавление руководства — [руководство пользователя](../user-guide.md).

## Отправить запрос

```bash
codelab -p "Перечисли файлы с тестами"
```

Откуда `codelab` берёт запрос:

| Что задано | Откуда запрос |
|---|---|
| `-p "<текст>"` | сам текст |
| `-f <файл>` | содержимое файла в UTF-8 |
| `-f -` | весь stdin |
| ничего, но stdin перенаправлен | весь stdin: `cat prompt.txt \| codelab` |

- `--timeout 10m` ограничивает время ответа. По истечении `codelab` отменяет ответ, печатает в stderr `codelab: timeout after <N>s, cancelling the turn` и выходит с кодом `130`. Значение — число с единицей `h`, `m` или `s`: `90s`, `10m`, `1h30m`; ноль и число без единицы — ошибка использования.
- Пустой запрос — ошибка `codelab: No prompt.` и код `64`; агент не запускается.
- Мастер настройки провайдера в этом режиме не открывается: конфигурацию подготовьте заранее и проверьте командой `codelab config check`.
- С `--resume <id>` и `--continue` запрос уходит в уже существующую сессию; ранее записанный текст сессии не печатается.

## Что куда печатается

- В stdout попадает только текст ответа агента, без цветов и разметки.
- В stderr идут сообщения об инструментах (`✓ …`, `✗ …`, `⊘ …`: выполнено, сбой, отменён или отклонён), решения по разрешениям, заметки `codelab: …` и ошибки.
- Ошибка использования оставляет stdout пустым.
- `-v` (`--verbose`) добавляет в stderr диагностику соединения.

```bash
codelab -C "$PROJECT_DIR" --approve read-only --timeout 10m -f prompt.md > answer.md 2> run.log
```

Ответ окажется в `answer.md`, а ход работы агента — в `run.log`.

## Разрешения без человека

Никто не отвечает на запросы разрешений, поэтому ответ выбирает правило `--approve`:

| Значение | Что разрешено |
|---|---|
| `reject` (по умолчанию) | ничего: все запросы отклоняются |
| `read-only` | только чтение без повышенного риска |
| `allow-all` | всё, кроме действий, которые агент пометил как критические; при старте печатается предупреждение |

Включайте `allow-all` только в проекте, которому доверяете, и лучше в изолированной среде. Что агент считает опасным и критическим — в [главе о разрешениях](../../../codelab_agent/doc/user/05-permissions.md#критические-действия).

Каждое решение `codelab` записывает в stderr одной строкой:

```text
codelab: warning: --approve allow-all allows every permission request except critical ones without asking
codelab: permission "echo hello": allow_once (policy)
```

Если агент не предложил подходящего варианта ответа, запрос отклоняется, а при отсутствии отклоняющего варианта ход отменяется.

## Коды выхода

| Код | Когда |
|---|---|
| `0` | агент закончил ответ, ответ не пустой |
| `1` | ошибка хода или соединения: ошибка агента или провайдера, пустой ответ, обрыв, агент не запустился |
| `64` | ошибка использования: неверный флаг, нет запроса, неизвестный профиль, несуществующая папка; невалидная конфигурация встроенного агента (например, не настроена модель) |
| `130` | отмена: Ctrl+C (`SIGINT`) или истёкший `--timeout` |
| `143` | завершение по `SIGTERM` |

Примеры ошибок, которые можно получить, если провайдер не отвечает (запрос к недоступному локальному адресу) и если запрос пуст:

```bash
codelab -p "Привет"
```

```text
codelab: request failed after 4 attempts in 5.4 s: attempt 1 network (connection failed: _ClientSocketException); … (network)
```

Код выхода — `1`.

```bash
codelab -p ""
```

```text
codelab: No prompt.
```

Код выхода — `64`.

Таблица кодов для всех режимов и подкоманд — в [эксплуатации](../operations.md#коды-выхода).

## Использовать в скриптах и CI

- Готовьте настройки заранее: `codelab config check` возвращает `0`, если конфигурация годится, и `1`, если есть ошибки.
- Передавайте ключ провайдера переменной окружения (`api_key_env` у провайдера или `CODELAB_SECRET_<ИМЯ>`): файл хранилища и запись секретов для этого не нужны. Подробнее — [секреты](07-secrets.md) и [эксплуатация](../operations.md#секреты).
- Создайте `CODELAB_HOME` заранее с правами `0700`: headless не создаёт его сам с нужными правами — [файлы в эксплуатации](../operations.md#файлы).
- Для CI с несколькими запусками задайте отдельный `CODELAB_HOME`, чтобы сессии и список недавних проектов не смешивались с настройками разработчика.
- Проверяйте код выхода: ответ с кодом `1` не считается успешным, даже если в stdout что-то напечатано.

Подробности для администраторов (окружение, права на файлы, сигналы) — [запуск без участия человека](../operations.md#запуск-без-участия-человека).
