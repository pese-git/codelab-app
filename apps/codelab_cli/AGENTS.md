# AGENTS.md — codelab_cli

Правила этого приложения дополняют корневой `AGENTS.md` и `packages/dart/codelab_client_core/AGENTS.md`.

Источники: `docs/architecture/proposals/dart-agent-and-clients/09-11-stage-6-cli-mvp.md` (задачи 6.1–6.10; подкоманда `config` — абзац «Подкоманды `config`, `provider`, `mcp` и `secret` по этапам»), §12.2 (отображение и ввод CLI), §9.10 (API kit), документ ядра §13 (коды выхода из событий) и §14 (фикстуры); `design.md` OpenSpec change `add-codelab-cli`; для полноэкранного режима — §12.2.7 и `design.md` change `add-cli-tui`; для встроенного агента — `09-12-stage-7-embedded.md` (задача 7.6) и `design.md` change `add-embedded-agent-mode` (D2, D3, D6–D8, D13). Если документов не хватает, сначала дополняется документация, потом пишется код.

## 1. Назначение

`apps/codelab_cli` — терминальный клиент `codelab`: REPL, полноэкранный режим `--ui tui` и headless-режим `codelab -p` поверх `ClientWorkspace` из `codelab_client_core`, драйвер фикстур `codelab test-scenario` и проверка и правка конфигурации встроенного агента `codelab config check|path|get|set|unset`, а также `codelab provider add|list|remove` и `codelab mcp add|list|remove` — без запуска агента, через общие `ConfigCommands`, `ProviderCommands` и `McpServerCommands` моста `codelab_setup`, поэтому вывод, коды и записанные байты `config.yaml` совпадают с `codelab-agent` (design.md change `add-agent-configuration`, D13, D14; change `add-config-writer-and-reload`, D6), а также управление секретами `codelab secret set|delete|list` — тоже без агента, через общий `SecretCommands` моста `codelab_setup` (значение секрета читается только из stdin, вывод и коды совпадают с `codelab-agent secret`; design.md change `add-agent-secret-store`, D8, D15). Агент — внешний процесс или сокет по профилю подключения либо встроенный агент в процессе CLI (`-a embedded`, профиль хоста `embedded-cli`) через мост `codelab_embedded` (design.md change `add-embedded-agent-mode`, D2). Состояния сессий, очереди промптов и одобрений у CLI нет: их владелец — kit; CLI только отображает `SessionView` и вызывает `SessionHandle`.

## 2. Границы

* Чистый Dart: НЕ ДОЛЖЕН импортировать `package:flutter/`, `package:fluent_ui/`, `package:codelab_ui/` и `package:codelab_agent_*` — правило `apps/codelab_cli` в `packages/dart/codelab_architecture_tests/test/support/rules.dart`.
* `dependencies` — только `codelab_client_core`, `codelab_client_io`, `codelab_client_acp`, `codelab_acp_protocol`, `codelab_acp_transports`, `codelab_acp_testing`, `codelab_setup`, `codelab_embedded`, `args`, `async`, `path`, `meta`, `dart_tui` (`cliAllowlist` сторожа). Расширение — только через OpenSpec change.
* `package:codelab_acp_testing/` импортируется только из `lib/src/scenario/` (драйвер фикстур, design.md, D3).
* Мост встроенного агента `codelab_embedded` (design.md change `add-embedded-agent-mode`, D3; правила сторожа):
  * `package:codelab_embedded/io.dart` (`localEmbeddedAgentOpener`) импортируется только из `lib/src/composition_root.dart`;
  * `package:codelab_embedded/testing.dart` (`scriptedEmbeddedAgentOpener`, сценарий модели) — только из `lib/src/scenario/`: единственное место рабочего кода со сценарием — `codelab test-scenario --agent embedded` (D8). Тестовая точка входа e2e передаёт сценарный открыватель через шов `runCodelab(…, embeddedOpener:)` (`lib/src/run.dart`) из `test/`, а не из `lib/`;
  * основной барель `package:codelab_embedded/codelab_embedded.dart` (типы `EmbeddedAgentOpener`, `EmbeddedAgentConfigException`, `Logger`) web-безопасен и сторожем внутри CLI не ограничен; прямой импорт `package:codelab_agent_*` по-прежнему запрещён.
* `package:codelab_setup/io.dart` (мост `ConfigCommands` для `codelab config`, design.md change `add-agent-configuration`, D14; `ProviderCommands` и `McpServerCommands` для `codelab provider` и `codelab mcp`, change `add-config-writer-and-reload`, D6; `SecretCommands` для `codelab secret`, design.md change `add-agent-secret-store`, D15) импортируется только из `lib/src/run.dart` — точки сборки режимов; вместо него прямой импорт `package:codelab_agent_*` запрещён.
* Выбор агента (capability `codelab-cli`, «Профили подключения CLI»; design.md change `add-embedded-agent-mode`, D13, п. 1, 7, 8): `-a embedded` — встроенный агент с профилем хоста `embedded-cli`; без `--agent` — профиль `default` из `profiles.json`, если он там есть, иначе встроенный агент, как с `-a embedded`. Правило одно для REPL, `--ui tui`, `-p` и `test-scenario` — у драйвера фикстур исключения нет. О неявном выборе встроенного агента CLI отдельной строкой не сообщает; профиль виден с `--verbose` и в `/profile`. Битый `profiles.json` (не JSON или неверной структуры) — код `64` с причиной, а не тихий переход на встроенного агента. Внешний агент выбирается явно: `-a stdio:…`, `-a ws://…`, `-a <id>`.
* `embedded` нельзя сохранить профилем (D7): `codelab profiles add <id> embedded` и id `embedded` — код `64` и `embedded is built in; use --agent embedded`, `profiles.json` не меняется. `JsonFileProfileStore` встроенный профиль не пишет и запись `"type": "embedded"` не читает.
* Встроенный агент в CLI (capability `codelab-cli`, «Встроенный агент в CLI»; D5, D6):
  * невалидный конфиг — `EmbeddedAgentConfigException`; `run.dart` печатает его текст (проблемы загрузчика и подсказку `Configure the embedded agent in <home>/config.yaml; check it with: codelab config check`) в stderr, код `64`, stdout пуст; в REPL и в `-p` сообщение одно. Значений секретов в тексте нет (CFG-2);
  * `--debug-secrets` (без значения) и `CODELAB_DEBUG_SECRETS=1` включают событие `secrets.lookup` встроенного агента и выводят его в stderr даже без `--verbose` — поля `name`, `purpose`, `source`, `found`, без значений; на внешнего агента флаг не влияет (design.md change `add-agent-secret-store`, D15; change `add-embedded-agent-mode`, D13, п. 9);
  * остальные логи агента идут в логгер CLI (`lib/src/embedded_logger.dart`): с `--verbose` — в stderr, иначе никуда; stdout headless не засоряется;
  * `EmbeddedTransportResolver` лежит в `lib/src/embedded_transport_resolver.dart` и импортирует только основной барель `codelab_embedded`; `composition_root.dart` лишь связывает его с `localEmbeddedAgentOpener` из `io.dart`. Резолвер сериализует `open`: сначала `await` `dispose()` прежнего агента, затем открыватель. Если подключение отменено — новым `open` или `close()` резолвера, — пока открыватель работает, агент, вернувшийся позже, сразу получает `dispose()` и не становится текущим (`AGENTS.md` §12; D6, «Резолвер клиента»). Отдельного «disconnect» у `ClientWorkspace` нет;
  * выход (конец REPL, `--ui tui`, конец `-p`, `SIGINT`/`SIGTERM`) дожидается `close()` резолвера — `dispose` агента — в `finally`: журнал сессии дописан до завершения процесса. Ожидание ограничено таймаутом 10 с: по истечении — событие `embedded.close_timeout` уровня `warning` в логгер агента и всегда одна строка `codelab: the embedded agent did not stop in <N> s` в stderr. Обработчики сигналов (`watchModeSignals`, шов `SignalSeam` / `runCodelab(signals:)`) снимаются только после `dispose`; сигнал, пришедший во время `dispose`, выходит сразу с `130`/`143` (D6, «Выход CLI»).
* `codelab test-scenario` (capability `cli-scenario-driver`): без `--agent` — выбор как во всём CLI (D13, п. 7); если не сыграна ни одна фикстура (все `SKIP` или пустой фильтр) — код `1` и `codelab: no fixtures were played` в stderr для любого агента (D13, п. 10).
* `codelab config path|get|set|unset`, `codelab provider`, `codelab mcp` (change `add-config-writer-and-reload`, D6; capability `codelab-cli`, «Подкоманда codelab config», «Подкоманды codelab provider и codelab mcp»):
  * листовые подкоманды регистрирует `cli_args.dart`; их `ArgResults` лежит в `CliOptions.subcommand`, опции общих команд собирает `run.dart` (единственное место импорта `codelab_setup/io.dart`). `config get` без `--layer` читает merged;
  * папка проекта — `--cwd` подкоманды (у `config` и у `provider list`, `mcp list`), общий `-C`, текущая; путь передаётся как есть. У `provider add|remove` и `mcp add|remove` своего `--cwd` нет, как у `codelab-agent` (папку задаёт общий `-C/--cwd`);
  * флаги подключения и запроса вместе с подкомандами — `codelab: --<flag> does not apply to <команда>` и код `64`, stdout пуст; `-C` разрешён. Неверное число аргументов и неизвестная подкоманда (`config migrate` — `Unknown command config migrate`) — `64` со справкой подкоманды (`UsageError.usage`). `--project` вместе с `--local` CLI не проверяет: флаги `project`/`local` передаются общему коду как есть, он даёт `64` и `<label>: --project and --local cannot be combined`; допустимые значения `--layer` в парсере — литерал (мост нельзя импортировать из `cli_args.dart`), его равенство `ConfigGetLayer.values` держит тест;
  * ошибка разбора argv у `config set` и `config unset` (слово `set`/`unset` после `config` где угодно в argv) — только `codelab: invalid arguments for config set|unset` и справка `config`: значение `set` может начинаться с `-` (`--sk-…`) и `package:args` процитировал бы его. Ошибки `config check|get|path` по-прежнему называют причину;
  * `CliOptions.positional` у `config|provider|mcp` пуст: аргументы листовой подкоманды — `CliOptions.subcommand` (`name`, `rest`);
  * ошибка разбора argv с `provider` или `mcp` в argv — только `codelab: invalid arguments for provider|mcp` и справка, без текста `package:args`: рядом с флагами идут ключи и заголовки. Ключ провайдера флагом не передаётся: `--api-key-stdin` читает его `StdinSecretInput`, а `--api-key-secret` и `--api-key-env` называют только имя. `provider add` без `--kind`, `--model`, `--context-window` — `64` (мастер на TTY — change `add-provider-setup-ui`);
  * подкоманды не создают `sessions/`, `profiles.json` и `cli_history` и не запускают агента; сбой общей реализации — `codelab: <команда> failed: <тип исключения>` и код `1`. Тест `test/e2e/config_write_command_test.dart` сравнивает с собранным `codelab-agent` код, stdout, stderr и байты файлов `CODELAB_HOME`.
* `codelab secret` (design.md change `add-agent-secret-store`, D8; capability `codelab-cli`, «Подкоманда codelab secret»): флаги подключения и запроса (`-a`, `-m`, `--mode`, `-r`, `-c`, `-p`, `-f`, `--approve`, `--timeout`, `--ui`) и `-C`/`--cwd` вместе с `secret` — ошибка использования `codelab: --<flag> does not apply to secret`, код `64`; любая ошибка разбора argv, если `secret` есть в argv где угодно (в том числе флаг верхнего уровня до `secret`), — только `codelab: invalid arguments for secret` и справка `secret` (`UsageError.showSecretUsage`), без текста `package:args` и присланных слов: среди них может быть значение секрета. `codelab secret` не создаёт `sessions/`, `profiles.json` и `cli_history` в `CODELAB_HOME` и не запускает агента.
* `package:dart_tui/` импортируется только из `lib/src/tui/` (адаптер полноэкранного режима); чистое ядро экрана `lib/src/tui/core/` не импортирует ни пакет, ни `dart:io` (TUI-5) — два правила сторожа, design.md change `add-cli-tui`, D3.
* `dart:io` — только в composition root (в том числе окружение процесса для `localEmbeddedAgentOpener`), точке входа, порте терминала (`IoTerminal`), домашнем каталоге, сигналах, connector драйвера фикстур (design.md, D2) и запуске TUI (`TuiRunner`). Логика — рендер, декодер клавиш, редактор строки, политика одобрений, коды выхода — чистая и тестируется без процессов.
* Домашний каталог CLI — только `CodelabHome.resolve` (design.md change `add-agent-project-files`, D17): `CODELAB_HOME` вида `~` и `~/…` раскрывается в `HOME`, иначе `USERPROFILE`, как у `codelabHomeOf` агента; `~user/…`, `~\…` и тильда без домашнего каталога — `UsageError` (код `64`) с теми же текстами, что у агента. Логика продублирована, потому что CLI не импортирует `codelab_agent_*` (PKG-4); одинаковость проверяют `test/home_test.dart` и `test/config_command_test.dart`.
* В headless stdout несёт только ответ агента; всё остальное — stderr. Ошибка использования оставляет stdout пустым.
* Значение `CODELAB_AGENT_TOKEN` не попадает ни в вывод, ни в `profiles.json`.

## 3. Тесты

* TDD — пары «тест → реализация» (§9.0, правило 3); красный тест коммитится до кода.
* Модульные тесты — `test/` на фейковом терминале и `ClientWorkspace` поверх `FakeAcpTransport` или `InProcessAcpLink`.
* Процессные и PTY-e2e — `test/e2e/` против агента из `CODELAB_E2E_AGENT`: `scripted` — scripted stdio-агент из `codelab_acp_testing` (по умолчанию), `dart` — `codelab-agent serve --stdio`, `python` — Python-агент, `embedded` — встроенный агент (тестовая точка входа `test/e2e/support/embedded_cli_main.dart` со сценарным открывателем; design.md change `add-embedded-agent-mode`, D8); CLI запускается из kernel, скомпилированного один раз. Это интеграционные тесты на Dart VM, они входят в `melos run test` (`AGENTS.md` §21). Имена e2e — id критериев матрицы целей (`cli/<id>`).

## 4. Готовность итерации

По `09-00-migration-plan.md` §9.0, правило 8: критерии строк матрицы итерации зелёные, полный `melos run check` зелёный в CI на `develop` после merge, проверки затронутого (корневой `AGENTS.md` §21) зелёные локально и в CI pull request, документы и код не расходятся, в PR названа следующая итерация по `tasks.md`.
