# AGENTS.md — codelab_cli

Правила этого приложения дополняют корневой `AGENTS.md` и `packages/dart/codelab_client_core/AGENTS.md`.

Источники: `docs/architecture/proposals/dart-agent-and-clients/09-11-stage-6-cli-mvp.md` (задачи 6.1–6.10; подкоманда `config` — абзац «Подкоманды `config`, `provider`, `mcp` и `secret` по этапам»), §12.2 (отображение и ввод CLI), §9.10 (API kit), документ ядра §13 (коды выхода из событий) и §14 (фикстуры); `design.md` OpenSpec change `add-codelab-cli`; для полноэкранного режима — §12.2.7 и `design.md` change `add-cli-tui`; для встроенного агента — `09-12-stage-7-embedded.md` (задача 7.6) и `design.md` change `add-embedded-agent-mode` (D2, D3, D6–D8, D13); для подкоманд `config|provider|mcp` — `design.md` change `add-config-writer-and-reload` (D6). Если документов не хватает, сначала дополняется документация, потом пишется код.

## 1. Назначение

`apps/codelab_cli` — терминальный клиент `codelab`: REPL, полноэкранный режим `--ui tui` и headless-режим `codelab -p` поверх `ClientWorkspace` из `codelab_client_core`, драйвер фикстур `codelab test-scenario` и проверка и правка конфигурации встроенного агента `codelab config check|path|get|set|unset`, а также `codelab provider add|list|remove` и `codelab mcp add|list|remove` — без запуска агента, через общие `ConfigCommands`, `ProviderCommands` и `McpServerCommands` моста `codelab_setup`, поэтому вывод, коды и записанные байты `config.yaml` совпадают с `codelab-agent` (design.md change `add-agent-configuration`, D13, D14; change `add-config-writer-and-reload`, D6), а также управление секретами `codelab secret set|delete|list` — тоже без агента, через общий `SecretCommands` моста `codelab_setup` (значение секрета читается только из stdin, вывод и коды совпадают с `codelab-agent secret`; design.md change `add-agent-secret-store`, D8, D15). Агент — внешний процесс или сокет по профилю подключения либо встроенный агент в процессе CLI (`-a embedded`, профиль хоста `embedded-cli`) через мост `codelab_embedded` (design.md change `add-embedded-agent-mode`, D2). Состояния сессий, очереди промптов и одобрений у CLI нет: их владелец — kit; CLI только отображает `SessionView` и вызывает `SessionHandle`.

Расширение — только через OpenSpec change.
* `package:codelab_acp_testing/` импортируется только из `lib/src/scenario/` (драйвер фикстур, design.md, D3).
* Мост встроенного агента `codelab_embedded` (design.md change `add-embedded-agent-mode`, D3; правила сторожа):
  * `package:codelab_embedded/io.dart` (`localEmbeddedAgentOpener`) импортируется только из `lib/src/composition_root.dart`;
  * `package:codelab_embedded/testing.dart` (`scriptedEmbeddedAgentOpener`, сценарий модели) — только из `lib/src/scenario/`: единственное место рабочего кода со сценарием — `codelab test-scenario --agent embedded` (D8). Тестовая точка входа e2e передаёт сценарный открыватель через шов `runCodelab(…, embeddedOpener:)` (`lib/src/run.dart`) из `test/`, а не из `lib/`;

* `package:codelab_setup/io.dart` (мост `ConfigCommands` для `codelab config`, design.md change `add-agent-configuration`, D14; `ProviderCommands` и `McpServerCommands` для `codelab provider` и `codelab mcp`, change `add-config-writer-and-reload`, D6; `SecretCommands` для `codelab secret`, design.md change `add-agent-secret-store`, D15) импортируется только из `lib/src/run.dart` — точки сборки режимов; вместо него прямой импорт `package:codelab_agent_*` запрещён.
* Выбор агента (capability `codelab-cli`, «Профили подключения CLI»; design.md change `add-embedded-agent-mode`, D13, п. 1, 7, 8): `-a embedded` — встроенный агент с профилем хоста `embedded-cli`; без `--agent` и с `-a default` — тоже встроенный агент (design.md change `add-app-settings-shell`, D21). Без `--agent` и с `-a embedded` `profiles.json` не читается. При `-a default` запись из файла для выбора агента не используется: файл читается только ради предупреждения о старой записи `default`, и любая ошибка этого чтения игнорируется. Id `embedded` и `default` зарезервированы (`reservedProfileIds` kit): `profiles add default …` — код `64`; прежняя запись `default` в `profiles.json` игнорируется с одним предупреждением в stderr при `profiles list`, `profiles show default` и `-a default`, удаляется `profiles remove default`. Правило одно для REPL, `--ui tui`, `-p` и `test-scenario` — у драйвера фикстур исключения нет. О неявном выборе встроенного агента CLI отдельной строкой не сообщает; профиль виден с `--verbose` и в `/profile`. Битый `profiles.json` (не JSON или неверной структуры) — код `64` с причиной только при `-a <id>` и в `codelab profiles …`. Внешний агент выбирается явно: `-a stdio:…`, `-a ws://…`, `-a <id>`.
* `embedded` нельзя сохранить профилем (D7): `codelab profiles add <id> embedded` и id `embedded` — код `64` и `embedded is built in; use --agent embedded`, `profiles.json` не меняется. `JsonFileProfileStore` встроенный профиль не пишет и запись `"type": "embedded"` не читает.
* Встроенный агент в CLI (capability `codelab-cli`, «Встроенный агент в CLI»; D5, D6):
  * невалидный конфиг — `EmbeddedAgentConfigException`; `run.dart` печатает его текст (проблемы загрузчика и подсказку `Configure the embedded agent in <home>/config.yaml; check it with: codelab config check`) в stderr, код `64`, stdout пуст; в REPL и в `-p` сообщение одно. Значений секретов в тексте нет (CFG-2);
  * `--debug-secrets` (без значения) и `CODELAB_DEBUG_SECRETS=1` включают событие `secrets.lookup` встроенного агента и выводят его в stderr даже без `--verbose` — поля `name`, `purpose`, `source`, `found`, без значений; на внешнего агента флаг не влияет (design.md change `add-agent-secret-store`, D15; change `add-embedded-agent-mode`, D13, п. 9);
  * остальные логи агента идут в логгер CLI (`lib/src/embedded_logger.dart`): с `--verbose` — в stderr, иначе никуда; stdout headless не засоряется;
  * `EmbeddedTransportResolver` лежит в `lib/src/embedded_transport_resolver.dart` и импортирует только основной барель `codelab_embedded`; `composition_root.dart` лишь связывает его с `localEmbeddedAgentOpener` из `io.dart`. Резолвер сериализует `open`: сначала `await` `dispose()` прежнего агента, затем открыватель. Если подключение отменено — новым `open` или `close()` резолвера, — пока открыватель работает, агент, вернувшийся позже, сразу получает `dispose()` и не становится текущим (`AGENTS.md` §12; D6, «Резолвер клиента»). Отдельного «disconnect» у `ClientWorkspace` нет;
  * выход (конец REPL, `--ui tui`, конец `-p`, `SIGINT`/`SIGTERM`) дожидается `close()` резолвера — `dispose` агента — в `finally`: журнал сессии дописан до завершения процесса. Ожидание ограничено таймаутом 10 с: по истечении — событие `embedded.close_timeout` уровня `warning` в логгер агента и всегда одна строка `codelab: the embedded agent did not stop in <N> s` в stderr. Обработчики сигналов (`watchModeSignals`, шов `SignalSeam` / `runCodelab(signals:)`) снимаются только после `dispose`; сигнал, пришедший во время `dispose`, выходит сразу с `130`/`143` (D6, «Выход CLI»).
* `codelab test-scenario` (capability `cli-scenario-driver`): без `--agent` — выбор как во всём CLI (D13, п. 7); если не сыграна ни одна фикстура (все `SKIP` или пустой фильтр) — код `1` и `codelab: no fixtures were played` в stderr для любого агента (D13, п. 10).
  * `--junit <файл>` пишет JUnit XML прогона (`lib/src/scenario/junit_report.dart`, чистая функция без IO и без пакета `xml`; capability `cli-scenario-driver`, «JUnit-отчёт test-scenario»; design.md change `switch-default-agent-to-dart`, D8): путь проверяется на запись до запуска первого агента (нельзя — код `64`, `codelab: cannot write --junit <путь>: <текст ОС>`, агент не запускается; проверочный файл удаляется сразу), файл пишется после последней фикстуры в том числе при `FAIL`, сбое запуска агента и «не сыграна ни одна» (пустой `testsuite`); прерывание сигналом файл не пишет. Тексты `failure` и `skipped` — те же строки, что в stdout, значения аргументов stdio-профиля и путь `{fixture}` в файл не попадают (D16). Импорт `package:codelab_acp_testing/` — по-прежнему только из `lib/src/scenario/`
* `codelab config path|get|set|unset`, `codelab provider`, `codelab mcp` (change `add-config-writer-and-reload`, D6; capability `codelab-cli`, «Подкоманда codelab config», «Подкоманды codelab provider и codelab mcp»):
  * листовые подкоманды регистрирует `cli_args.dart`; их `ArgResults` лежит в `CliOptions.subcommand`, опции общих команд собирает `run.dart` (единственное место импорта `codelab_setup/io.dart`). `config get` без `--layer` читает merged;
  * папка проекта — `--cwd` подкоманды (у `config` и у `provider list`, `mcp list`), общий `-C`, текущая; путь передаётся как есть. У `provider add|remove` и `mcp add|remove` своего `--cwd` нет, как у `codelab-agent` (папку задаёт общий `-C/--cwd`);

Неверное число аргументов и неизвестная подкоманда (`config migrate` — `Unknown command config migrate`) — `64` со справкой подкоманды (`UsageError.usage`). `--project` вместе с `--local` CLI не проверяет: флаги `project`/`local` передаются общему коду как есть, он даёт `64` и `<label>: --project and --local cannot be combined`; допустимые значения `--layer` в парсере — литерал (мост нельзя импортировать из `cli_args.dart`), его равенство `ConfigGetLayer.values` держит тест;
  * ошибка разбора argv у `config set` и `config unset` (слово `set`/`unset` после `config` где угодно в argv) — только `codelab: invalid arguments for config set|unset` и справка `config`: значение `set` может начинаться с `-` (`--sk-…`) и `package:args` процитировал бы его. Ошибки `config check|get|path` по-прежнему называют причину;
  * `CliOptions.positional` у `config|provider|mcp` пуст: аргументы листовой подкоманды — `CliOptions.subcommand` (`name`, `rest`);
  * ошибка разбора argv с `provider` или `mcp` в argv — только `codelab: invalid arguments for provider|mcp` и справка, без текста `package:args`: рядом с флагами идут ключи и заголовки. Ключ провайдера флагом не передаётся: `--api-key-stdin` читает его `StdinSecretInput`, а `--api-key-secret` и `--api-key-env` называют только имя. `provider add` без `--kind`, `--model`, `--context-window` — `64` (мастер на TTY — change `add-provider-setup-ui`);

Тест `test/e2e/config_write_command_test.dart` сравнивает с собранным `codelab-agent` код, stdout, stderr и байты файлов `CODELAB_HOME`.
* `codelab secret` (design.md change `add-agent-secret-store`, D8; capability `codelab-cli`, «Подкоманда codelab secret»): флаги подключения и запроса (`-a`, `-m`, `--mode`, `-r`, `-c`, `-p`, `-f`, `--approve`, `--timeout`, `--ui`) и `-C`/`--cwd` вместе с `secret` — ошибка использования `codelab: --<flag> does not apply to secret`, код `64`; любая ошибка разбора argv, если `secret` есть в argv где угодно (в том числе флаг верхнего уровня до `secret`), — только `codelab: invalid arguments for secret` и справка `secret` (`UsageError.showSecretUsage`), без текста `package:args` и присланных слов: среди них может быть значение секрета. `codelab secret` не создаёт `sessions/`, `profiles.json` и `cli_history` в `CODELAB_HOME` и не запускает агента. `codelab secret migrate [--all | [--project] [--local]] [--cwd <dir>] [--dry-run] [--force]` (design.md change `add-config-literal-secrets-and-migrate`, D7) вызывает `SecretCommands.migrate` через `codelab_setup/io.dart`: его `--cwd` — флаг подкоманды (общий `-C/--cwd` с `secret` по-прежнему `64`), stdin не читается, строка о 1.0 в справке `secret` и `codelab --help` — `before1Note` из основного бареля `codelab_setup` (`cli_args.dart` не импортирует `codelab_setup/io.dart`, D13). `codelab mcp add --header-stdin|--env-stdin|--header-scheme` читает ОДНО значение из stdin (скрыто на терминале) и пишет в файл только ссылку `${secret:…}` (D11).
* `package:dart_tui/` импортируется только из `lib/src/tui/` (адаптер полноэкранного режима); чистое ядро экрана `lib/src/tui/core/` не импортирует ни пакет, ни `dart:io` (TUI-5) — два правила сторожа, design.md change `add-cli-tui`, D3.
* `dart:io` — только в composition root (в том числе окружение процесса для `localEmbeddedAgentOpener`), точке входа, порте терминала (`IoTerminal`, `SharedStdin`), домашнем каталоге, сигналах, connector драйвера фикстур (design.md, D2) и запуске TUI (`TuiRunner`); исключение — тип `ProcessException` (`show`) в `describeStartFailure` (`session_setup.dart`) для второй линии D9 change `redact-cli-stdio-profile-args`. Агентский `codelabHomeOf` остаётся отдельным, потому что CLI не импортирует `codelab_agent_*` (PKG-4); одинаковость проверяют `test/home_test.dart` и `test/config_command_test.dart`.
* В headless stdout несёт только ответ агента; всё остальное — stderr. Ошибка использования оставляет stdout пустым.
* Значение `CODELAB_AGENT_TOKEN` не попадает ни в вывод, ни в `profiles.json`. Токен WebSocket-профиля берёт общий `ProfileSecretSource` kit (`env:<NAME>`, D15); собственного источника секретов у CLI нет.
* Значения аргументов stdio-профиля не печатаются нигде — ни в ошибках запуска и подключения, ни в `/profile`, `profiles list|show`, ни в ошибке разбора `stdio:…`: только команда и число аргументов (`"my-agent" with 3 arguments`, `args: 3 (values hidden)`); значения видны только в `profiles.json`. Ошибки выбора профиля (`Unknown agent profile`, `Invalid agent` у `profiles add`) не повторяют значение `--agent`: без префикса `stdio:` оно может быть командной строкой с токеном. Причина сбоя запуска процесса в журнале `--verbose` и в строке `FAIL` `test-scenario` тоже без аргументов: транспорт отдаёт `ProcessException` без `arguments`, а `_play` печатает только `ProcessException.message` (design.md change `redact-cli-stdio-profile-args`, D1–D4, D6, D8, D9).

Профиль `secret:` без значения (`ProfileSecretSource.isSecretMissing`, проверка через `isSet`) перед подключением REPL, TUI, headless и `test-scenario` даёт в stderr `codelab: the token secret of profile <id> is not set; connecting without a token.`, а с `--verbose` ещё и событие `connection_profile.token_secret_missing` (поле `profile_id`); `test-scenario` читает `secret:` из того же хранилища (`ScenarioAgent(profileSecrets:)`). Мастер, первый запуск, `/provider` и `/settings` — итерация 4.
* Мастер провайдера, первый запуск, `/provider` и `/settings` (change `add-provider-setup-ui`, D15–D17; capability `codelab-cli`, «Мастер первого запуска CLI», «Команды /provider и /settings в REPL и TUI», «Подкоманды codelab provider и codelab mcp»; итерация 4a):

Слой 3 клиенты не пишут (SETUP-3), `--project` с клиентскими флагами и с мастером — `64`;
  * один владелец stdin на процесс: `run.dart` создаёт `SharedStdin` (`lib/src/input/shared_stdin.dart`, одна подписка на `io.stdin`, пауза без слушателей) и отдаёт его `stream` в `IoTerminal(input:)` и `TuiRunner(input:)` (`withInput`): мастер первого запуска и следующий за ним REPL или TUI читают один терминал, отмена подписки не закрывает fd 0. Первый запуск вызывает `run.dart` (`_firstRun` в `_runRepl` и `_runTui`, до `buildCliRuntime`), а не `composition_root.dart`; в `-p`, без терминала и для внешних агентов готовность не вычисляется (SETUP-7);
  * `/provider` и `/settings` — в `replCommands`; TUI 4a остаётся на `mvpReplCommands` (оверлеи — 4b). В REPL клавиши мастера идут из подписки `Repl` (`_wizard`), второй подписки на `Terminal.input` нет; Ctrl+C и Esc закрывают только мастер, в `Saving` игнорируются; во время хода и без терминала мастер не открывается. Для `RemoteReadOnly` и `NotManaged` (`resolveSettingsAccess` профиля подключения) команды печатают строку §12.4.8, шаг 3, и порт не вызывают;
  * значение ключа живёт только в `SecretValue` автомата и в буфере поля; в вывод, `cli_history` и журнал попадает маска.
* Модальные экраны `--ui tui` (change `add-provider-setup-ui`, D17, D21; capability `codelab-tui` «Кадр TUI», «Одобрение в TUI»; итерация 4b):
  * `TuiModel.overlay` — закрытая иерархия `TuiOverlay` (`lib/src/tui/core/tui_overlay.dart`): `PickerOverlay` (клавиши по-прежнему у адаптера `TuiApp`/`ListModel`), `ProviderWizardOverlay` (мастер `/provider add`) и `SettingsOverlay` (экран `/settings`). Клавиши и вставка (`KeyMsg`, `PasteMsg`) двух модальных оверлеев идут в `reduce` ядра раньше зоны одобрения и композера (`overlay_update.dart`): Enter не отправляет промпт, Esc и Ctrl+C закрывают экран (мастеру уходит `WizardEventCmd(Cancel)`, закрытие — по `WizardStateMsg(Cancelled)` от автомата), ход не отменяется; `Saving` блокирует Esc (D21). Ожидающее одобрение показывает статус-строка (`approval pending · esc to answer`), зона одобрения вернётся после закрытия экрана;
  * тексты шагов мастера — только `wizardStepOf` (`lib/src/setup/wizard_steps.dart`), поле ввода — `LineField` (`line_field.dart`), запись настроек и слой записи — `applySetting`/`settingWriteLayerOf` (`settings_rows.dart`): у оверлея своих текстов и своих проверок нет. Ядро экрана `lib/src/tui/core/` остаётся без `dart_tui` и `dart:io` (TUI-5, сторож `melos run guard`);
  * значение секрета в кадре — только маска `*` (Ctrl+R показывает и прячет, Ctrl+U очищает, многострочная вставка и значение длиннее `maxKeyBytes` — `keyRejectedLine`); оно живёт только в буфере поля оверлея и в `SecretValue` события `KeySubmitted`, буфер очищается в той же `reduce`, что отправляет шаг, при `Cancel`, переходе в `Checking` и закрытии;
  * адаптер: `TuiCommandContext.runWizard` — единственный владелец подписки на `flow.states` (сообщения `OpenWizardMsg`/`WizardStateMsg` с номером оверлея, поздние состояния чужого номера игнорируются), отменяет подписку и вызывает `flow.dispose()` на любом выходе, в том числе при `close()` контекста; `showSettings(SettingsScreen)` открывает `SettingsOverlay`, запись идёт командой `ApplySettingCmd` → `applySettingFor` → `SettingsAppliedMsg` с новым снимком. `turnRunning` в TUI остаётся `false`: отказ Q14 относится только к построчному REPL. TUI использует `replCommands`; `ctrl+r` в `TuiInput` — `Key.ctrlR`;
  * экран `/settings` в TUI показывает только ключи реестра со `scope: shared`; карты и списки отображений (`map`/`mapList`) только для чтения (Enter — подсказка), списки правятся полем через `parseCliValue` (Q16 (а)); для чужого агента экран открывается только для чтения.
