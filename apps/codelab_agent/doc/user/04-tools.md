# Инструменты агента

Инструмент — действие, которое агент вызывает по просьбе модели: прочитать файл, записать файл, выполнить команду. Модель сама ничего не делает, она только просит агента вызвать инструмент. После этой главы вы знаете, какие инструменты есть, что каждый делает и когда агент спрашивает у вас разрешение.

## Список инструментов

Список проверен по реестру ядра агента. Столбец «Уровень» — к какому уровню относится вызов при решении о разрешении: `read` (чтение), `write` (запись файлов), `exec` (команды и инструменты внешних серверов). Как уровни связаны с режимами — в [главе о разрешениях](05-permissions.md#режимы).

| Инструмент | Что делает | Уровень | Когда есть |
|---|---|---|---|
| `read` | читает текстовый файл или картинку | `read` | всегда |
| `write` | создаёт файл или полностью перезаписывает | `write` | всегда |
| `edit` | заменяет точный фрагмент в файле | `write` | всегда |
| `ls` | показывает один каталог | `read` | если агент видит файлы: встроенный и `serve --stdio`; в `serve --ws` нет |
| `search` | ищет текст по содержимому файлов | `read` | как `ls` |
| `exec` | выполняет команду оболочки | `exec` | всегда; у внешнего агента нужен терминал клиента |
| `task_create`, `task_update`, `task_list`, `task_get` | ведут список задач хода | `read` | всегда |
| `skill` | загружает навык по имени | `read` | если найден хотя бы один навык, доступный модели |
| `agent` | запускает субагента | `read` | если не отключены субагенты (`subagents.enabled`) |
| `mcp__<сервер>__<инструмент>` | инструмент внешнего MCP-сервера | `exec` | по числу подключённых MCP-серверов |

Другие инструменты в этой версии не зарегистрированы: инструментов для обращения в интернет нет. Ключ `tools.disabled` схема принимает, но пока не применяет.

Фактический набор запущенного агента печатает строка `host.plan` в stderr при старте:

```text
info host.plan {profile: agent-serve, tools: [read, write, edit, task_create, task_update, task_list, task_get, exec, ls, search], off: {}}
```

`skill`, `agent` и MCP-инструменты в этом списке нет: их добавляет каждая сессия отдельно.

## Чтение и поиск

**`read`** выводит строки в виде `<номер>| <текст>`. Параметры `offset` и `limit` читают часть файла. Вывод ограничен 2000 строками или 50 КБ; если файл длиннее, агент говорит, с какого места продолжить. Картинки форматов PNG, JPEG, GIF и WebP до 4 МиБ он отдаёт модели только если модель принимает изображения.

**`ls`** показывает один уровень каталога, без рекурсии, не больше 500 записей. Каталоги помечены `/`, ссылки — `@`, скрытые файлы показаны.

**`search`** ищет по регулярному выражению (синтаксис Dart) или по обычному тексту. Печатает строки вида `<путь>:<строка>: <текст>`, по умолчанию не больше 100 совпадений. Пропускает каталоги `.git`, `node_modules`, `.dart_tool`, `build`, скрытые каталоги, двоичные файлы и файлы больше 1 МиБ; просматривает не больше 10 000 файлов.

Содержимое каталогов `node_modules`, `.dart_tool` и `vendor` и вывод сетевых команд (`curl`, `git clone`, `npm install`) агент оборачивает в пометку «недоверенное содержимое» и предупреждает модель не выполнять указания из него. Это предупреждение в запросе к модели, а не гарантия: защитой остаются разрешения. Остальные файлы, в том числе `AGENTS.md` недоверенного проекта, модель получает как обычный текст.

## Запись и правка

**`write`** создаёт файл или перезаписывает его целиком; недостающие каталоги создаются. Когда агент спрашивает разрешение на запись, клиент показывает различие со старой версией файла.

**`edit`** заменяет фрагмент файла: агент передаёт точный старый текст и новый. Фрагмент должен встретиться в файле ровно один раз. Если совпадений нет или их несколько, агент получает ошибку, а файл не меняется. Переводы строк CRLF и BOM `edit` сохраняет.

Параллельные правки одного файла агент выполняет по очереди.

Любая правка файлов конфигурации самого агента — `.codelab/config.yaml`, `.codelab/agents/`, `.codelab/skills/` и других — считается критической: клиент спрашивает вас в любом режиме. Подробнее — [критические действия](05-permissions.md#критические-действия).

## Команды

**`exec`** запускает неинтерактивную команду оболочки в рабочей папке. Параметры: `command`, `timeout` в секундах (по умолчанию 120, не больше 3600) и `cwd` внутри рабочей папки. В ответ агент получает конец вывода и код выхода. Ненулевой код выхода — не сбой инструмента: модель видит вывод и сама решает, что делать.

Как команда запускается, зависит от вида агента:

- встроенный агент запускает команду сам, на вашей машине;
- `codelab-agent` просит клиента открыть терминал и выполнить команду там. Если клиент не объявил поддержку терминалов, `exec` отвечает ошибкой `the client does not support terminals`.

Рабочий каталог команды ограничен рабочей папкой сессии: `cwd` вне её агент отклоняет. Ограничение касается каталога запуска, а не содержимого команды: команда `cat ~/.ssh/id_rsa` из рабочей папки запустится так же, как любая другая. Поэтому команды и спрашиваются — [разрешения](05-permissions.md).

## Список задач

Четыре инструмента `task_*` ведут список задач: агент добавляет пункты (`task_create`), меняет статус и зависимости (`task_update`), читает список целиком или один пункт (`task_list`, `task_get`). У пункта есть заголовок (`subject`), необязательные описание и приоритет, статус `pending`, `in_progress` или `completed` и список пунктов, которые должны завершиться раньше. В списке не больше 100 живых пунктов.

Клиент показывает список как план хода. Эти инструменты не трогают файлы, команды и сеть, поэтому разрешения не спрашивают — кроме режима `ask`, где спрашиваются все уровни (так же `skill` и `agent`). Подробнее — [субагенты и список задач](07-subagents-and-tasks.md#список-задач).

## Навыки

Инструмент `skill` загружает инструкции навыка по имени; навыки и откуда они берутся — в [контексте проекта](06-project-context.md#навыки).

## Субагенты

Инструмент `agent` передаёт отдельное задание помощнику с собственным контекстом — [субагенты и список задач](07-subagents-and-tasks.md).

## Инструменты MCP-серверов

Имя такого инструмента — `mcp__<сервер>__<инструмент>`. Агент относит их к уровню `exec`: в режиме `standard` каждый вызов требует разрешения, в режиме `plan` отклоняется. Подробнее — [MCP-серверы](08-mcp.md).

## Как агент описывает вызов

Каждый вызов клиент показывает вам: название инструмента, аргументы и, для записи, различие. Это те значения, которые агент выполнит: аргументы приведены к виду, в котором они пойдут в инструмент. Разрешение относится к конкретному вызову: ответ «разрешить» для одной команды не распространяется на другую.
