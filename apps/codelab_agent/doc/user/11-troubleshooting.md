# Если что-то пошло не так

Здесь — сообщения агента, которые видит пользователь, их причины и что делать. Таблицы собраны из реальных запусков и из кода агента. Проблемы сборки, портов, прав на файлы и значения кодов выхода для оператора — в [эксплуатации](../operations.md). Что мешает при разработке и тестировании агента — в [частых проблемах разработчика](../troubleshooting.md).

Сначала полезно проверить настройки:

```bash
codelab-agent config check
```

Команда читает конфигурацию так же, как агент, и показывает источники, ошибки и предупреждения с файлом и строкой.

## Запуск и подключение

| Что видите | Почему | Что сделать |
|---|---|---|
| `agent.default_model: no model is configured; add a provider with at least one model` | в конфигурации нет провайдера с моделью | `codelab-agent provider add …` — [подключить модель](01-install-and-run.md#подключить-модель) |
| `serve` завершается кодом `64`, в stderr `serve.config.invalid` | конфигурация невалидна | `codelab-agent config check` покажет файл, строку и ключ |
| `--ws needs a Bearer token in CODELAB_AGENT_TOKEN; the server does not start without it` | для `serve --ws` не задан токен | задайте `CODELAB_AGENT_TOKEN` или переменную из `--token-env` |
| клиент по сети получает `401` | токен не передан или неверный; в stderr `serve.ws.unauthorized` | передайте заголовок `Authorization: Bearer <token>` с тем же значением |
| клиент по сети получает `426` | запрос без WebSocket upgrade | подключайтесь по `ws://`, а не по обычному HTTP |
| `serve.ws.bind_failed`, код `1` | порт занят или адрес недоступен | другой `--port`; `--port 0` — система выберет свободный, он будет в `serve.ws.listening` |
| агент не появляется в Zed | Zed не нашёл программу или она сразу завершилась | абсолютный путь в настройках; запустите ту же команду в терминале — [Zed](../../../../docs/user/zed.md#если-что-то-не-работает) |
| `codelab-agent serve --stdio` ничего не печатает | так и должно быть: агент ждёт сообщения клиента на stdin | запускайте его из клиента или закройте stdin (`Ctrl+D`) |
| предупреждение `the environment variable with the API key is not set` | `api_key_env` указывает на переменную, которой нет у процесса агента | задайте её там, где запускается агент; Zed и app, запущенные из меню, не видят переменных оболочки — используйте секрет — [ключ API](../../../../docs/user/configuration.md#шаг-2-задайте-ключ-api) |
| `note: restart the agent to apply: <ключ>` после `config set` | ключ действует только после перезапуска | перезапустите агента; в app — «Restart agent» |
| `the global permissions changed after the agent started; restart the agent to open sessions in this folder` | вы изменили глобальные `permissions`, а в папке есть свой `.codelab/config.yaml` | перезапустите агента — [почему](../../../../docs/user/configuration.md#правки-после-перезапуска-и-сессии-других-папок) |

## Разрешения и рабочая папка

| Что видите | Почему | Что сделать |
|---|---|---|
| `Permission denied for write: plan mode: changes are not allowed` | сессия в режиме `plan` | смените режим: `/mode standard` — [режимы](05-permissions.md#режимы) |
| `Permission denied for <инструмент>: denied by configuration` | запрет в `permissions.deny` или `permissions.tools` | уберите запись, если запрет случайный — [свои правила](05-permissions.md#своё-правило-для-инструмента) |
| `Permission denied for <инструмент>: previously rejected by the user` | вы ответили «отклонять всегда» на такой же вызов | откройте новую сессию: решение живёт до её закрытия |
| `Permission denied for <инструмент>: no approval interface is available` | клиент не умеет показывать вопросы | подключитесь клиентом с поддержкой разрешений или смените режим на тот, где вопрос не нужен |
| `Permission denied for exec: critical command blocked in autopilot: <метка>` | критическая команда в режиме `autopilot` | выполните её сами или запустите агента не в `autopilot` |
| `Editing agent configuration requires a human: <путь>` | модель попыталась изменить конфигурацию агента без человека | правьте файл сами — [критические действия](05-permissions.md#критические-действия) |
| `Path is outside the workspace: <путь>` | файловый инструмент получил путь вне рабочей папки сессии или `exec` — `cwd` вне неё | откройте сессию в нужной папке. Файловые инструменты не принимают пути вне папки; команды `exec` ограничены только каталогом запуска, их содержимое подтверждаете вы — [рабочая папка](05-permissions.md#рабочая-папка) |
| `the client does not support terminals` | клиент не объявил поддержку терминалов, а `codelab-agent` запускает команды через терминал клиента | используйте клиент с терминалом или встроенный агент |
| `Unknown mode: autopilot. Available: plan, ask, standard, accept-edits, bypass.` | `autopilot` включается только флагом запуска | `codelab-agent serve --permission-mode autopilot` |
| `/mode` отвечает `Mode: …`, но агент всё равно не спрашивает | агент запущен с `--permission-mode autopilot`: флаг перекрывает селектор, `/mode` и `permissions.mode`, а `/status` показывает выбранный, а не действующий режим | перезапустите агента без флага — [режимы](05-permissions.md#режимы) |

Отказ агент возвращает модели как данные, и ход продолжается: модель обычно предлагает другой путь.

## Модель и ход

| Что видите | Почему | Что сделать |
|---|---|---|
| `Unknown model: <имя>. Run /status to see the current model.` | такой модели нет в конфигурации | проверьте `providers.<id>.models` и `/status` |
| `The model reached its token limit, so the turn ended.` (заметка клиента) | ответ модели упёрся в `max_output_tokens`; у моделей с рассуждением лимит расходуется ещё и на рассуждение | увеличьте `max_output_tokens` в записи модели — [настройка](../../../../docs/user/configuration.md#шаг-1-подключите-провайдера-и-модель) |
| `The turn stopped: budget exceeded: <лимит>.` (заметка клиента; стоп-причина ACP `max_turn_requests`) | исчерпан бюджет хода: `budget.max_steps` (по умолчанию 50), `budget.max_tokens`, `budget.max_cost` или `budget.max_duration` | повторите запрос или увеличьте лимит — [лимиты хода](03-model-and-providers.md#лимиты-хода) |
| в stderr `warning llm.catalog.default_used` | у модели нет записи о размере окна и лимите ответа во встроенном каталоге, агент взял умолчания | задайте `context_window` и `max_output_tokens` в `providers.<id>.models.<модель>` |
| `Unknown command: /<слово>. Run /help to list commands.` | такой команды нет у агента: нет шаблона, навыка или встроенной | `/help` — список; для шаблона проверьте [доверие к проекту](06-project-context.md#доверие-к-проекту) |

## Контекст проекта, навыки, MCP

| Что видите | Почему | Что сделать |
|---|---|---|
| `the project is not trusted; add it to trusted_projects` | шаблоны команд, агенты и навыки проекта читаются только из доверенного проекта | [добавьте проект в `trusted_projects`](06-project-context.md#доверие-к-проекту) и перезапустите агента |
| шаблона, агента или навыка нет в списке | файл с ошибкой пропущен: неверное имя, нет `description`, не UTF-8, больше 64 КиБ (`SKILL.md` — 128 КиБ) | `codelab-agent config check` печатает причину; после правки откройте новую сессию |
| `CLAUDE.md is ignored: AGENTS.md exists at the same level` | на одном уровне есть оба файла | так и задумано: агент читает `AGENTS.md` |
| в `serve --ws` нет `AGENTS.md`, навыков, MCP, `ls` и `search` | режим по сети намеренно сужен | [таблица в обзоре](00-overview.md#три-способа-запустить-агента) |
| `mcp.server.failed … spawn failed: No such file or directory` | команда `stdio`-сервера не найдена | проверьте `command` и `PATH` процесса агента; `/mcp list` покажет состояние, `/mcp reload` повторит подключение |
| `MCP server <имя> is not connected (retry in <n>s). Continue without it or try later.` | сервер упал или ещё подключается; агент повторяет попытки с растущей паузой | подождите или `/mcp reload`; причина — в столбце `LAST ERROR` команды `/mcp list` |
| сервер отключён с `tool name collision: <имя>` | инструмент сервера называется так же, как встроенный или как инструмент другого сервера | переименуйте инструмент на стороне сервера или отключите лишний сервер |

## Сессии

| Что видите | Почему | Что сделать |
|---|---|---|
| после продолжения сессии агент снова спрашивает про то, что вы разрешили «всегда» | решения «всегда» не записываются в журнал | это ожидаемо |
| вызов инструмента в конце сессии помечен «прерван» | агент остановился посреди вызова | перечитайте состояние: команда могла выполниться наполовину — [продолжить сессию](09-sessions.md#продолжить-сессию) |
| рядом с журналом появился `….jsonl.corrupt` | в журнале были повреждённые строки; агент вынес их и открыл остальное | сессия работает; файл можно удалить, когда он не нужен |

Не нашли своего случая: в [эксплуатации](../operations.md#логи-и-диагностика) описано, как включить подробный лог (`--log-level debug`), а в [данных и логах](10-data-and-logs.md#что-попадает-в-логи-и-журналы) — как не раскрыть лишнего при пересылке логов.
