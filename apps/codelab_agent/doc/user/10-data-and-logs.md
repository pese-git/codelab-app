# Данные и логи

Агент хранит на диске конфигурацию, секреты, журналы сессий и, если вы попросите, файл лога. После главы вы знаете, что где лежит и что из этого может содержать ваши данные.

## Что где лежит

Каталог `CODELAB_HOME` по умолчанию — `~/.codelab`. Раскладку каталога и правила его выбора описывает [каталог `CODELAB_HOME`](../../../../docs/ops/codelab-home.md); общие переменные — [переменные окружения](../../../../docs/ops/environment.md). Здесь — только то, что пишет сам агент.

| Что | Где | Когда появляется |
|---|---|---|
| Журналы сессий | `$CODELAB_HOME/sessions/<папка-проекта>/…jsonl`; другой корень — ключ `sessions.dir` | при первой сессии — [сессии](09-sessions.md#где-лежат-сессии) |
| Расход токенов сессии | каталог данных рядом с журналом, файл `usage.json` | в сессии без запросов к модели каталога нет |
| Последняя выбранная модель | `$CODELAB_HOME/state/last-model.json` | когда вы явно выбрали модель |
| Конфигурация | `$CODELAB_HOME/config.yaml`; в проекте — `.codelab/config.yaml`, `.codelab/config.local.yaml` | вы или команды `config`, `provider`, `mcp` — [слои конфигурации](../../../../docs/user/configuration.md#слои-конфигурации) |
| Секреты | `$CODELAB_HOME/secrets.yaml`, открытым текстом, права `0600` | только при `secrets.backend: file` |
| Файл лога | путь из `--log-file`, `CODELAB_LOG_FILE` или `logging.file` | только если вы его задали |

Каталога `$CODELAB_HOME/logs` и файла лога по умолчанию агент не создаёт — [эксплуатация](../operations.md#логи-и-диагностика).

Проверить, где лежат файлы конфигурации и есть ли они:

```bash
codelab-agent config path
```

```text
user: ~/.codelab/config.yaml (exists)
project: ~/projects/demo/.codelab/config.yaml (missing)
local: ~/projects/demo/.codelab/config.local.yaml (missing)
```

## Логи

`codelab-agent serve` пишет события в stderr всегда. Строка — время UTC, уровень, имя события и поля. Уровень задаёт `--log-level`, `CODELAB_LOG_LEVEL` или `logging.level`: `trace`, `debug`, `info` (по умолчанию), `warning`, `error`.

Для файла лога задайте `--log-file <путь>`: в нём формат JSON Lines, ротации нет. Подробности, список событий и правила файла — в [эксплуатации](../operations.md#логи-и-диагностика). Встроенный агент в `codelab` и app ключ `logging.file` пока не применяет; приложение и `codelab` пишут собственные логи — [эксплуатация app](../../../codelab_desktop/doc/operations.md#логи-и-диагностика), [эксплуатация `codelab`](../../../codelab_cli/doc/operations.md).

Логи привязывают события к сессии полем `session_id`, а к вызову инструмента — `tool_call_id`. Вопросы разрешений агент записывает событиями `permission.asked` и `permission.decided` (уровень `debug`) и `permission.denied` (`info`): в них видны инструмент, уровень, решение и причина, но не значения аргументов. Причина (`reason`) может содержать путь правки конфигурации агента или метку критической команды.

Проверить, какие секреты агент ищет и где, помогает флаг `--debug-secrets`: в лог пишется имя секрета и источник, значение — никогда.

## Что попадает в логи и журналы

Правила описаны в одном месте — [«Что попадает в логи и журналы»](../../../../docs/user/configuration.md#что-попадает-в-логи-и-журналы): до выпуска 1.0 тексты запросов и вывод инструментов не редактируются ни в журнале сессии, ни в логах.

Не публикуйте журналы и логи, не просмотрев их. Что агент отправляет провайдеру модели и MCP-серверам — [политика конфиденциальности](../../../../PRIVACY.md) ([русская редакция](../../../../PRIVACY.ru.md)).
