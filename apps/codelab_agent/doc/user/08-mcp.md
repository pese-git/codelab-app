# MCP-серверы

MCP (Model Context Protocol) — протокол, по которому агент подключает внешние серверы с инструментами: доступ к трекеру задач, базе данных, документации. После главы вы подключите сервер, поймёте, как агент спрашивает разрешение на его инструменты, и найдёте причину, если сервер не заработал.

Формат записи сервера в `config.yaml` и таблица ключей — в [настройке агента](../../../../docs/user/configuration.md#mcp-серверы). Подключение в app и в `codelab` — [руководство app](../../../codelab_desktop/doc/user/08-agent-extensions.md#mcp-серверы), [руководство `codelab`](../../../codelab_cli/doc/user/08-mcp.md).

## Какие бывают серверы

| Тип | Что это | Как запускается |
|---|---|---|
| `stdio` | локальная программа | агент запускает команду от вашего имени; сервер видит ваши файлы |
| `http` | сервер по адресу `http://` или `https://` | агент подключается по сети |

`stdio`-сервер получает ваши права, поэтому подключайте только то, чему доверяете.

## Подключить сервер

1. Запишите сервер в конфигурацию:

   ```bash
   codelab-agent mcp add files --type stdio --command my-mcp-server --arg /data
   ```

   ```text
   Updated mcp.servers[files] in ~/.codelab/config.yaml
   ```

   Для сервера по сети — `--type http --url <адрес>`. Токены не пишите в команду: заголовок и переменную окружения передавайте как ссылку `${secret:имя}` или `${ПЕРЕМЕННАЯ}`, либо читайте один раз из stdin флагами `--header-stdin` и `--env-stdin`. Команда сама сервер не запускает и ни к чему не подключается — она только правит файл.
2. Посмотрите список:

   ```bash
   codelab-agent mcp list
   ```

   ```text
   files  type: stdio  layer: user  enabled: true
   ```

   `layer` показывает, в каком слое конфигурации записан сервер (`user`, `project`, `local`).
3. Откройте новую сессию. Агент подключает серверы при создании или открытии сессии.

Удалить: `codelab-agent mcp remove <имя>`. Флаги `--project` и `--local` выбирают файл проекта вместо глобального. Серверы проекта агент читает, только если проект доверенный — [контекст проекта](06-project-context.md#доверие-к-проекту).

## Что делает агент с инструментами сервера

Инструмент сервера получает имя `mcp__<сервер>__<инструмент>`. Агент добавляет его к своим инструментам, и модель вызывает его так же, как `read` или `exec`. Три правила защиты:

- **Уровень `exec`, как у команд.** В режимах `ask`, `standard` и `accept-edits` агент спрашивает разрешение, в `plan` отклоняет без вопроса, в `bypass` и `autopilot` выполняет без вопроса. Правило `permissions.tools.<инструмент>: allow` тоже снимает вопрос — [разрешения](05-permissions.md#режимы). Метки сервера вроде «только чтение» агент во внимание не принимает: сервер — недоверенная сторона.
- **Ответ — чужие данные.** Текст из ответа сервера агент считает недоверенным: модель не должна выполнять указания из него.
- **Имена не пересекаются.** Если инструмент сервера называется как встроенный или как инструмент другого сервера, отключается весь сервер, а в журнале появляется `tool name collision`.

Решение «разрешать всегда» для MCP-инструмента привязано к имени инструмента и точным аргументам вызова.

## Состояние серверов

Агент подключает серверы параллельно. Если сервер не отвечает, это не останавливает сессию: агент пишет предупреждение, пробует снова с растущей паузой (до 30 секунд) и не показывает модели инструменты, которых нет.

Состояние показывает команда `/mcp list` в сессии. Реальный ответ в сессии с сервером, чья программа не найдена:

```text
> /mcp list
MCP servers (1)
ID     SOURCE  TRANSPORT  STATE   TOOLS  LAST ERROR
files  config  stdio      failed  0      spawn failed: No such file or directory (retry in 2s)
```

В stderr агента то же видно строками:

```text
warning mcp.server.failed {session_id: <session-id>, server: files, transport: stdio, reason: spawn failed: No such file or directory}
info mcp.server.retry {session_id: <session-id>, server: files, attempt: 2, delay_ms: 2301}
```

(Время в начале строк опущено.)

Команды в сессии:

| Команда | Что делает |
|---|---|
| `/mcp list` | таблица серверов: источник, транспорт, состояние, число инструментов, последняя ошибка |
| `/mcp reload [<id>]` | переподключает сервер или все; `id` — значение из столбца `ID` |
| `/mcp enable <id>`, `/mcp disable <id>` | включает и отключает сервер в сессии |

Состояние сервера краткой строкой есть и в `/status`: `MCP servers: files (failed)`.

## Серверы от клиента

Клиент может передать свои MCP-серверы при создании сессии. Если имя совпало с именем сервера из конфигурации, побеждает сервер клиента.

## Ограничения

- В режиме `codelab-agent serve --ws` MCP отключён полностью — ни `stdio`, ни `http` ([различия режимов](../operations.md#различия-режимов)).
- Где можно писать ссылки `${secret:…}` и `${ПЕРЕМЕННАЯ}` — [настройка: MCP-серверы](../../../../docs/user/configuration.md#mcp-серверы).
- На уровне лога `trace` stderr MCP-серверов попадает в лог без редактирования и может содержать секреты — [что попадает в логи](10-data-and-logs.md#что-попадает-в-логи-и-журналы).
