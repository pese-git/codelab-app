# AGENTS.md — codelab_agent

Правила этого приложения дополняют корневой `AGENTS.md` и `packages/dart/codelab_agent_core/AGENTS.md`.

Источники: `docs/architecture/proposals/dart-agent-and-clients/09-09-stage-4-acp-adapter.md` (задачи 4.5, 4.6), документ ядра `agent-core-architecture.md` — §12.3 (логи), §13.1, §13.3, §13.10 (адаптер и транспорт), §15.6 (флаги и переменные), §14 (фикстуры); `design.md` OpenSpec change `add-codelab-agent-binary`, `add-agent-configuration` (D4, D10, D11, D16), `add-agent-project-files` (D16, D17) и `add-agent-secret-store` (D8, D11, D15). Если документов не хватает, сначала дополняется документация, потом пишется код.

## 1. Назначение

`apps/codelab_agent` — бинарь `codelab-agent serve --stdio | --ws`: хост ядра в профиле `agent-serve`. Он разбирает флаги, загружает конфигурацию (`ConfigLoader` из `codelab_agent_io`: `config.yaml`, переменные `CODELAB_*`, флаги — `agent-core-architecture` §15; change `add-agent-configuration`), собирает ядро через `buildAgentCore`, поднимает `AcpAgentServer` на серверном транспорте и отвечает за логи, сигналы и коды выхода. Команда `codelab-agent config check [--cwd <dir>]` проверяет конфиг без запуска сервера: разбор аргументов — `lib/src/cli/config_cli.dart`, тексты, правила и коды выхода — общий `ConfigCommands` из `codelab_agent_io` (design.md change `add-agent-configuration`, D13); свой вывод здесь не формируется. Команда `codelab-agent secret set|delete|list` управляет секретами без запуска сервера: разбор аргументов — `lib/src/cli/secret_cli.dart`, тексты, правила и коды выхода — общий `SecretCommands` из `codelab_agent_io` (design.md change `add-agent-secret-store`, D8). Поведения агента здесь нет: оно в пакетах `codelab_agent_*`.

## 2. Границы

* Чистый Dart: НЕ ДОЛЖЕН импортировать `package:flutter/`, `package:fluent_ui/` и клиентские пакеты (`codelab_client_acp`, `codelab_ui`) — правило `apps/codelab_agent` в `packages/dart/codelab_architecture_tests/test/support/rules.dart`.
* `dependencies` — только `codelab_agent_core`, `codelab_agent_io`, `codelab_agent_acp`, `codelab_agent_mcp`, `codelab_acp_protocol`, `codelab_acp_transports`, `args`, `http`, `async`, `meta`. Расширение — только через OpenSpec change.
* Ядро собирается только через `buildAgentCore` (HOST-6): `ToolRegistry(`, `Agent(`, `AgentRuntime(` в `lib/` и `bin/` запрещены.
* stdout в режиме `--stdio` несёт только кадры ACP; логи — stderr и файл.
* Значение ключа провайдера (`CODELAB_API_KEY`, переменные из `api_key_env`, подстановки `${ENV}`) и токен WebSocket не попадают в лог, текст ошибок и строковое представление опций.
* Флаги строят слой `ConfigTree` (`ServeOptions.flags`), а не модели: настройки ядра берутся из результата `loadServeConfig`. С `--llm-script` слои 2–4 не читаются; невалидный конфиг — код `64` до старта транспорта. Разбор сценария (`LlmScript`, `withScriptedProviders`, `CwdTrackingStore`) живёт в `codelab_agent_io` и импортируется из `package:codelab_agent_io/testing.dart`, а не из основного бареля (`lib/src/scripted/`; change `add-embedded-agent-mode`, D8, задача 2.9): бинарь переводит `LlmScriptException` в `UsageError` (код `64`) в `AgentHost.build` и `loadServeConfig`.
* Файлы конфигурации (`agent-core-architecture` §15.2): `$CODELAB_HOME/config.yaml`, `<cwd>/.codelab/config.yaml`, `<cwd>/.codelab/config.local.yaml` и дополнительный файл `--config <path>` / `CODELAB_CONFIG` (только `.yaml`/`.yml`; `CODELAB_CONFIG` — только абсолютный путь, `--config` — от текущего каталога процесса; явно названный, но отсутствующий файл — код `64`). Файлы Python-агента (`$CODELAB_HOME/codelab.toml`, `$CODELAB_HOME/auth.toml`, `<cwd>/codelab.toml`, `<cwd>/codelab.local.toml`) не читаются: найденный файл даёт только предупреждение `config.legacy_found` (D12).
* `--max-steps <n>` и `CODELAB_MAX_STEPS` — `budget.max_steps`, целое `≥ 1`: неверный флаг — ошибка использования, неверная переменная — проблема конфигурации `budget.max_steps`; в обоих случаях код `64`; `--model <provider>/<model>` без `--provider` выбирает модель конфига (§15.6; D4).
* Файлы проекта (`agent-core-architecture` §11.5, §15.8, §17.2.2; design.md change `add-agent-project-files`, D2, D16): `AgentHost.build` передаёт `ProjectFilesLoader` из `codelab_agent_io` в `AgentCoreServices.projectFiles` только для `--stdio`; с `--llm-script` — `home: null`: `$CODELAB_HOME` не читается, а проект всегда недоверенный — `trusted_projects` берётся только из глобального слоя, который сценарий не читает, а в файле `--config`/`CODELAB_CONFIG` этот ключ — ошибка конфига (код `64`); поэтому `.codelab/prompts` и `.codelab/agents` проекта не загружаются (`untrusted_project`), читается только контекст `AGENTS.md` дерева `cwd`. `--ws` загрузчик не передаёт и один раз при запуске пишет `project_files.skipped {transport: ws}`: клиент WebSocket выбирает `cwd`, а чтение шло бы с машины агента.
* `CODELAB_HOME` берётся только из `codelabHomeOf` (D17): `~` и `~/…` раскрываются в `HOME`/`USERPROFILE`; `~user/…`, `~\…` и тильда без домашнего каталога — код `64` и текст в stderr до чтения файлов и до старта транспорта. С `--llm-script` значение не раскрывается и не проверяется.
* Секреты (`agent-core-architecture` §17.5.4; design.md change `add-agent-secret-store`, D8, D11, D15):
  * `AgentHost.build` создаёт один `SecretResolver` на процесс только через `openHostSecrets` по `HostSettings.secretsBackend` и окружению процесса и передаёт его в `createRoutedStreamFunction(…, secrets:)` и `AgentCoreServices.secrets`; своих хранилищ и чтения `CODELAB_SECRET_*` в приложении нет. `--llm-script` всегда использует бэкенд `env` независимо от `secrets.backend` (`secrets.yaml` не открывается; `openHostSecrets(selectionReason: 'forced by --llm-script')` даёт `secrets.backend.selected {backend: env, reason: forced by --llm-script}`); `serve --ws` разрешает ключи так же, как `--stdio`. `secrets.backend: file` даёт при каждом старте `secrets.backend.plaintext {path}`.
  * `--debug-secrets` (флаг без значения) и `CODELAB_DEBUG_SECRETS=1` включают `secrets.lookup` (имя, назначение, источник, найдено ли); значение, длина и хеш не пишутся, уровень лога режим не меняет. `secrets.backend: keychain` и другое недопустимое значение — проблема конфигурации, код `64` до старта транспорта.
  * `secret` — вторая подкоманда рядом с `config`: `set <name>` читает значение только из stdin (аргументом — код `64`, аргумент не печатается), `delete <name>`, `list`. Бэкенд берётся из `secrets.backend` пользовательского конфига и `CODELAB_CONFIG` без полной загрузки конфига (флаг `serve --config` подкоманды не видят). Любая ошибка разбора argv, если `secret` есть в argv где угодно (в том числе флаг верхнего уровня до `secret`), печатает только `codelab-agent: invalid arguments for secret` и справку `secret`, без текста `package:args` и присланных слов: среди них может оказаться значение секрета. По той же причине `serve` и `config` лишних слов не цитируют: `unexpected arguments (N)` и `codelab-agent: unknown config arguments (N)` — только число. Неизвестная подкоманда и ошибки использования (неверное имя, значение аргументом, ошибка argv) — код `64` со справкой `secret` в stderr; ошибки значения (пустое, перевод строки, недопустимый UTF-8, длиннее 64 КиБ, коллизия `envOverride`) и отсутствие домашнего каталога (`cannot find the home folder: set CODELAB_HOME or HOME`) — код `64` без справки (`SecretCommandResult.showUsage`); ошибка хранилища, в том числе бэкенд `env` при `set`/`delete`, — код `1`.
  * Значение секрета не попадает в stdout, stderr, лог, argv и текст ошибок; в тестах значения только тестовые, `CODELAB_HOME` — временный.
* `config` — единственная подкоманда `check [--cwd <dir>]`; `set`, `migrate` и прочие не регистрируются и дают `64` со справкой. `config check` не запускает сервер, не читает stdin и ничего не пишет.
