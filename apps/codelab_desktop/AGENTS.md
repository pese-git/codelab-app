## Встроенный агент

* Встроенный агент работает в процессе приложения через мост `codelab_embedded`: профиль (строка «Embedded agent» страницы «Connection», первая в списке) `ConnectionProfile.embedded(id: 'embedded', hostProfile: 'embedded-app-desktop')` (D9). Прямой импорт `package:codelab_agent_*` по-прежнему запрещён (корневой `AGENTS.md` §5; правило `apps/codelab_desktop` сторожа).
* Границы барелей моста (D3, правила `packages/dart/codelab_architecture_tests/test/support/rules.dart`):
  * `package:codelab_embedded/io.dart` (`localEmbeddedAgentOpener`) импортируется только из `lib/app/` — composition root;
  * `package:codelab_embedded/testing.dart` запрещён во всём `lib/`: сценарий модели в релизную сборку не попадает (D8). Сценарный открыватель передают только тесты и `integration_test/` через шов `createCodeLabRootScope(embeddedOpener:)` (D9);
  * основной барель `package:codelab_embedded/codelab_embedded.dart` web-безопасен и сторожем внутри app не ограничен.
* `EmbeddedTransportResolver` и адаптер `Logger` → логгер приложения лежат в `lib/app/`; `app_scope.dart` регистрирует резолвер вторым резолвером `ClientWorkspace` и закрывает его (`close()`) при закрытии root scope, параллельно с закрытием ядра клиента, после рабочего пространства (`add-client-process-shutdown-on-exit`, D11). Ожидание `close()` ограничено 10 с, как в CLI: по истечении — событие `embedded.close_timeout` уровня `warning`, освобождение транспорта и `AcpClientApplication` продолжается (D9, «Таймаут закрытия»). При выходе из app (`AppLifecycleListener.onExitRequested`) действует ещё и общий предел 5 с на весь `CodeLabRootLifecycle.dispose()`: не уложилось — `app.exit_timeout` с именами незавершённых шагов и ответ `exit`, закрытие агента продолжается до остановки VM (`add-client-process-shutdown-on-exit`, D2; закрытие агента при выходе не укорачивается — Q3). Резолвер сериализует `open`: сначала `await` `dispose()` прежнего агента, затем открыватель. Агент, вернувшийся из открывателя после отмены подключения, сразу получает `dispose()` и текущим не становится (корневой `AGENTS.md` §12; D6, «Резолвер клиента»).
* Поводов отмены подключения два — новый Connect или Reconnect и `close()` резолвера при закрытии root scope. Кнопки Disconnect нет, публичный API `TransportResolver` и `ClientWorkspace` ради встроенного агента не меняется (решение L4, подтверждено пользователем 2026-11-02; D6, «Отмена подключения в app»). Disconnect — отдельный change клиентского слоя для всех типов подключения. Вытесненная попытка подключения не меняет состояние: `ClientWorkspace` ведёт номер попытки, а `ConnectionCubit` не пишет для неё ни `failed`, ни «started» (D6, «Устаревшая попытка в `ClientWorkspace`»).
* Невалидный или отсутствующий конфиг — `ConnectionFailed`, резолвер переводит `EmbeddedAgentConfigException` в `ClientWorkspaceException(message)`, и баннер показывает его текст без имени класса (проблемы загрузчика и подсказку `codelab config check`); нет ключа провайдера — соединение открывается, первый ход даёт заметку «Failed turn» (D5).

## Профили подключения и настройки

* Экран настроек и страница «Connection» — feature `lib/features/settings/` (`application/`: `ConnectionSettingsCubit`, `DefaultProfileResolver`, `ConnectionCommands`; `presentation/`: `SettingsShell`, `ConnectionPage`). Переходы рабочее место ↔ настройки — только `NavigationCubit` (`lib/app/navigation/`); виджеты не открывают настройки маршрутом `Navigator`.
* Профили подключения app и CLI — один файл `$CODELAB_HOME/profiles.json` (`CODELAB_HOME` непуст, иначе `~/.codelab`), один `JsonFileProfileStore` из `codelab_client_io` (D7). Путь и окружение даёт `ConnectionEnvironment` (`lib/app/connection_environment.dart`; правило дома — `resolveCodelabHome` из `codelab_client_io`, общее с CLI) из шва `createCodeLabRootScope(environment:)`; тесты подставляют хранилище швом `profileStore:`. Битый или незнакомый файл не перезаписывается: страница показывает ошибку, а «Add profile», «Rename» и «Remove» недоступны (целостность данных, корневой `AGENTS.md` §2).
* **Недавние проекты** — файл `$CODELAB_HOME/recent_projects.json`, общий с CLI (change `share-recent-projects-store`, D1, D8): `JsonFileRecentProjectsStore` из `codelab_client_io`, привязка в `CodeLabPlatformModule` (`app_scope.dart`). Шов тестов — `createCodeLabRootScope(recentProjectsStore:)` (`CodeLabTestBinding(recentProjects:)`, двойник `FakeRecentProjectsStore`): настоящий файл внутри `testWidgets` зависает. Недопустимый `CODELAB_HOME` — `UnavailableRecentProjectsStore` (`RecentProjectsUnavailableException`), список пуст, причина в диагностике. Нечитаемый файл не перезаписывается (D2). Перенос прежнего списка из `shared_preferences` (`codelab.recent_projects`) делает `MigratingRecentProjectsStore` (`lib/core/platform/recent_projects_migration.dart`, D4): только предвыпускные сборки, код удаляет change `remove-recent-projects-migration` до первого `stable` (Q2 (б), D9); события `recent_projects.{migrated,legacy_unreadable,migration_failed}` без путей (D11). Тесты, собирающие scope без `CodeLabTestBinding`, передают `recentProjectsStore:` или временный `CODELAB_HOME`; `test/flutter_test_config.dart` сверяет настоящий `recent_projects.json` до и после каждого файла тестов и роняет файл при изменении.
* Без явного выбора профиль по умолчанию — **встроенный агент**; выбор — ключ `shared_preferences` `codelab.connection.default_profile` (порт `ConnectionPreferences` в `lib/core/platform/`). «Connect on start» удалён: прежний ключ `codelab.connection.connect_on_start` не читается и не пишется, его значение игнорируется; агент стартует по триггерам D13, а при запуске — по восстановленному проекту (change `require-project-folder`, D19). `default` — второе имя встроенного агента: запись `default` в `profiles.json` игнорируется, страница предлагает её удалить (D5, D21). Встроенный агент в файл не пишется.
* Токен профиля — **только ссылка**: `env:<NAME>` или `secret:<имя>` (design.md change `add-provider-setup-ui`, D13). Значение читает `ProfileSecretSource(environment, stored: …)` из `codelab_client_core` в момент открытия транспорта (`env:` — из окружения, `secret:` — из хранилища секретов агента через порт `ProfileSecrets`, без кэша); в профиле, состоянии (Cubit), журнале, диагностике и на экране его нет, строка показывает только источник. `InMemorySecretSource` в app не используется. Приложение из Finder (macOS) не видит переменных оболочки — это видно в строке профиля («<NAME> is not set in CodeLab's environment.»).
* Четыре варианта токена диалога (D14, отступление от артборда — «From environment variable», D24): «No token», «Use stored secret» (имена `ProfileSecrets.names()`), «Store a new token» (`PasswordBox` без режима подглядывания; значение — `SecretText` в `NewSecretToken` черновика, сбрасывается при закрытии диалога), «From environment variable». Запись «секрет → профиль» с откатом и «профиль → секрет» при удалении выполняет `ProfileCommitter` (kit): Cubit-ы не пишут в хранилище секретов сами. Отказ записи, откат и удаление дают события `connection_profile.token_*` (D18) только с `profile_id` и `backend`: имён секретов, значений и `toString()` исключений в событиях нет. Строка профиля с `secret:` — `Token secret <имя>` и тег `<backend> · set|missing` по `ProfileSecrets.isSet` (значение не читается); «Remove» собственного секрета `codelab/profiles/<id>/token` показывает флажок «Also delete the stored token …» (по умолчанию включён), чужой секрет не удаляется никогда. Правило `ws://` (подтверждение «Save anyway» перед записью) действует для всех вариантов, кроме «No token», и сбрасывается при смене секрета и значения токена.
* События журнала настроек — логгер `codelab_desktop.settings`, компонент `settings` (D17): без токенов, аргументов и `env` stdio, имени переменной токена, путей и query URL, без `toString()` исключений (только имя типа).
* Диалог «Add connection profile» (`features/settings/`: `AddProfileCubit` и закрытая иерархия `AddProfileState` в `application/`, `AddProfileDialog` в `presentation/`; D11–D14). Правила черновика — `ProfileDraft` из `codelab_client_core`; при «Save» выполняется только локальная валидация черновика — сети, `PATH` и чтения значения выбранного секрета нет. Проверки подключения («Test connection», «Not tested», «Test anyway») в app нет: профиль проверяет «Use» и автоматический старт агента, результат виден в бейдже строки и на экране или баннере сбоя рабочего места (change `remove-test-connection`, D1, D4). Cubit создаётся на каждое открытие диалога и закрывается вместе с ним; «задана ли переменная токена» он узнаёт из `Map<String, String>` окружения composition root, значения не читает; незаданная переменная даёт ОДНУ заметку «<NAME> is not set in CodeLab's environment.» под полем токена. Подтверждение `ws://` — только при сохранении («Save anyway»), одно на пару «URL, выбор токена»; события — `connection_profile.*` по D17 (`connection_profile.saved` без поля `tested`). «Rename» строки — `ConnectionSettingsCubit.renameProfile`.
* Строка «Current» бывает только при живом соединении (`Connected` или `Reconnecting`) и «Connect» не показывает (`ConnectionProfileRow.canConnect`): переподключение — «Restart agent» блока Behavior. У `Connecting…`, `Failed` и остальных строк «Connect» есть. Заголовки `ContentDialog` (диалог профиля, подтверждение «Remove profile …?») — `CodeLabDialogTitle` из `codelab_ui` (20 px, w600), не крупный заголовок по умолчанию.
* `ConnectionCubit` подключает окно по профилю (`connect([profile])`, `reconnect()`) и реализует узкий `ConnectionCommands`; страница «Connection» вызывает только его. Форма подключения (`ConnectionSetupDialog`, `TransportSetupPanel`, поля `stdioCommand` и т. п.) удалена (D6).

## Страница «Providers»

* Feature `lib/features/settings/` (design.md change `add-provider-setup-ui`, D5, D10, D21): `application/` — `ProviderSettingsCubit`, закрытая иерархия `ProviderSettingsState` (`Loading | ReadOnly | Unreadable | Ready`, запись — флаг `Ready.saving`) и порт `ProviderSettingsSession`; `presentation/` — `ProvidersPage` (тело `settings-providers`) в `settingsPageBuilders`, страница в `defaultSettingsPages` и ключевые слова поиска `provider`, `model`, `api key`, `key storage`, `base url`. Cubit создаётся на каждое открытие страницы (`CodeLabDependencies.createProviderSettingsCubit`), страница вызывает `reload()` и закрывает его.
* **Чьи настройки** решает `resolveSettingsAccess` моста `codelab_setup`: профиль текущего подключения (`Connected`/`Reconnecting`), без подключения — профиль по умолчанию (`DefaultProfileResolver`). Встроенный агент и stdio-`codelab-agent` — `EditableSettings` (`CODELAB_HOME` из `env` stdio-профиля, иначе дом app из `ConnectionEnvironment.codelabHome`; папка проекта — для stdio только при «Run in the project folder»); WebSocket — `RemoteReadOnly`, чужой stdio-агент — `NotManaged`: локальный конфиг НЕ читается (SETUP-2), страница показывает InfoBar `providers-read-only` и текущую модель сессии. Смена подключения перечитывает доступ. Имя агента из `initialize` в `WorkspaceState` не доступно, поэтому для stdio решает команда профиля.
* **IO только в `lib/app/`:** `provider_settings_session.dart` (`openProviderSettingsSession`) собирает `ClientSecretAccess`, `FileAgentConfigStore` и `ioProviderCheck` из `codelab_setup/io.dart` для дома, `--config` и окружения агента (окружение app плюс `env` stdio-профиля) и переоткрывается при каждой загрузке страницы, как хранилище токенов профилей (D3). `ReopenableProfileSecrets` страница не использует: ей нужен не порт токенов, а открытое хранилище по дому агента. Шов тестов — `createCodeLabRootScope(providerSettingsOpener:)`.
* **Check:** ключ читается ТОЛЬКО в адаптере `lib/app/` (`ClientSecretAccess.read` или переменная `api_key_env` окружения агента) и сразу передаётся `ProviderCheck` в `SecretValue`; в Cubit, состояние, события и логи значение не попадает (SETUP-1), порт сессии получает лишь ссылку `KeyStatusView`. Ключа нет (`Key: missing`) — запрос не отправляется. Номер проверки на строку отбрасывает поздний итог; закрытие страницы отбрасывает все (`provider_settings.check_discarded`). Повторный Check строки, закрытие страницы, смена подключения, исчезновение или удаление провайдера отменяют `CancelToken` проверки: мост закрывает соединение, `CheckCancelled` и поздний итог отбрасываются. Check неактивна для литерального ключа в `config.yaml` (значение app не читает; подсказка `codelab secret migrate`); под строкой с `http://` к нелокальному хосту — предупреждение «The key is sent unencrypted to <host>.» (SETUP-10, правило локальных хостов `isLocalHost` общее с `ProfileDraft`).
* **Запись** — только мост: «Default model» пишет `SetValue('agent.default_model')` в слой, где ключ определён сейчас, если он редактируемый, иначе в `user`; «Remove» — `ProviderRemover` одним `apply`, секрет удаляется после `ConfigSaved` (SETUP-24). Пока идёт запись (`saving`), повторные действия игнорируются; конфликт даёт баннер `providers-banner` и перечитывание, без автоповтора (SETUP-6). Битый `config.yaml` — `Unreadable` с проблемами загрузчика, файл не пишется. Проектный слой применяет загрузчик моста только для доверенного проекта (`trusted_projects`); страница отдельной проверки не делает.
* События — логгер `codelab_desktop.settings`, `provider_settings.{loaded,unreadable,check_started,check_finished,check_discarded,default_model_changed,removed}` (D18): только `provider_id`, виды и числа, без имён секретов и переменных, адресов, текстов исключений.
* «Add provider» (`providers-add`, в пустом состоянии также `providers-empty-add`) и «Edit» (`providers-edit-<id>`) открывают мастер провайдера (см. ниже). «Edit» неактивна с подсказкой `editHint` по правилу моста `providerEditRefusal` (общее с «Remove» и с проверкой автомата при «Save»; разные тексты для `notEditable` и `multipleLayers`, D7, D9). После `ConfigSaved` страница показывает баннер мастера (`providers-banner`, при незапущенном агенте с кнопкой `providers-banner-connect`) и перечитывает снимок. Подсказку «after Restart agent» в баннере решает правило ядра: `restartRequiredProviders(снимок страницы до записи, свежий снимок)` моста, а не вид ключа; вызов ограничен 5 с, при сбое подсказка не показывается и пишется `provider_wizard.restart_hint_failed` (Q35, D11 «Итерация 6»).

## Мастер провайдера

* Design.md change `add-provider-setup-ui`, D7 (шаги и ключи), D9 (баннеры после записи; подсказка «Restart agent» — по правилу ядра, D11 «Итерация 6»), D18 (события), D21 (поздние результаты), D24 (артборд `Wizard`), D26 (баннер соединения). Автомат — `ProviderSetupFlow` моста `codelab_setup` (один на CLI и app, SETUP-8); `features/settings/application/provider_wizard_cubit.dart` — тонкая обёртка: `ProviderWizardState` = состояние автомата + шаг строки шагов + сводка + баннер конфликта. Отображение `ProviderSetupState` на шаги и тексты отказов — `provider_wizard_view.dart` (чистые функции, тесты без виджетов); диалог — `presentation/provider_wizard_dialog.dart` (`ContentDialog` `provider-wizard`, Esc через `CallbackShortcuts`).
* **Автомат строит composition root:** `ProviderSettingsSession.openWizard({editing, forceDefault})` (адаптер `lib/app/provider_settings_session.dart`) собирает `ProviderSetupFlow` с `providerKeysOf`, `FileAgentConfigStore`, `ioProviderCheck` и `isLocalHost` kit (правило одно, второй копии в app нет). Cubit порта `ProviderKeys` не видит: значение ключа вводится в `PasswordBox` без «глазка» (`revealMode: hidden`), уходит в автомат внутри `SecretValue` и в состояние, события, логи и тексты ошибок не попадает (SETUP-1); контроллер поля очищается при уходе с шага.
* **Cancel и Esc** закрывают мастер, кроме `Saving` (кнопки неактивны, Esc игнорируется, повторное «Save» не даёт второй записи); закрытие Cubit отменяет идущую проверку и сбрасывает ключ. `provider_wizard.check_discarded` и `cancelled` пишет Cubit (автомат при `dispose` молчит). Конфликт записи (`ConfigConflict`) возвращает в «Review» с баннером `provider-wizard-review-notice`, без автоповтора (SETUP-6); автомат перечитывает снимок, повторный «Save» пишет поверх свежего файла. Отказ плана (`Reviewing.refusal`) гасит «Save»; текст берётся из `Reviewing.error` автомата (единственное место строк). Содержимое диалога имеет минимальную высоту (диалог по центру не прыгает между шагами); на «Model» при правке отмечена текущая модель (`ChoosingModel.currentModel`).
* **Баннер соединения без провайдера (D26):** `EmbeddedTransportResolver` при `EmbeddedAgentConfigException` зовёт функцию composition root `providerSetupNeededAt` (`lib/app/provider_setup_probe.dart`, снимок `FileAgentConfigStore` и признак моста `providerSetupNeeded`) и пишет ответ в порт `ProviderSetupOffer` до исключения. `ConnectionCubit` при сбое попытки встроенного агента читает порт и публикует метку `ProviderSetupNotice` в `WindowConnectionState`; любая новая попытка метку сбрасывает; `connectAfterProviderSetup(notice)` подключает встроенный профиль только при той же метке (иначе `provider_wizard.reconnect_skipped`). `WorkbenchMainPane` вместо сырого текста показывает `No model provider is configured for the embedded agent.` и «Add provider» (`connection-banner-add-provider`; единственная основная кнопка карточки, «Reconnect» в этом состоянии скрыт, «Connect» обычная; однократный запуск гарантирует `ConnectionCubit.runProviderSetup`); мастер — `CodeLabDependencies.openEmbeddedWizard` (`forceDefault: true`, цель `user`).
* Шов тестов: `createCodeLabRootScope(providerSetupProbe:)` (`CodeLabTestBinding(providerSetupProbe:)`); настоящую функцию по снимку проверяет `test/app/provider_setup_probe_test.dart` на временном `CODELAB_HOME`.
* События (D18): все `provider_wizard.*` автомата пишет мост — `started` (поле `entry`: `app` со страницы Providers, `banner` из баннера), `check_finished`, `check_discarded`, `saved`, `save_failed`, `cancelled`; Cubit мастера их не дублирует. ## Фокус одобрения (`fix-approval-focus`)

* **Цель перехода выбирает application, не виджет.** Сочетание `CodeLabShortcut.goToApproval` (Cmd/Ctrl+Shift+A) вызывает `CodeLabShellCubit.goToApproval`: цель — `goToApprovalTargetOf` (`application/approval_go_to_target.dart`), ожидающее одобрение активной сессии с признаком `focused` модели клиентского ядра (самое раннее по `requestedAt`; признак не значит клавиатурного фокуса). Цели нет, если ожидающего одобрения нет, соединение не `Connected`, сессия `detached` или открыта палитра команд: нажатие ничего не делает. Дальше `TranscriptViewCubit.requestShow(..., focusApproval: true)`; ответа на запрос переход не отправляет (§10). Колбэк `onGoToApproval` передаётся всегда.
* **Возврат фокуса в композер.** Полоса с фокусом уходит → `onApprovalFocusReleased` (через `WorkbenchFocus`, `presentation/workbench_focus.dart`) → хост (`_CodeLabHomeState`, `app/codelab_app_widget.dart`) запоминает узел, который Flutter отдал сам, и в следующем кадре сравнивает его с текущим `primaryFocus`; цель выбирает чистая `approvalFocusReturnOf` (`application/approval_focus_return.dart`): композер (есть и включён), иначе рабочее место, а если фокус успел взять пользователь, — ничего (§12). Узел композера принадлежит хосту. Следующему одобрению фокус не передаётся.
* **Ответ сочетанием решает application (D14, D15).** `CodeLabWorkbenchShortcuts.onAnswerApproval` (⌘Y, ⌥⌘Y, ⌥⌘Z, ⌥⇧⌘Z; Alt+Shift+Y, Q, X, W; без автоповтора) вызывает `CodeLabShellCubit.answerApprovalByShortcut(kind, isVisible:, modifiersHeldFor:)`. Виджет решения не принимает: функция `approvalShortcutDecisionOf` (`application/approval_shortcut_decision.dart`) проверяет по порядку цель (самое раннее ожидающее одобрение активной сессии; соединение `Connected`, сессия не `detached`; иначе `no_target`), срок зажатия Alt и Shift (`modifiers_not_held`: на Windows и Linux меньше `approvalShortcutModifierHoldDelay` — 150 мс — не отвечает и не показывает полосу, потому что Alt+Shift — смена раскладки; срок сообщает кит, на macOS `modifiersHeldFor == null` и условия нет), вариант по виду (`no_option`), видимость полосы через `CodeLabApprovalVisibility` (`not_visible`) и возраст запроса (`settling`: `approvalShortcutSettleDelay` — 500 мс). Любой отказ, кроме `no_target` и `modifiers_not_held`, только показывает полосу (`requestShow` без фокуса), ответа нет. Возраст считает `ApprovalActivationTracker`, которым владеет `ActiveSessionCubit` (его `observe` вызывается на каждый снимок показанной сессии), потому что отсчёт идёт от появления запроса, а не от нажатия; после отказа `not_visible` фасад вызывает `activation.restart`, и 500 мс идут от показа полосы, а не от активации. Часы — один параметр `clock` (`CodeLabShellParts.build` → `ActiveSessionCubit`, трекер и `CodeLabWorkbenchShortcuts.clock`); тесты двигают их явно, реального ожидания нет (`testing.md` §20). При открытой палитре или диалоге выбора корня диска (`pendingRootSession`) нажатие не делает ничего. Если предыдущий ответ ещё в полёте (`isRespondingToApproval`), нажатие ничего не отправляет и пишет `answer_in_flight`. Ручку `CodeLabApprovalVisibility` создаёт и держит хост (`_CodeLabHomeState`), в ленту она идёт через `WorkbenchFocus`.
* **Терминал не пропускает клавиши ответа.** `TerminalPane` оборачивает `TerminalView` в `_AbsorbApprovalAnswerKeys`: необработанная эмулятором клавиша ответа поглощается и не доходит до привязки рабочего места, потому что терминал пользователя работает мимо одобрений агента.
* **Журнал (D9, D14).** `ActiveSessionCubit.respondToApproval(..., source:)` (`ApprovalAnswerSource`: `shortcut` или `button`, по умолчанию `button`) пишет `workbench.approval_answer` с полем `source`; отказ сочетания — `workbench.approval_shortcut_skipped` с `reason` (`ApprovalShortcutSkipReason`: `no_target`, `no_option`, `not_visible`, `settling`, `modifiers_not_held`, `answer_in_flight`); при `not_visible` добавляется `visibility_detail` — диагностика ленты без подписей и текста: `not_built`, `out_of_viewport bar=(l,t,r,b) viewport=(l,t,r,b)` или `obscured by=<RenderObject> owner=<Widget> at=(x,y)`. Сырых аргументов вызова в событиях нет.
* **Страница «Keyboard».** Строки ответа показывают клавиши платформы (`combosFor(defaultTargetPlatform)`), а поиск знает нотации всех платформ (`searchNotations`). Прежних локальных клавиш полосы и подсказки перехода `codeLabApprovalGoToHint` нет.
* Тексты: `settingsKeyboardActionGoToApproval`, `settingsKeyboardWhereApprovalPending` (место строки «Go to approval»), `settingsKeyboardWhereApprovalAnywhere` (место четырёх строк ответа: рабочее место, самое раннее ожидающее одобрение, если в нём есть вариант). Все с меткой `security`.

* Design.md change `add-desktop-usage-pane` (D1 — слои, D2 — состав, D3 — когда обновлять журнал, D4 — подписи шагов, D5 — CSV, D6 — клик по строке статуса, D10 — доступность, D11 — палитра, D13 — события), spec `agent-workbench-ui` «Панель Usage», «Подпись шага в панели Usage», «Экспорт usage в CSV». Все числа форматирует kit (`usage_format.dart`); app ничего не суммирует и свои правила формата не держит. Неизвестное — `—`, а в CSV пустая ячейка, не `0` (DSK-11). **Источник карточек (D1 change `fix-usage-pane-live-cards`):** Input, Output, Cost и Turns · steps строятся целиком из одного агрегата — `total` журнала, если `ledger.seq ≥ usage.lastSeq` (или снимков нет), иначе `usage.session` (`turns` живого агрегата — число ходов карточки; без него только шаги); журнал и снимок не складываются, таблицы и CSV — только из журнала. Cost агрегата без шагов, токенов, цены и причин неполноты — `—` и `no usage yet` (D8). Строка состояния журнала (D7): `rebuilt` с причиной `stale`/`missing` — `Ledger: up to date · N records`, причина в `UsagePaneData.statusHint` (подсказка `CodeLabUsagePane.statusHint`); `invalid`, `explicit`, незнакомая причина — `rebuilt from journal (<reason>) · N records` без подсказки.
* **Правило сторожа:** `lib/features/usage/application/` без `package:flutter/` и без `dart:io`; запись файла — только порт `UsageCsvSaver` в `lib/core/platform/usage_csv_saver.dart` (`FileSelectorUsageCsvSaver` на `file_selector.getSaveLocation` и `dart:io`; результат — sealed `UsageCsvSaveResult`: `UsageCsvSaved | UsageCsvCancelled | UsageCsvFailed(errorClass)`, сбой — результатом, а не исключением; запись идёт через временный файл `<path>.tmp` рядом и `rename` (`writeFileAtomically`), поэтому существующий файл при обрыве не обрезается, а временный при сбое удаляется). `ActiveSessionCubit` и `CodeLabShellParts.build` принимают порт обязательным (`app_scope` всегда его привязывает). Тесты подменяют порт через `CodeLabTestBinding(usageCsvSaver: FakeUsageCsvSaver())`.
* **Владелец данных и подписки** — `ActiveSessionCubit`: данные панели (`ActiveSessionState.usage`, в фасаде `CodeLabShellState.usage`) собираются в той же единственной подписке `_onView` на `SessionHandle.view`, что и `statusBar`; второй подписки нет. Пересчёт идёт только при смене входов (`usage`, `usageLedger`, identity вызовов `ToolCallItem` ленты — `tool_call_update` обновляет подписи шагов без новой записи), а не на каждый фрагмент ответа. Доступность — `CodeLabShellState.usageAvailable` (таблица D10: есть `usageLedger` или `usage.support` не `unknown`); недоступная панель остаётся в `LayoutState.openPanes` и в `codelab.dock.*`.
* **Обновление журнала (D3).** Автозапрос `refreshUsageLedger(id)` без `rebuild` идёт только из `ActiveSessionCubit` по `ledgerRefreshNeeded`: панель показана (`usagePaneShown(true)` из `initState` виджета, `false` из `dispose`; фасад считает экземпляры, показана — пока их больше нуля, поэтому пересборка дока с двумя экземплярами показ не гасит), сессия не `running`/`cancelling`, журнал `idle` или `loaded` с `seq < usage.lastSeq`, и для этого `lastSeq` автозапрос ещё не уходил. Возврат журнала в `idle` из другого состояния (переподключение, загрузка сессии) сбрасывает учёт и даёт ровно один новый автозапрос; смена сессии учёт тоже сбрасывает. `failed` автоматически не повторяется — только `Retry` (`refreshUsageLedger()`) и `Rebuild from log` (`rebuildUsageLedger()` → `rebuild: true`). Автозапрос из реакции на ревизию уходит микрозадачей: kit публикует `loading` синхронно, а `add` в broadcast-поток внутри доставки события запрещён. Опроса по таймеру нет; слияние запросов и поздние ответы отбрасывает kit.
* **Блок «Turn budget» и тик (D9, Q11 (а)).** Источник — `usage.budget` (не журнал), поэтому блок есть и у агента без журнала. `application/usage_budget.dart`: `usageBudgetDataOf(SessionView)` собирает `UsagePaneData.budget` (заголовок `This turn` — только при `running`/`cancelling` и неитоговом бюджете, иначе `Last turn`; строки Steps, Tokens, Cost с подписями kit и тоном в целых: `used·5 ≥ limit·4` — warning, `used ≥ limit` — danger; признак `ticking`), чистая `usageBudgetRowsAt(budget, now:)` добавляет Time живого бюджета (`running`/`cancelling`, не итоговый; `UsageBudgetTime.live`): `usedMs + max(0, (now − receivedAt) − |W ∩ (receivedAt, now]|)`, где `W` — объединение ожиданий одобрений корня (`SessionView.approvalWaits`, `UsageBudgetTime.waits`; ожидание без `resolvedAt` идёт до `now`; D4 change `fix-usage-pane-live-cards`), поэтому пока одобрение ждёт, Time стоит, а после ответа не прыгает; насыщающее сложение, отрицательная разность — ноль; `formatUsageDuration` — `m:ss`/`h:mm:ss`. **Тик принадлежит `WorkbenchUsagePane`:** `Timer.periodic` раз в секунду, только пока панель смонтирована и `UsageBudgetData.ticking` истинно (решает application: бюджет живой — в том числе при `cancelling`, нет ожидающего одобрения корня, есть `duration`; одобрение потомка тик не останавливает); отмена при смене признака (слушатель фасада) и в `dispose`; часы — параметр `clock` (как у `WorkbenchAgentsPane`), в `build` они спрашиваются только при наличии блока. Кэш данных панели в `ActiveSessionCubit` ключуется ещё статусом сессии и списком `approvalWaits` по значению (D5), иначе заголовок, тик и Time застревали бы до следующего снимка; одобрение потомка и новая ревизия без изменения ожиданий данные не пересчитывают. Маппер в кит — `usageBudgetViewOf` (`usage_pane_view.dart`).
* **Клик по строке статуса и палитра (D6, D11).** `CodeLabSessionStatusBar.onTap` передаёт `main_pane.dart` только при `usageAvailable`; клик и пункт палитры `Usage` (`usage-pane`, `/usage-pane`; `/usage` остаётся командой агента) вызывают `openUsagePane()` (`LayoutCubit.openPane`) — повторный клик панель не закрывает. Пути файла, подписи ходов и шагов, токены и деньги в записи не попадают.
* **CSV (D5).** RFC 4180, CRLF, UTF-8 без BOM; значение текстовой ячейки с `=`, `+`, `-`, `@`, TAB или CR в начале получает префикс `'` (подписи ходов — слова пользователя, подписи шагов и модели — строки агента). ## Секреты

* Секреты (ключи провайдеров, токены) читаются и пишутся только через общие бэкенды `codelab_agent_io` — через `package:codelab_setup/io.dart` (`ClientSecretAccess`, `secretReadOnlyHint`; тот же файл реэкспортирует `SecretAdmin`, `DescribedSecretStore`, `SecretStoreUnavailableException` и `Logger`) и встроенный агент через `codelab_embedded`. Приложение не импортирует `package:codelab_agent_*` напрямую (корневой `AGENTS.md` §5).
* **`package:codelab_setup/io.dart` импортируется только из `lib/app/`** (composition root; правило сторожа, design.md change `add-provider-setup-ui`, D20): `lib/app/client_profile_secrets.dart` (`openProfileSecrets`, `ClientProfileSecrets`) открывает `ClientSecretAccess` для `CODELAB_HOME` и превращает исходы `SecretAdmin` в порт `ProfileSecrets` kit; подсказку бэкенда только для чтения строит `secretReadOnlyHint` (первая буква заглавная, в конце точка: «Secret store env is read-only. …», D3). Cubit-ы, application и presentation получают только порт `ProfileSecrets`. В `lib/features/settings/presentation/` запрещены `dart:io` и `codelab_setup/io.dart` (SETUP-9). Хранилище первый раз открывается в `main` до сборки scope (`ProfileSecrets.backend` синхронный) и передаётся швом `createCodeLabRootScope(profileSecrets:)`; затем `ReopenableProfileSecrets` открывает его заново (фабрика `profileSecretsOpener`) при каждом открытии диалога «Add connection profile» и страницы Connection, поэтому правка `secrets.backend` применяется без перезапуска (D3); тесты подставляют `FakeProfileSecrets`, без шва хранилище «не открыто» и только для чтения. Событие `secrets.client.backend` пишет scope.
* `flutter_secure_storage` и другие Flutter-плагины хранения секретов на desktop НЕ ИСПОЛЬЗУЮТСЯ: у приложения, CLI и автономного агента ОДНО хранилище (общий файловый бэкенд `$CODELAB_HOME/secrets.yaml` и переменные `CODELAB_SECRET_*`; после 1.0 — общие записи хранилища ОС, change `add-agent-os-secret-backends`), иначе записи разошлись бы (D15, D16).
* Перенос секретов из файла конфига встроенного агента (задача 8.11; design.md change `add-config-literal-secrets-and-migrate`, D8): признак `EmbeddedAgent.secretsInConfig` резолвер передаёт в `SecretMigrationOffer` (`lib/app/`); порт `SecretMigrationRunner` (`features/workbench/application/`) реализуется только в `lib/app/` через `SecretMigrator` из `package:codelab_embedded/io.dart` (app уже импортирует его из `lib/app/`; `codelab_setup` app не нужен) с тем же `CODELAB_HOME`, `CODELAB_CONFIG` и окружением, что у открывателя; тексты ошибок — без `error.toString()`; виджеты к файлам и хранилищу не обращаются; `--force` в app не предлагается.
* Приложение, запущенное из Finder (macOS), получает минимальное окружение и не видит переменных `CODELAB_SECRET_*` оболочки. Рабочий путь в 1.0 — `secrets.backend: file` в конфиге и ключ, записанный `codelab secret set` (design.md change `add-embedded-agent-mode`, D5).
* Значения секретов живут только в памяти и проходят через `SecretAdmin`; в виджетах, состоянии (Cubit/`SessionView`), логах и диагностике их быть НЕ ДОЛЖНО — только имя секрета и признак «задан».
* Условие macOS App Sandbox: сейчас `com.apple.security.app-sandbox = false` в `macos/Runner/*.entitlements`. Если песочницу включат, бэкенды файла и ОС потребуют пересмотра — это отдельный change, а не правка на месте.

## Локализация

Change `add-desktop-localization` (D1–D5, D7, D9, D12). Языки `en` и `ru`; язык применяется сразу, без перезапуска.

* **Каталог.** `lib/l10n/app_en.arb` (шаблон) и `app_ru.arb`; код генерирует `fvm flutter gen-l10n` (`l10n.yaml`) и коммитится; `melos run l10n:check` ловит устаревший сгенерированный код. Ключи camelCase `<экран><элемент><смысл>`, у каждого сообщения `@key.description` с контекстом. Количество — только ICU `plural` (в `ru` формы `one|few|many|other`), склейка фраз и `n == 1 ? … : …` запрещены: одно сообщение с плейсхолдерами. Эталон `en` совпадает со спецификацией символ в символ.
* **Три вида текста (D5).** (1) Текст виджета берётся в `build` через `context.l10n` (`lib/l10n/l10n.dart`), а у кита — через его каталог. (2) Производный текст в состоянии Cubit-а — функция `(входы, язык)`: язык — явный вход проекции, переведённую строку, которую нельзя пересобрать из входов, Cubit не хранит. (3) Разовое сообщение (исход действия) хранится как типизированное сообщение (sealed-класс с аргументами), текст собирает presentation. Делегат кита `CodeLabLocalizations.delegate` стоит рядом с делегатами app в `FluentApp` (`CodeLabApp`) и в тестовом `localizedFluentApp`: без него кит остаётся на английском; названия панелей дока app получает от кита (`toolPaneTitleOf`), а не из `ToolPane`.
* **`AppStrings` в Cubit-ах с текстом.** Единственный владелец языка — `AppLanguageCubit` (root scope); Cubit-у приходит узкий порт `AppStrings` (`current`, `changes`). Подписка одна, создаётся в конструкторе, отменяется в `close()`; событие после `close` игнорируется; по событию пересобирается вся проекция из последних входов. Список Cubit-ов с текстом (D12): `ConnectionCubit`, `ActiveSessionCubit`, `SessionsCubit`, фасад `CodeLabShellCubit` (своей подписки нет: палитра берёт каталог из `parts.strings.current` при пересчёте за частями), `ConnectionSettingsCubit`, `AddProfileCubit`, `ProviderSettingsCubit`, `ProviderWizardCubit`. `SecretMigrationCubit` в списке нет: в его состоянии нет текста от языка (сбои типизированы, текст диалога собирает presentation), подписки у него нет. Новый Cubit с текстом в состоянии добавляется в список и получает тест смены языка.
* **Страницы «Connection», «Providers» и мастер (итерация 4; D6 «Тексты моста настроек»).** `ConnectionSettingsCubit`, `AddProfileCubit`, `ProviderSettingsCubit` и `ProviderWizardCubit` принимают обязательный `AppStrings` и пересобирают производный текст при смене языка: подписи строк профилей (в том числе встроенного агента — `localizedProfileTitle`, `profileSummary`), «Behavior», ошибки полей формы по `ProfileDraftIssueCode`, подсказки токена, подписи строк провайдеров и итоги проверок (хранятся данные `ProviderCheckOutcome`, подписи строит `ProviderCheckView.of`), сводка и уведомление мастера. Разовые сообщения хранятся типизированными: `ConnectionSettingsFailure`, `AddProfileFailure`, `ProviderMessage` (баннеры), `ConfirmingPlaintext(origin, hasToken)`; текст строит presentation (`providerMessageText`, `addProfileFailureText`). Тексты моста `codelab_setup` app переводит **по типу**, а не по готовой строке: `wizardErrorText` — по `errorCode` и `refusal`, `wizardKeyNotice` — по `literalKeyInConfig`, `wizardReviewWarnings` — по `notVerified`, `wizardPresetLabel` и строка «Type» — по `ProviderPreset.id`, `keyStatusLabel` — по виду `KeyStatusView`; дубль «ключ уже есть» скрывает `isKeyAlreadyStoredError` (по коду). Сравнивать `error`, `message` или `label` моста и ядра со строками ЗАПРЕЩЕНО (D5, п. 5). Как есть остаются тексты хранилища секретов (`readOnlyHint`, `unavailableReason`, `ProfileSaveFailed.storeReason`, причина `ProviderKeyNotStored`) и `ConfigIssue.message` внутри переведённой рамки.
