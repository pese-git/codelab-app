## Встроенный агент

* Встроенный агент работает в процессе приложения через мост `codelab_embedded`: профиль (строка «Embedded agent» страницы «Connection», первая в списке) `ConnectionProfile.embedded(id: 'embedded', hostProfile: 'embedded-app-desktop')` (D9). Прямой импорт `package:codelab_agent_*` по-прежнему запрещён (корневой `AGENTS.md` §5; правило `apps/codelab_desktop` сторожа).
* Границы барелей моста (D3, правила `packages/dart/codelab_architecture_tests/test/support/rules.dart`):
  * `package:codelab_embedded/io.dart` (`localEmbeddedAgentOpener`) импортируется только из `lib/app/` — composition root;
  * `package:codelab_embedded/testing.dart` запрещён во всём `lib/`: сценарий модели в релизную сборку не попадает (D8). Сценарный открыватель передают только тесты и `integration_test/` через шов `createCodeLabRootScope(embeddedOpener:)` (D9);
  * основной барель `package:codelab_embedded/codelab_embedded.dart` web-безопасен и сторожем внутри app не ограничен.
* `EmbeddedTransportResolver` и адаптер `Logger` → логгер приложения лежат в `lib/app/`; `app_scope.dart` регистрирует резолвер вторым резолвером `ClientWorkspace` и закрывает его (`close()`) при закрытии root scope, до `AcpClientApplication` (D9). Ожидание `close()` ограничено 10 с, как в CLI: по истечении — событие `embedded.close_timeout` уровня `warning`, освобождение транспорта и `AcpClientApplication` продолжается (D9, «Таймаут закрытия»). Резолвер сериализует `open`: сначала `await` `dispose()` прежнего агента, затем открыватель. Агент, вернувшийся из открывателя после отмены подключения, сразу получает `dispose()` и текущим не становится (корневой `AGENTS.md` §12; D6, «Резолвер клиента»).
* Поводов отмены подключения два — новый Connect или Reconnect и `close()` резолвера при закрытии root scope. Кнопки Disconnect нет, публичный API `TransportResolver` и `ClientWorkspace` ради встроенного агента не меняется (решение L4, подтверждено пользователем 2026-11-02; D6, «Отмена подключения в app»). Disconnect — отдельный change клиентского слоя для всех типов подключения. Вытесненная попытка подключения не меняет состояние: `ClientWorkspace` ведёт номер попытки, а `ConnectionCubit` не пишет для неё ни `failed`, ни «started» (D6, «Устаревшая попытка в `ClientWorkspace`»).
* Невалидный или отсутствующий конфиг — `ConnectionFailed`, резолвер переводит `EmbeddedAgentConfigException` в `ClientWorkspaceException(message)`, и баннер показывает его текст без имени класса (проблемы загрузчика и подсказку `codelab config check`); нет ключа провайдера — соединение открывается, первый ход даёт заметку «Failed turn» (D5).

## Профили подключения и настройки

* Экран настроек и страница «Connection» — feature `lib/features/settings/` (`application/`: `ConnectionSettingsCubit`, `DefaultProfileResolver`, `ConnectionCommands`; `presentation/`: `SettingsShell`, `ConnectionPage`). Переходы рабочее место ↔ настройки — только `NavigationCubit` (`lib/app/navigation/`); виджеты не открывают настройки маршрутом `Navigator`.
* Профили подключения app и CLI — один файл `$CODELAB_HOME/profiles.json` (`CODELAB_HOME` непуст, иначе `~/.codelab`), один `JsonFileProfileStore` из `codelab_client_io` (D7). Путь и окружение даёт `ConnectionEnvironment` (`lib/app/connection_environment.dart`; правило дома — `resolveCodelabHome` из `codelab_client_io`, общее с CLI) из шва `createCodeLabRootScope(environment:)`; тесты подставляют хранилище швом `profileStore:`. Битый или незнакомый файл не перезаписывается: страница показывает ошибку, а «Add profile», «Rename» и «Remove» недоступны (целостность данных, корневой `AGENTS.md` §2).
* Без явного выбора профиль по умолчанию — **встроенный агент**; выбор — ключ `shared_preferences` `codelab.connection.default_profile`, «Connect on start» — `codelab.connection.connect_on_start` (порт `ConnectionPreferences` в `lib/core/platform/`). `default` — второе имя встроенного агента: запись `default` в `profiles.json` игнорируется, страница предлагает её удалить (D5, D21). Встроенный агент в файл не пишется.
* Токен профиля — **только ссылка**: `env:<NAME>` или `secret:<имя>` (design.md change `add-provider-setup-ui`, D13). Значение читает `ProfileSecretSource(environment, stored: …)` из `codelab_client_core` в момент открытия транспорта (`env:` — из окружения, `secret:` — из хранилища секретов агента через порт `ProfileSecrets`, без кэша); в профиле, состоянии (Cubit), журнале, диагностике и на экране его нет, строка показывает только источник. `InMemorySecretSource` в app не используется. Приложение из Finder (macOS) не видит переменных оболочки — это видно в строке профиля («<NAME> is not set in CodeLab's environment.»).
* Четыре варианта токена диалога (D14, отступление от артборда — «From environment variable», D24): «No token», «Use stored secret» (имена `ProfileSecrets.names()`), «Store a new token» (`PasswordBox` без режима подглядывания; значение — `SecretText` в `NewSecretToken` черновика, сбрасывается при закрытии диалога), «From environment variable». Запись «секрет → профиль» с откатом и «профиль → секрет» при удалении выполняет `ProfileCommitter` (kit): Cubit-ы не пишут в хранилище секретов сами. Отказ записи, откат и удаление дают события `connection_profile.token_*` (D18) только с `profile_id` и `backend`: имён секретов, значений и `toString()` исключений в событиях нет. Строка профиля с `secret:` — `Token secret <имя>` и тег `<backend> · set|missing` по `ProfileSecrets.isSet` (значение не читается); «Remove» собственного секрета `codelab/profiles/<id>/token` показывает флажок «Also delete the stored token …» (по умолчанию включён), чужой секрет не удаляется никогда. Правила `ws://` (подтверждение «Test anyway»/«Save anyway») действуют для всех вариантов, кроме «No token», и сбрасываются при смене секрета и значения токена.
* События журнала настроек — логгер `codelab_desktop.settings`, компонент `settings` (D17): без токенов, аргументов и `env` stdio, имени переменной токена, путей и query URL, без `toString()` исключений (только имя типа).
* Диалог «Add connection profile» (`features/settings/`: `AddProfileCubit` и закрытая иерархия `AddProfileState` в `application/`, `AddProfileDialog` в `presentation/`; D11–D14). Правила черновика — `ProfileDraft`, проверка — `ProfileProbe` из `codelab_client_core`; composition root собирает `ProfileProbe` с теми же резолверами, что у `ClientWorkspace`, и классификатором `classifyProbeFailure`. Cubit создаётся на каждое открытие диалога и закрывается вместе с ним (закрытие отменяет проверку); «задана ли переменная токена» он узнаёт из `Map<String, String>` окружения composition root, значения не читает; незаданная переменная даёт ОДНУ заметку «<NAME> is not set in CodeLab's environment.» под полем токена — в блоке Check её нет. Тексты исходов проверки — без адреса, аргументов, `env` и сообщения транспорта (`probeOutcomeText`; команда показывается только в `Command not found: <command>`, D12); события — `connection_profile.*` по D17. «Test connection» строки и «Rename» — `ConnectionSettingsCubit.testProfile` и `renameProfile`.
* Строка «Current» бывает только при живом соединении (`Connected` или `Reconnecting`) и «Connect» не показывает (`ConnectionProfileRow.canConnect`): переподключение — «Restart agent» блока Behavior. У `Connecting…`, `Failed` и остальных строк «Connect» есть. Заголовки `ContentDialog` (диалог профиля, подтверждение «Remove profile …?») — `CodeLabDialogTitle` из `codelab_ui` (20 px, w600), не крупный заголовок по умолчанию.
* `ConnectionCubit` подключает окно по профилю (`connect([profile])`, `reconnect()`) и реализует узкий `ConnectionCommands`; страница «Connection» вызывает только его. Форма подключения (`ConnectionSetupDialog`, `TransportSetupPanel`, поля `stdioCommand` и т. п.) удалена (D6).

## Страница «Providers»

* Feature `lib/features/settings/` (design.md change `add-provider-setup-ui`, D5, D10, D21): `application/` — `ProviderSettingsCubit`, закрытая иерархия `ProviderSettingsState` (`Loading | ReadOnly | Unreadable | Ready`, запись — флаг `Ready.saving`) и порт `ProviderSettingsSession`; `presentation/` — `ProvidersPage` (тело `settings-providers`) в `settingsPageBuilders`, страница в `defaultSettingsPages` и ключевые слова поиска `provider`, `model`, `api key`, `key storage`, `base url`. Cubit создаётся на каждое открытие страницы (`CodeLabDependencies.createProviderSettingsCubit`), страница вызывает `reload()` и закрывает его.
* **Чьи настройки** решает `resolveSettingsAccess` моста `codelab_setup`: профиль текущего подключения (`Connected`/`Reconnecting`), без подключения — профиль по умолчанию (`DefaultProfileResolver`). Встроенный агент и stdio-`codelab-agent` — `EditableSettings` (`CODELAB_HOME` из `env` stdio-профиля, иначе дом app из `ConnectionEnvironment.codelabHome`; папка проекта — для stdio только при «Run in the project folder»); WebSocket — `RemoteReadOnly`, чужой stdio-агент — `NotManaged`: локальный конфиг НЕ читается (SETUP-2), страница показывает InfoBar `providers-read-only` и текущую модель сессии. Смена подключения перечитывает доступ. Имя агента из `initialize` в `WorkspaceState` не доступно, поэтому для stdio решает команда профиля.
* **IO только в `lib/app/`:** `provider_settings_session.dart` (`openProviderSettingsSession`) собирает `ClientSecretAccess`, `FileAgentConfigStore` и `ioProviderCheck` из `codelab_setup/io.dart` для дома, `--config` и окружения агента (окружение app плюс `env` stdio-профиля) и переоткрывается при каждой загрузке страницы, как хранилище токенов профилей (D3). `ReopenableProfileSecrets` страница не использует: ей нужен не порт токенов, а открытое хранилище по дому агента. Шов тестов — `createCodeLabRootScope(providerSettingsOpener:)`.
* **Check:** ключ читается ТОЛЬКО в адаптере `lib/app/` (`ClientSecretAccess.read` или переменная `api_key_env` окружения агента) и сразу передаётся `ProviderCheck` в `SecretValue`; в Cubit, состояние, события и логи значение не попадает (SETUP-1), порт сессии получает лишь ссылку `KeyStatusView`. Ключа нет (`Key: missing`) — запрос не отправляется. Номер проверки на строку отбрасывает поздний итог; закрытие страницы отбрасывает все (`provider_settings.check_discarded`). Повторный Check строки, закрытие страницы, смена подключения, исчезновение или удаление провайдера отменяют `CancelToken` проверки: мост закрывает соединение, `CheckCancelled` и поздний итог отбрасываются. Check неактивна для литерального ключа в `config.yaml` (значение app не читает; подсказка `codelab secret migrate`); под строкой с `http://` к нелокальному хосту — предупреждение «The key is sent unencrypted to <host>.» (SETUP-10, правило локальных хостов `isLocalHost` общее с `ProfileDraft`).
* **Запись** — только мост: «Default model» пишет `SetValue('agent.default_model')` в слой, где ключ определён сейчас, если он редактируемый, иначе в `user`; «Remove» — `ProviderRemover` одним `apply`, секрет удаляется после `ConfigSaved` (SETUP-24). Пока идёт запись (`saving`), повторные действия игнорируются; конфликт даёт баннер `providers-banner` и перечитывание, без автоповтора (SETUP-6). Битый `config.yaml` — `Unreadable` с проблемами загрузчика, файл не пишется. Проектный слой применяет загрузчик моста только для доверенного проекта (`trusted_projects`); страница отдельной проверки не делает.
* События — логгер `codelab_desktop.settings`, `provider_settings.{loaded,unreadable,check_started,check_finished,check_discarded,default_model_changed,removed}` (D18): только `provider_id`, виды и числа, без имён секретов и переменных, адресов, текстов исключений.
* Кнопки «Add provider» и «Edit» неактивны до мастера провайдера (итерация 3 change; подсказка из D10); разметка и ключи (`providers-add`, `providers-edit-<id>`) уже совпадают с артбордом `Providers`.

## Секреты

* Секреты (ключи провайдеров, токены) читаются и пишутся только через общие бэкенды `codelab_agent_io` — через `package:codelab_setup/io.dart` (`ClientSecretAccess`, `secretReadOnlyHint`; тот же файл реэкспортирует `SecretAdmin`, `DescribedSecretStore`, `SecretStoreUnavailableException` и `Logger`) и встроенный агент через `codelab_embedded`. Приложение не импортирует `package:codelab_agent_*` напрямую (корневой `AGENTS.md` §5).
* **`package:codelab_setup/io.dart` импортируется только из `lib/app/`** (composition root; правило сторожа, design.md change `add-provider-setup-ui`, D20): `lib/app/client_profile_secrets.dart` (`openProfileSecrets`, `ClientProfileSecrets`) открывает `ClientSecretAccess` для `CODELAB_HOME` и превращает исходы `SecretAdmin` в порт `ProfileSecrets` kit; подсказку бэкенда только для чтения строит `secretReadOnlyHint` (первая буква заглавная, в конце точка: «Secret store env is read-only. …», D3). Cubit-ы, application и presentation получают только порт `ProfileSecrets`. В `lib/features/settings/presentation/` запрещены `dart:io` и `codelab_setup/io.dart` (SETUP-9). Хранилище первый раз открывается в `main` до сборки scope (`ProfileSecrets.backend` синхронный) и передаётся швом `createCodeLabRootScope(profileSecrets:)`; затем `ReopenableProfileSecrets` открывает его заново (фабрика `profileSecretsOpener`) при каждом открытии диалога «Add connection profile» и страницы Connection, поэтому правка `secrets.backend` применяется без перезапуска (D3); тесты подставляют `FakeProfileSecrets`, без шва хранилище «не открыто» и только для чтения. Событие `secrets.client.backend` пишет scope.
* `flutter_secure_storage` и другие Flutter-плагины хранения секретов на desktop НЕ ИСПОЛЬЗУЮТСЯ: у приложения, CLI и автономного агента ОДНО хранилище (общий файловый бэкенд `$CODELAB_HOME/secrets.yaml` и переменные `CODELAB_SECRET_*`; после 1.0 — общие записи хранилища ОС, change `add-agent-os-secret-backends`), иначе записи разошлись бы (D15, D16).
* Перенос секретов из файла конфига встроенного агента (задача 8.11; design.md change `add-config-literal-secrets-and-migrate`, D8): признак `EmbeddedAgent.secretsInConfig` резолвер передаёт в `SecretMigrationOffer` (`lib/app/`); порт `SecretMigrationRunner` (`features/workbench/application/`) реализуется только в `lib/app/` через `SecretMigrator` из `package:codelab_embedded/io.dart` (app уже импортирует его из `lib/app/`; `codelab_setup` app не нужен) с тем же `CODELAB_HOME`, `CODELAB_CONFIG` и окружением, что у открывателя; тексты ошибок — без `error.toString()`; виджеты к файлам и хранилищу не обращаются; `--force` в app не предлагается.
* Приложение, запущенное из Finder (macOS), получает минимальное окружение и не видит переменных `CODELAB_SECRET_*` оболочки. Рабочий путь в 1.0 — `secrets.backend: file` в конфиге и ключ, записанный `codelab secret set` (design.md change `add-embedded-agent-mode`, D5).
* Значения секретов живут только в памяти и проходят через `SecretAdmin`; в виджетах, состоянии (Cubit/`SessionView`), логах и диагностике их быть НЕ ДОЛЖНО — только имя секрета и признак «задан».
* Условие macOS App Sandbox: сейчас `com.apple.security.app-sandbox = false` в `macos/Runner/*.entitlements`. Если песочницу включат, бэкенды файла и ОС потребуют пересмотра — это отдельный change, а не правка на месте.

## Тесты

* Widget-тесты работают с `InMemoryProfileStore` (`test/support/`): настоящий файл внутри `testWidgets` зависает в fake-async зоне, а `profiles.json` проверяют обычные `test` (`app_scope_profiles_test.dart`, `connection_settings_cubit_test.dart`). `CodeLabTestBinding` по умолчанию хранит профиль по умолчанию — stdio-агента (`stdioDefault: true`); тесты правила «нет выбора — встроенный агент» передают `stdioDefault: false`.
* Интеграционные тесты подключаются через временный `CODELAB_HOME` с `profiles.json` и «Connect» в строке страницы «Connection» (`integration_test/support/e2e_agent.dart`: `E2eLaunch.connect`).
* Интеграционный прогон со встроенным агентом — `CODELAB_E2E_AGENT=embedded` (скрипт `test:e2e:app:embedded`, вне `check`): сценарный открыватель и сценарии `integration_test/llm_scripts/`. Как все `test:e2e:app:*`, он запускается на устройстве или симуляторе только в `release/<version>`; в `feature/*` и `hotfix/*` — только `fvm flutter analyze` (корневой `AGENTS.md` §21; D10).
