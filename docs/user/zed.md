# Агент CodeLab в Zed

[Zed](https://zed.dev) умеет запускать внешних ACP-агентов. `codelab-agent serve --stdio` — такой агент: Zed запускает процесс и общается с ним по протоколу ACP через stdin/stdout.

Формат настроек Zed принадлежит Zed и меняется между версиями; в этом репозитории он не описан. Пример ниже — минимальный, сверьте его с документацией вашей версии Zed (раздел про внешних агентов, ключ `agent_servers`). Совместимость с Zed проверяется в воротах MVP по чек-листу Zed (`design.md` change [`switch-default-agent-to-dart`](../../openspec/changes/switch-default-agent-to-dart/design.md#чек-лист-zed-98)); пока чек-лист не подписан, пример не подтверждён проверкой.

## Шаг 1. Соберите агента и настройте модель

```bash
fvm dart run melos run build:agent   # результат: build/bin/codelab-agent
```

Запомните абсолютный путь к бинарю: Zed, запущенный не из терминала, не видит ваш `PATH`.

Настройте провайдера и проверьте конфиг — как в [configuration.md](configuration.md):

```bash
codelab-agent config check
```

Агент запускается с рабочей папкой проекта, который открыт в Zed, и читает глобальный `$CODELAB_HOME/config.yaml` и проектный `.codelab/config.yaml` так же, как в других клиентах.

## Шаг 2. Добавьте агента в настройки Zed

Откройте настройки Zed (`settings.json`) и добавьте:

```json
{
  "agent_servers": {
    "CodeLab": {
      "type": "custom",
      "command": "/абсолютный/путь/к/codelab-agent",
      "args": ["serve", "--stdio"],
      "env": {}
    }
  }
}
```

Откройте панель агентов Zed и начните новый разговор с агентом `CodeLab`.

## Шаг 3. Передайте ключ, не записывая его в настройки Zed

`settings.json` обычно лежит в репозитории с dotfiles, поэтому ключ в `env` не пишите. Два надёжных способа:

- **Секрет в хранилище.** В конфиге провайдера укажите `api_key_secret: codelab/openai`, включите файловый бэкенд и сохраните значение:

  ```bash
  codelab-agent config set secrets.backend file
  codelab-agent secret set codelab/openai   # спросит значение; ввод не отображается
  ```

  Значение не набирают в командной строке (оно останется в истории оболочки). Способ для скриптов и подробности — в [configuration.md](configuration.md#шаг-2-задайте-ключ-api). В настройках Zed тогда нет ни ключа, ни имени переменной.
- **Переменная окружения.** `api_key_env: OPENAI_API_KEY` в конфиге и сама переменная в окружении процесса. Zed, запущенный из терминала (`zed .`), передаёт процессам агента окружение этой оболочки; запущенный из меню — нет.

Если нужен другой каталог состояния, задайте `"env": { "CODELAB_HOME": "/путь" }`: там будут конфиг, секреты и сессии.

Локальной модели (LM Studio, Ollama) ключ не нужен.

## Разрешения и режимы

Агент спрашивает у Zed разрешение на опасные действия (правки, команды) по правилам режима. Новая сессия стартует в режиме `standard` — он и рекомендуется: чтение без вопросов, правки и команды — с разрешением. Режим меняется в Zed селектором режима агента, ключом `permissions.mode` или флагом запуска, например `"args": ["serve", "--stdio", "--permission-mode", "standard"]`.

Режимы `plan`, `ask`, `standard`, `accept-edits`, `bypass` доступны всеми тремя способами. `autopilot` включается только флагом запуска `--permission-mode autopilot`: ни селектор Zed, ни конфиг, ни переменная `CODELAB_PERMISSION_MODE` его не включают.

`bypass` и `autopilot` выполняют правки и команды без вопросов. Включайте их только в доверенном проекте или в песочнице. Критические команды (например, `rm -rf /` или `curl … | sh`) в `bypass` всё равно спрашиваются, а в `autopilot` запрещены; сетевой доступ в `autopilot` тоже запрещён.

## Если что-то не работает

- **Агент не появляется или сразу падает.** Запустите ту же команду в терминале: `codelab-agent serve --stdio`. Ошибка конфигурации придёт в stderr с файлом и строкой, код выхода `64`. Причину покажет и `codelab-agent config check`.
- **Логи агента.** Агент пишет логи в stderr. В файл логи идут, только если вы их попросили: флаг `--log-file <путь>` в `args` или `logging.file` в конфиге. Каталог `$CODELAB_HOME/logs` и файл по умолчанию агент сам не создаёт. Подробнее — `--log-level debug`; `trace` включайте только для отладки (см. ниже).
- **Журналы сессий.** Каждый разговор записывается в `$CODELAB_HOME/sessions/<папка-проекта>/…jsonl` (по умолчанию `~/.codelab/sessions`).
- **Протокольный журнал.** Отдельного файла `acp-trace.jsonl` в этой версии агент не пишет. Кадры ACP смотрите в журнале ACP самого Zed: просмотр «ACP logs», команда палитры `dev: open acp logs` (детали — в документации Zed).

Значения из хранилища секретов и ключи API агент не логирует. Но на уровне `trace` stderr MCP-серверов попадает в лог без редактирования, а до выпуска 1.0 тексты промптов и вывод инструментов не редактируются ни в журнале сессии, ни в логах. Журнал ACP Zed тоже содержит разговор целиком. Не публикуйте журналы и логи, не просмотрев их — [подробнее](configuration.md#что-попадает-в-логи-и-журналы).
