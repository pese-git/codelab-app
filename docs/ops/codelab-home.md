# Каталог `CODELAB_HOME`

`CODELAB_HOME` — каталог настроек и данных CodeLab. Его общими файлами пользуются оба клиента — терминальный `codelab` и настольное приложение CodeLab app, — встроенный агент внутри них и отдельный `codelab-agent`. Здесь — где лежит каталог и что в нём общего. Что пишет каждое приложение сверх этого, описано в его руководстве по эксплуатации.

## Где лежит каталог

| Значение `CODELAB_HOME` | Каталог |
|---|---|
| не задана или пустая | `~/.codelab` (`%USERPROFILE%\.codelab` в Windows) |
| `~` или `~/…` | раскрывается в домашний каталог из `HOME` (или `USERPROFILE`) |
| абсолютный путь | этот путь |
| `~user/…` | ошибка: `CODELAB_HOME: ~user is not supported, use an absolute path` |

Домашний каталог берётся из `HOME`, а если он пуст или не задан — из `USERPROFILE`. Значения `~`, `~/…` и ошибка для `~user/…` одинаковы для `codelab`, app и `codelab-agent`; у `codelab-agent` ошибка в значении — код выхода `64`.

Если нет ни `CODELAB_HOME`, ни домашнего каталога, `codelab` сообщает `Cannot find the home folder: set CODELAB_HOME or HOME.` и завершается. App запускается, но сохранённые профили подключения и хранилище секретов недоступны: обращение к ним завершается ошибкой с этой причиной. `codelab-agent` в этом случае ошибки не даёт: он молча берёт `./.codelab` в папке, из которой запущен, — задайте `CODELAB_HOME` или `HOME` явно.

## Общие файлы

| Путь | Что | Кто пишет |
|---|---|---|
| `$CODELAB_HOME/config.yaml` | глобальная конфигурация агента: провайдеры, модель, MCP-серверы, бэкенд секретов | `codelab config set`, `provider`, `mcp`, мастер провайдера в `codelab` и app, страницы «Providers» и «MCP servers» app; вы |
| `$CODELAB_HOME/profiles.json` | профили подключения к внешним агентам | `codelab profiles add` и `remove`; страница «Connection» app |
| `$CODELAB_HOME/secrets.yaml` | значения секретов открытым текстом, права `0600`; только при `secrets.backend: file` | `codelab secret set`, мастер провайдера, диалог профиля app |
| `$CODELAB_HOME/sessions/` | журналы сессий встроенного агента, по подкаталогу на папку проекта; другой каталог задаёт `sessions.dir` в конфигурации | встроенный агент |

- Профиль, сохранённый в app, сразу виден в `codelab -a <id>`, и наоборот: это один файл.
- Встроенный агент в `profiles.json` не записывается. Запись с id `default` клиенты не используют: `default` — второе имя встроенного агента.
- Если `profiles.json` повреждён или в незнакомом формате, клиенты его не перезаписывают.
- Секреты в `secrets.yaml` общие для `codelab`, app и `codelab-agent`. Другого хранилища секретов у app нет.
- Слои конфигурации проекта (`<проект>/.codelab/config.yaml`, `<проект>/.codelab/config.local.yaml`) лежат в папке проекта, а не в `CODELAB_HOME` — [слои конфигурации](../user/configuration.md#слои-конфигурации).

Что из этих файлов может содержать личные данные и ключи — в [что попадает в логи и журналы](../user/configuration.md#что-попадает-в-логи-и-журналы).

## Изолированный каталог

Чтобы запустить клиент с отдельными настройками — в CI, для проверки или для демонстрации, — задайте свой каталог:

```bash
export CODELAB_HOME="$PWD/.codelab-ci"
```

В CI заранее создайте каталог с правами `0700`: не каждый режим клиента создаёт его сам с такими правами.
