# 11. Допущения и открытые вопросы

> Часть предложения [«Dart-агент и клиенты CodeLab»](../dart-agent-and-clients.md). Status: Accepted. Исходные решения, связанные документы и порядок чтения — в оглавлении.

**Допущения** (приняты для этого документа, проверить при утверждении):

1. Монорепо (**подтверждено** владельцем репозитория 2026-10-22, веха M0): агентские пакеты добавляются в этот репозиторий (его стоит переименовать в общий
   `codelab`). Альтернатива — отдельный репозиторий, который тянет `codelab_acp_protocol` как
   git-зависимость; тогда contract test клиент ↔ агент становится сложнее.
2. Формат конфигурации агента — YAML (`config.yaml`, agent-core-architecture §15): тот же
   разборщик и профиль, что у frontmatter определений агентов и skills, и редактор с сохранением
   комментариев (`yaml_edit`). Существующий `codelab.toml` не читается: при нём без
   YAML-конфига агент пишет одно предупреждение `config.legacy_found`, настройки переносятся
   вручную по таблице §15.7 (решение пользователя 2026-10-29, change `add-agent-configuration`). Профили
   подключения клиентов — JSON (`~/.codelab/profiles.json`): их пишут UI и `codelab profiles`, а
   разбор JSON уже есть в проекте.
3. Существующие JSON-сессии Python не переносятся: форматы разные, журналы живут в разных каталогах (agent-core-architecture §8.9, §16.1).
4. Python TUI заменяется codelab_cli; Web UI через textual-serve не нужен после перехода.
5. Имена команд: клиент — `codelab` (привычная пользователям команда), агент — `codelab-agent`.
   Сейчас `codelab` в Python объединяет `serve` и `connect`; после перехода `codelab serve` остаётся
   переходным алиасом на `codelab-agent serve`: он есть в первой `stable` с пометкой deprecated и
   снимается первой minor-версией после условия удаления Python-агента; алиаса `codelab connect`
   нет (change `retire-python-agent`, D11; решения пользователя 2026-11-10, Q3, Q7).
6. melos 8 читает конфигурацию из секции `melos:` корневого `pubspec.yaml` (**подтверждено** в задаче 0.1: `melos.yaml` уже не читался, три скрипта из него были недоступны), поэтому `melos.yaml`
   можно удалить (проверить на этапе 0 командой `melos list` до и после).

**Открытые вопросы.** Столбец «Блокирует веху» — какую веху
[дорожной карты](../delivery-roadmap.md) нельзя закрыть без ответа: M3 MVP (этап 9, все Must и
переключение по умолчанию) или M4 Продукт 1.0 (публичный релиз, задача 9.4). Вопросы о
подписи, ключах релиза и домене блокируют только 9.4, то есть M4: MVP — внутренняя сборка без
публичного релиза.
