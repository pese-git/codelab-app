# 9.14. Этап 9 — Цели Must и переключение по умолчанию

> Часть предложения [«Dart-агент и клиенты CodeLab»](../dart-agent-and-clients.md). Status: Accepted. Исходные решения, связанные документы и порядок чтения — в оглавлении.

← [9.13. Этап 8 — MCP, конфигурация, AGENTS.md](09-13-stage-8-mcp-config.md) · [Оглавление](../dart-agent-and-clients.md) · [9.15. Этап 10 — Мобильные и web](09-15-stage-10-mobile-web.md) →

**Цель.** Dart-агент становится агентом по умолчанию в обоих клиентах; Python-агент и Python TUI
выводятся из эксплуатации.

**Задачи.**

1. **9.1. Автоматическая проверка доказательств:**
   `packages/dart/codelab_architecture_tests/test/parity_evidence_test.dart` разбирает таблицы
   матрицы целей и для каждой строки Must проверяет, что доказательство существует и прошло:
   `acp/<id>` — файл фикстуры; `cli/<id>` — тест с таким именем в `apps/codelab_cli/test/e2e`;
   `app:<файл>` — файл в `apps/codelab_app/integration_test`; `core/<id>` — тест в агентских
   пакетах. Существования мало: тест читает машинные отчёты последнего ночного прогона CI
   (JUnit XML `codelab test-scenario --junit` и `dart test --reporter json` всех наборов,
   артефакт `parity-results/`) и требует для каждого доказательства статус `pass`; `skip`
   (в том числе тег `scripted-only` в режиме `dart`) и отсутствие в отчёте считаются
   незакрытой строкой. Падает со списком строк и причиной: `missing` (нет файла или теста),
   `not-run` (нет в отчёте), `failed`, `skipped`.
2. **9.2.** Закрыть оставшиеся строки Must (по отчёту 9.1).
3. **9.3. Профили по умолчанию:** в app — «Встроенный агент» (не нужен отдельный бинарь) и
   встроенный профиль «codelab-agent (stdio)» с командой `codelab-agent serve --stdio` вместо
   `codelab serve --stdio` в `codelabAgentStdioProfile`; в CLI — `embedded`.
4. **9.4. Поставка** (Should — не блокирует MVP; веха «продукт 1.0») по §12.7: `release.yml`, артефакты `codelab` и `codelab-agent` для пяти
   целей, подписанный `SHA256SUMS`, скрипты `install.sh` / `install.ps1` и каналы (U-29),
   происхождение сборки; инструкция установки. Переключение по умолчанию МОЖЕТ выйти
   `beta`-релизом; первый публичный `stable`-релиз выпускается только вместе с подписанными
   дистрибутивами app (D-16, REL-4) и опубликованной политикой конфиденциальности (D-18,
   REL-9, §12.7.7). До первого релиза заменить `com.example.codelabApp` и
   `PRODUCT_COPYRIGHT` в `AppInfo.xcconfig`, создать платформы `windows` и `linux` app.
5. **9.5. Предупреждение о Python-сессиях** в пользовательской документации: сохранённые сессии
   Python-агента не переносятся, мигратора нет (agent-core-architecture §16.1, задача 3.7).
6. **9.6. Онбординг** (Should — не блокирует MVP): нет ключа провайдера → мастер в CLI и экран настройки в app вместо голой
   ошибки (U-17, D-05; §12.4.3–§12.4.5).
7. **9.7. Документация** по чек-листу `docs/architecture/adr/README.md`: `AGENTS.md`
   дописывается окончательно, а не создаётся — правила агентских пакетов и TDD внесены на
   этапе 0 (задача 0.11), вложенные `AGENTS.md` новых пакетов — на их этапах; здесь §5
   (структура монорепозитория) приводится к итоговому составу пакетов;
   `layers-and-dependencies.md`, `acp-boundary.md` (агентская сторона), `permissions.md`,
   `testing.md` (включая правило TDD §9.0 п.3 с исключениями (а)–(д): красный тест из критерия
   матрицы до кода, пары "тест → реализация" в `tasks.md`; и правило итераций §9.0 п.8: unit-тесты
   на каждое новое поведение, интеграционные — на каждую пересечённую границу), `platform-integration.md`,
   `technology-stack.md`
   (`args`, `yaml`, `yaml_edit`, `toml` только для чтения `codelab.toml`); пользовательская
   документация: установка (скрипты §12.7.5, проверка подписи вручную — `docs/release/verify.md`),
   README репозитория со ссылками на установку и `PRIVACY.md` (D-18), конфигурация (`config.yaml`), LiteLLM Proxy как `baseUrl`, миграция с
   `codelab.toml` командой `codelab config migrate`.
8. **9.8. Ручная проверка совместимости с Zed** — чек-лист ниже («Чек-лист Zed»); проводит
   ответственный за релиз. Сверка с другим ACP-агентом — не на глаз, а диффом trace на том же
   сценарии (там же).
9. **9.9. Заморозка и удаление:** с переключения Python-агент получает только исправления
   безопасности (заморозка — часть MVP). Удаление — после одного релизного цикла без регрессий:
   после переключения опубликована одна версия канала `stable` (первая такая версия выходит с
   вехой «продукт 1.0», 9.4) и до решения об удалении в трекере нет открытой регрессии, связанной
   со строкой Must матрицы. Тогда Python-агент удаляется вместе с Python TUI отдельным change
   `retire-python-agent`; команда `codelab` принадлежит CLI, `codelab serve` — алиас на
   `codelab-agent serve` в течение этой одной `stable`-версии.
10. **9.10. Чтение `codelab.toml`:** после переключения по умолчанию чтение устаревшего файла
    объявляется устаревшим — подсказка при старте (agent-core-architecture §15.7) называет срок
    удаления. Само удаление читателя, `package:toml` и команды `config migrate` — отдельный
    OpenSpec change `remove-legacy-codelab-toml` после вывода Python-агента (9.9); до него
    `core/config-reads-legacy-codelab-toml` остаётся обязательным тестом.
11. **9.11. Решение о песочнице ОС (P-13):** пересмотреть Won't «сейчас» по модели угроз после
    переключения по умолчанию: оставить границу папки и одобрения, песочница только на macOS или
    полноценная песочница на трёх ОС (agent-core-architecture §16.3). Итог — ADR; при решении
    «делать» — строка P-13 в матрице получает приоритет и этап, при «не делать» — снимается
    пометка «сейчас».

**OpenSpec change.** `switch-default-agent-to-dart` (scope: профили по умолчанию, онбординг,
предупреждение о непереносимых Python-сессиях), `add-release-pipeline-and-installer` (scope:
поставка 9.4, U-29, §12.7.2–§12.7.6, §12.7.8), `add-signed-app-distributions` (D-16) и
`add-privacy-policy` (D-18, §12.7.7) и `retire-python-agent` (scope: заморозка, сроки удаления,
алиасы команд). Смена значения по умолчанию `ui.mode` в CLI с `line` на `tui` после приёмки
U-12 — отдельный OpenSpec change, не входящий в эти два (§12.2.1). `tasks.md` — пары
"тест → реализация" со ссылкой на критерий (§9.0, правило 3); для 9.2 — по строке Must из
отчёта 9.1.

**Чек-лист Zed (9.8).** Версия Zed фиксируется в `design.md` change `switch-default-agent-to-dart`
(номер версии и дата) и не меняется во время проверки. Zed запускает
`codelab-agent serve --stdio` как внешнего агента; доказательство каждого шага — скриншот и
фрагмент ACP trace агента (`$CODELAB_HOME/logs/acp-trace.jsonl`, agent-core-architecture §12.5;
для сверки полей — debug-сборка с `logging.trace_payload: true`). Результаты — таблица в
`design.md` со ссылками на файлы; проверку проводит и подписывает ответственный за релиз.

| № | Шаг | Пройдено, если | Не пройдено, если |
|---|---|---|---|
| 1 | подключение | Zed показывает агента готовым; в trace `initialize` с ответом `protocolVersion: 1` | ошибка подключения, нет ответа за 10 с |
| 2 | возможности | ответ `initialize` содержит `loadSession`, `promptCapabilities`, `mcpCapabilities`; Zed не сообщает о несовместимости | Zed отключает функцию из-за ответа агента |
| 3 | промпт и стриминг | текст приходит частями до ответа на `session/prompt`; все `session/update` хода — раньше ответа | текст появляется только целиком или после ответа |
| 4 | инструмент и одобрение «разрешить» | `tool_call` → `session/request_permission` → после «allow» — `tool_call_update` `completed` | вызов без запроса одобрения или зависание |
| 5 | одобрение «отклонить» | после «reject» — `tool_call_update` `failed`, ход продолжается и завершается `end_turn` | ход обрывается ошибкой |
| 6 | файлы | чтение и правка идут через `fs/read_text_file` и `fs/write_text_file` Zed; правка видна в буфере Zed | агент пишет файл мимо клиента при объявленной `fs` |
| 7 | терминал | команда идёт через `terminal/create` и `terminal/output`, вывод виден в Zed | команда выполняется мимо клиента при объявленном `terminal` |
| 8 | отмена | отмена в Zed даёт `session/cancel`; ход завершается `stopReason: cancelled` за 5 с | ход продолжается или ответ — ошибка |
| 9 | `session/load` | после перезапуска Zed сессия открывается; реплей `session/update` до ответа на `session/load` восстанавливает историю | история пуста или дублируется |
| 10 | режим и модель | смена режима и модели в Zed даёт `session/set_config_option` (или `session/set_mode`), следующий ход идёт в новом режиме | значение не меняется или ошибка |
| 11 | отключение | закрытие агента в Zed завершает процесс `codelab-agent` за 5 с, журнал сессии дописан | процесс остаётся или журнал повреждён |

Сверка с другим ACP-агентом: если для сверки выбран агент, его имя и версия записываются в
`design.md`; шаги 3–5 и 8 прогоняются в Zed на одном и том же промпте с ним и с
`codelab-agent`, trace обоих нормализуются (id, время, тексты модели) и сравниваются по порядку
методов и форме сообщений. Пройдено: одинаковый порядок «все `session/update` до ответа на
`session/prompt`», отказ не завершает ход у обоих, лишние поля не ломают Zed. Если агент для
сверки не выбран, сверка не проводится — чек-лист выше достаточен.

**Что прочитать.** Матрица целей целиком, особенно блок «не регрессировать» и критерий вывода
Python-агента; `docs/architecture/adr/README.md`.

**Definition of Done.**

Ворота MVP (все пункты обязательны):

* `fvm dart test packages/dart/codelab_architecture_tests/test/parity_evidence_test.dart` зелёный
  на отчётах ночного прогона: у каждой строки Must статус `pass`.
* Все условия критерия вывода Python-агента из матрицы целей (§6 матрицы) выполнены; таблица
  условий с доказательствами в `proposal.md` change `switch-default-agent-to-dart` подписана
  владельцем продукта (решение о переключении) и ответственным за релиз (доказательства и
  сборка).
* «Три ночи подряд»: ночной CI-прогон (`schedule` в `.github/workflows/ci.yml`, §9.5) наборов `test:e2e:app:*`,
  `test:e2e:app:dart-agent`, `test:e2e:app:embedded`, `test:e2e:cli` и `parity_evidence_test`
  зелёный в трёх последовательных запусках по расписанию на одной ветке `main` без ручного
  перезапуска упавших заданий; любой красный или пропущенный запуск обнуляет счёт. Ссылки на
  три запуска — в `proposal.md`.
* Чек-лист Zed (9.8) пройден по всем 11 шагам, версия Zed и доказательства записаны в
  `design.md`, подписан ответственным за релиз.
* Профили по умолчанию переключены (9.3), Python-агент заморожен (9.9), предупреждение о
  Python-сессиях (9.5) и документация 9.7 опубликованы.

Если сделано (Should — не блокирует MVP):

* 9.4 — выпуск по §12.7 (веха «продукт 1.0»); 9.6 — онбординг U-17 и D-05 с тестами §12.4.13.
* Удаление Python-агента (9.9) — после одной `stable`-версии, вне ворот MVP.

**Зависимости.** Этапы 7 и 8.

**Риски.** Функция текущего CodeLab не попала в цели и теряется — блок «не регрессировать» в
матрице, составленный по OpenSpec specs Python-агента. Пользователи с `codelab serve` в скриптах
— алиас на один релиз и предупреждение.
