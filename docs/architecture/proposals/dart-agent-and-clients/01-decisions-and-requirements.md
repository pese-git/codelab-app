# 1. Исходные решения и требования

> Часть предложения [«Dart-агент и клиенты CodeLab»](../dart-agent-and-clients.md). Status: Accepted. Исходные решения, связанные документы и порядок чтения — в оглавлении.

[Оглавление](../dart-agent-and-clients.md) · [2. Факты о текущей системе](02-current-system.md) →

**Решения, принятые пользователем:**

| Вопрос | Решение |
|---|---|
| Основа ядра | **собственная архитектура встраиваемого ядра, описанная в [agent-core-architecture.md](../agent-core-architecture.md)**; ядро пишется с нуля, без зависимости от стороннего ядра агента и без форка |
| Цели | каталог целевых возможностей в охвате «ядро + CLI и десктоп» с приоритетами и сценариями приёмки ([agent-parity-goals.md](../agent-parity-goals.md)) |
| Эталон поведения | **спецификация ACP + golden ACP-фикстуры + интеграционные тесты codelab-app и codelab_cli**; дифференциальный паритет с Python-агентом не требуется |
| Python-агент | **второй этап**: источник наработок, если понадобятся (§7б); работает параллельно, пока не закрыты цели уровня Must, затем удаляется |
| Платформы ядра | **десктоп + мобильные + web**: ядро на чистом Dart без `dart:io` и Flutter |

**Функциональные требования:**

- F1. Ядро агента доступно как Dart-библиотека: хост создаёт сессию, отправляет промпт и подписывается на поток событий без сериализации.
- F2. То же ядро доступно как ACP-агент по stdio и WebSocket; поведение для внешних ACP-клиентов (codelab-app, Zed) не меняется.
- F3. codelab-app может работать в двух режимах: с внешним агентом по ACP (как сейчас) и со встроенным ядром.
- F3a. Разрабатывается терминальный клиент **codelab_cli**. Он работает с агентом по ACP так же, как codelab-app (внешний агент по stdio/WS или встроенный), и поддерживает headless-режим `-p`. CLI заменяет Python TUI.
- F4. Закрыть цели уровня Must из матрицы целей, включая блок «не регрессировать» — функции текущего CodeLab.
- F5. Закрыть критические дефекты текущего Python-агента **архитектурно, а не латками**:
  1. проверку разрешений можно обойти: часть инструментов (в том числе MCP) исполняется мимо общей точки проверки;
  2. граница рабочей папки проверяется строковым префиксом: путь `/proj_evil` проходит проверку для `cwd=/proj`;
  3. «разрешить всегда» запоминается по виду инструмента (`edit`, `execute`), а не по инструменту и аргументам;
  4. запрос разрешения приходит без аргументов вызова: пользователь не видит команду и путь;
  5. агент отправляет статус tool call `cancelled`, которого нет в ACP; строгий клиент отбрасывает такое обновление целиком.

**Нефункциональные требования:**

- N1. Ядро компилируется для VM (AOT), Flutter (macOS / iOS / Android) и web (dart2js / wasm).
- N2. Ошибки провайдеров и инструментов не роняют ход (ошибки как события).
- N3. Отмена доходит до HTTP, процессов и ожиданий клиента.
- N4. Все исполнения инструментов проходят одну точку проверки разрешений.
- N5. Границы пакетов и запрет IO в ядре проверяются в CI, а не на ревью.
- N6. Каждый этап плана оставляет репозиторий в рабочем состоянии: `melos run check` зелёный, codelab-app работает с текущим Python-агентом до этапа 9.
