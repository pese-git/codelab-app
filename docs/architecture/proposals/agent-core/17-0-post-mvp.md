# 17. Спецификации после MVP

> Часть [архитектуры ядра агента CodeLab](../agent-core-architecture.md). Status: Accepted. Общие соглашения, термины и порядок чтения — в оглавлении.

← [16. Что не входит в MVP и открытые вопросы](16-non-mvp-and-open-questions.md) · [Оглавление ядра](../agent-core-architecture.md) · [17.1. Web-инструменты: `web_fetch` и `web_search`](17-1-web-tools.md) →

Раздел описывает возможности уровня **Should** из матрицы целей
([agent-parity-goals.md](../agent-parity-goals.md)), которые реализуются после MVP: web-инструменты,
skills и субагенты — после переключения на Dart-агента (этапы 8 и 9+), вынос огромного
результата инструмента — на этапе 3 вместе с журналом (его расширение ACP — после 9),
настройка агента (секреты, предконфигурация из окружения, запись и живая перезагрузка конфига,
реестр настроек, переподключение MCP) — на этапе 8 (секреты — на этапе 7 вместе со встроенным
агентом, страница MCP в app — 9+); управление сессиями (переименование, ветки, перемотка, fork,
lease), steering посреди хода, инструмент `lsp` поверх языковых серверов и фоновые команды — на
этапе 9+. Там же, на этапе 9+, — возможности уровня **Could**: провайдеры и устойчивость LLM
(Gemini, пул ключей, роли моделей, вход по подписке, совместимость Kimi, MiniMax, Z.AI, диагностика
зависаний, инструменты через промпт), дополнительные инструменты (картинки, архивы и SQLite в
`read`, якоря строк, память, `inspect_image`, `checkpoint`, `ask`, `session_history`,
`discover_tools`), цикл и безопасность (режимы-промпты, супервизия зависшего инструмента, проверка
ответа, дедлайн, перезапись и запрет секретов), масштаб сессий (большие журналы, экспорт
траектории, структурное сжатие) и расширения (пользовательские хуки, плагины на Dart, обмен
настройками провайдеров, прогон Terminal-Bench), а также связь с другими агентами по A2A: удалённые
агенты как субагенты (**Should**) и агент как A2A-сервер (**Could**). Устройство
подразделов то же, что у §1–§15: назначение → контракт →
алгоритм → примеры → инварианты → обоснование → как проверить. Каждый подраздел опирается на
контракты MVP и перечисляет, какие из них расширяет; эти расширения уже внесены в
соответствующие разделы и помечены ссылкой на §17.
