## Карточки

### SMK-01. Проектный конфиг берётся из папки процесса агента, а не сессии (P1)

**Где:** `apps/codelab_agent` (загрузка конфига при `serve`), `apps/codelab_desktop` (смена папки).

**Шаги:** desktop подключён к stdio-профилю с «запускать в папке проекта» в проекте A → «Open folder» → проект B,
у которого `.codelab/config.yaml` с `mcp.servers` (B в `trusted_projects`) → новая сессия → попросить вызвать
MCP-инструмент.

**Факт:** сессия работает в B (`ls` видит файлы B), но агент отвечает «у меня нет инструмента». Лог:
`host.config.loaded … project_root: <A>` — процесс агента остался в A, проектный слой B не загружен.
После «Reconnect» агент перезапускается в B, MCP подключается.

**Ожидание:** проектные слой, доверие и MCP-серверы соответствуют `cwd` сессии. Варианты: агент
разрешает проектный слой по `cwd` из `session/new`/`session/load`; и/или desktop перезапускает
stdio-агента при смене папки, если профиль запускается в папке проекта.

**Риск:** проектные `permissions`, `mcp.servers` и `trusted_projects` применяются от другого проекта.

### SMK-02. Инструмент неизвестного вида подписан «read-only» (P1)

**Где:** `packages/dart/codelab_client_acp/lib/src/domain/approval_policy.dart`, `_riskForKind`:
`ToolKind.other` и `null` → `ApprovalRiskLevel.readOnly`.

**Факт:** MCP-инструмент без `annotations` (агент даёт `ToolKind.other`) в карточке одобрения CLI —
`(read-only)`, в desktop — зелёная метка «Read-only». Агент тот же вызов относит к уровню `exec`
(лог `permission.asked … tier: exec`). Автоодобрения нет (`decidePermission` не вызывается), дефект в подписи.

**Ожидание:** неизвестный вид — не «read-only» (`AGENTS.md` §10: неизвестная capability по умолчанию
опасна); например, отдельная метка «unknown» или уровень не ниже `shell`.

### SMK-03. Правка одобряется без diff (P1)

**Где:** CLI (`approval_prompt.dart`), desktop (карточка одобрения и инструмента), ACP-проекция агента.

**Факт:** ни в CLI, ни в desktop diff не показан ни до одобрения, ни после — только сырой JSON
`oldText`/`newText` в деталях `{}` и «Overwrote calc.py (66 bytes)» после. В desktop карточка
«Edit calc.py», а модель перезаписала файл целиком и потеряла функцию `mul`. В журнале сессии diff есть.

**Ожидание:** diff (или хотя бы явная пометка «перезапись файла целиком») в карточке одобрения
`edit`/`write`. Модель — `kit` (dart-agent-and-clients §12.1), CLI §12.2.5, app §12.3.3 (U-11, D-07).

### SMK-04. После «Open folder» список сессий и метка устаревшие (P2)

**Факт:** под новым проектом показаны сессии старого проекта, в шапке новой сессии — имя старого
проекта; исправляется только после «Reconnect». Связано с SMK-01.

### SMK-05. Ответ только в reasoning даёт повтор ответа (P2)

**Факт:** Qwen через LM Studio иногда кладёт весь финальный ответ в reasoning (`thinking`), блока `text`
нет. Цикл считает ответ пустым, отправляет `loop_nudge: empty_response`, модель отвечает снова —
пользователь видит ответ дважды (сначала как мысли, потом текстом). В журнале сессии — сообщения
`assistant` с одним `thinking` и `stopReason: stop`.

**Ожидание:** решить политику для ответа «только thinking» (например, считать его ответом, если reasoning
не скрытый и шаг завершён без вызова инструмента). Меняет поведение цикла — через OpenSpec.

### SMK-06. Нет событий жизненного цикла сессии в логе агента (P2)

**Факт:** при `--log-level debug` в логе есть `permission.*`, `mcp.server.*`, `acp.cancel`,
`loop.empty_response`, но нет создания и загрузки сессии, начала и конца хода, запросов к LLM
(модель, токены, длительность, ошибки). Нарушает `AGENTS.md` §16.

**Ожидание:** показывать хвост stderr агента при падении до инициализации.

### SMK-13. Отображение в REPL (P3)

* Мысли следующего шага приклеиваются к тексту ответа без перевода строки («…вычитание.Я получил…»).

### SMK-14. `config check` (P3)

* Пока в конфиге есть ошибка, предупреждения (например, `config.project.untrusted_key`) не печатаются —
  исправлять приходится в два захода.
* Без `agent.default_model` результат «invalid», хотя `serve` с `--provider/--model` работает.

### SMK-15. Headless `--approve read-only` отклоняет `ls` и `search` (P3)

**Факт:** спецификация `cli-headless` разрешает только вид `read`; `ls` и `search` агента — вид `search`.
Режим «только чтение» на практике почти бесполезен. Поправить спецификацию (разрешить `search`).

### SMK-16. Одобрение до проверки containment (P3)

**Факт:** пользователя спрашивают про `List /`, который затем всё равно отклоняется как выход за рабочую
папку. Безопасность не страдает, но запрос лишний.

### SMK-17. Формат вывода `read` и `edit` слабых моделей (P3)

**Факт:** `read` выводит `1| def add…`; 9B-модель переносит пробел после `|` в `oldText` (`" def add…"`),
`edit` трижды подряд падает с «No exact match». Рассмотреть разделитель без пробела или табуляцию,
либо подсказку в ошибке `edit`.

### SMK-18. Не проверено в TUI (P3)

* Shift+Enter во вкладке терминала отправил сообщение — выяснить, ограничение терминала или TUI;
  проверить Alt+Enter.
* Esc-отмена хода в TUI в журнале не подтверждена.
