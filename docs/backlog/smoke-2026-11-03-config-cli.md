## Карточки

### SMK-31. `config unset` отклонялся из-за ошибок, скрытых ступенчатой проверкой (P1, исправлено)

**Где:**
- `packages/dart/codelab_agent_core/lib/src/config/resolve.dart` (`_resolve`: ошибка слоя обрывает поздние ступени);
- `packages/dart/codelab_agent_io/lib/src/config/config_writer.dart` (сравнение базы и кандидата, R3-1).

**Шаги:** в `config.yaml` под `providers.lm` одновременно литеральный `api_key: sk-fake-1` и неверный
`base_url: "https://u:p@ss@host/v1"` → `codelab config check` → `codelab config unset providers.lm.api_key`.

**Факт:**
- `config check` показывал одну проблему, `api_key`;
- `config unset` завершался кодом `1` и называл `providers.lm.base_url` и `agent.default_model … not in the model catalog`.

Обе проблемы были в файле и до правки. Ошибка ранней ступени скрывала их в базе сравнения, поэтому R3-1 считал их новыми.
Исправить конфиг, правленный руками и содержащий больше одной ошибки, через CLI было практически нельзя. Правка проходила
только в «правильном» порядке, который пользователь знать не может.

**Решение:** R3-3 (решение пользователя 2026-11-03; `design.md` D5, спека `agent-configuration`).
- База и кандидат проверяются полной проверкой без обрыва ступеней, со всеми каскадными ошибками.
- Правило доверия считается по исходным слоям, до вырезания.
- Если полную проверку кандидата не удалось довести до конца, запись отклоняется: `config.validation.incomplete`, fail-closed.
- Проблемы сравниваются по мультимножеству сигнатур.
- Ревью безопасности прошло четыре прохода, финальный вердикт SAFE.

**Риск до исправления:** для безопасности нет, отказ консервативный. Пользователь не мог убрать литеральный секрет командой.

### SMK-32. `provider list` при невалидном конфиге печатает только ошибку (P3)

**Где:** `packages/dart/codelab_agent_io/lib/src/cli/provider_commands.dart` (`list`).

**Шаги:** пустой `CODELAB_HOME` → `codelab config set budget.max_steps 40` → `codelab provider list`.

**Факт:** вывод — только строка `<home>/config.yaml: agent.default_model: required`. Нет ни `Secrets: <backend>`, ни
списка провайдеров из файлов.

**Ожидание:** `provider list` показывает `Secrets:` и провайдеров из файлов слоёв даже при невалидном итоге, а проблемы
итога — отдельными строками `warning:`. Иначе нельзя посмотреть, что уже настроено, пока не задана модель по умолчанию.
Выход сейчас есть — `provider add … --default`, — но он неочевиден. Меняется вывод подкоманды, поэтому нужна правка
спеки `agent-configuration`.

**Риск:** нет.

### SMK-33. Проблема незаданного ключа привязана к файлу последнего слоя (P3)

**Где:** привязка `source` у проблем итога без ключа в файлах (`agent.default_model: required`), загрузчик
`codelab_agent_io` / ядро `codelab_agent_core`.

**Шаги:** пустой `CODELAB_HOME` → `codelab config set budget.max_steps 5 --local` → `codelab provider list --cwd <proj>`.

**Факт:** `<proj>/.codelab/config.local.yaml: agent.default_model: required`. Ключ не задан ни в одном слое, а сообщение
отсылает к файлу проекта.

**Ожидание:** проблема обязательного ключа, которого нет ни в одном файле, указывает на итог (`config`), либо на
пользовательский `config.yaml` как слой записи по умолчанию. Тогда подсказка ведёт туда, куда `config set` запишет ключ.

**Риск:** нет. Сообщение вводит в заблуждение, где чинить.
