In shortCodeLab has no telemetry. Your prompts, files and command output go only to the model provider and tools you set up yourself.

1. No telemetry

Neither the app, the codelab CLI nor the embedded agent sends usage analytics, crash reports or installation identifiers. No analytics SDK is included.

2. Network requests

This is the complete list. Anything not listed here never leaves your computer.

WhereWhenWhat is sentHow to turn it off
The model provider you configuredEvery turnPrompt, session history, files and command output the agent read, your API keyConfigure no provider, or use a local model (Ollama)
MCP servers in your configWhen the agent calls one of their toolsThe call's argumentsRemove the server
Web tools web_fetch, web_searchAfter you approve the callThe URL or the search queryApproval mode, or deny the tool
Release site [SITE]CLI update check, at most once per 24 h; codelab update; the installer. The app does not checkA plain file request: IP and User-Agent: codelab/<version>, no identifiersupdate.check: false or the pinned channel

Commands you run or approve make their own requests. External ACP agents follow their own policies.

3. What is stored on this computer

  • ~/.codelab — configuration, sessions and their journals, logs.
  • API keys — in the system keychain, never in plain files.
  • App preferences — in the app's local preferences store.

4. Third-party policies

Data sent to your model provider or an MCP server is handled under that service's own terms and privacy policy.

5. Contact and changes

Questions: [CONTACT FROM SECURITY.md]. Every change to this policy is listed under “Privacy” in the release notes, with the revision date above.
