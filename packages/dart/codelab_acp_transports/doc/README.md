# Руководство по транспортам ACP

Руководство для разработчика объясняет, как устроен пакет `codelab_acp_transports`: что такое порт `AcpTransport`, чем отличаются пять реализаций, почему барелей два и как транспорт живёт от `start()` до `close()`. Прочитав его, вы запустите тесты, найдёте причину сбоя соединения и добавите свой транспорт.

Руководство описывает код как он есть. Нормы лежат в спецификации `openspec/specs/agent-transports/spec.md` и в [`AGENTS.md`](../AGENTS.md) пакета. Состав API и короткие примеры — в [README пакета](../README.md).

## Порядок чтения

1. [Начало работы](00-getting-started.md) — подготовка репозитория, анализ и тесты (какие нужны процессы и сокеты), проверки репозитория, как посмотреть события транспорта, отладка, карта «что изменить — куда смотреть».
2. [Устройство транспортов](01-design.md) — контракт порта и коды ошибок, два бареля и правило web-безопасности, кадрирование, каждая реализация, жизненный цикл со схемами, ошибки запуска, кто что буферизует.
3. [Тестирование, расширение и частые проблемы](02-extending-and-troubleshooting.md) — приёмы тестов, рецепт нового транспорта со скелетом и тестом, «симптом → причина → что сделать», ссылки на спецификации.

## Что где лежит

| Файл `lib/` | Содержимое |
|---|---|
| `lib/codelab_acp_transports.dart` | основной барель, web-безопасный |
| `lib/io.dart` | барель на `dart:io` |
| `lib/src/acp_transport.dart` | порт, состояния, события, ошибки |
| `lib/src/transport_configs.dart` | конфигурации и `codelabAgentStdioProfile` |
| `lib/src/in_process_acp_transport.dart` | пара в памяти |
| `lib/src/io/` | клиентские и серверные транспорты на `dart:io`, разбор кадров агента |
