# AGENTS.md — codelab_client_core

Правила этого пакета дополняют корневой `AGENTS.md`. Источник архитектуры — `docs/architecture/proposals/dart-agent-and-clients/09-10-stage-5-client-kit.md` и `design.md` OpenSpec changes `extract-acp-client-kit`, `add-session-list-and-reload` (список, загрузка и восстановление сессий) и `add-command-palette-agent-commands` (каталог команд); поведение — spec `acp-client-kit`.

## 1. Назначение

Общий клиентский слой ACP без UI: рабочее пространство (`ClientWorkspace`), соединение (`ConnectionView`, профили и их разбор, резолверы транспорта, ссылка на токен профиля `ProfileTokenRef` и общий источник `ProfileSecretSource` (`env:<NAME>`), правила id профиля `isValidProfileId`, `reservedProfileIds`, `suggestProfileId` и `usableStoredProfiles` в `profile_ids.dart`, черновик профиля формы `ProfileDraft` с проверкой и выбором токена `ProfileTokenChoice`), сессии (`SessionHandle`, `SessionView`), транскрипт (`TranscriptItem`, `ToolRowView`, виды субагентов; проектор `TranscriptProjector` внутренний и барелем не экспортируется), очередь промптов (`PromptQueue`), одобрения, опции и команды агента (`ConfigOptionView`, `AgentCommandView`), каталог команд палитры (`CommandCatalog`, `HostCommand`: слияние команд хоста и агента, конфликты имён, нечёткий поиск), расход сессии (`lib/src/usage/`: `UsageDecoder`, `UsageFold`, `UsageView` в `SessionView.usage`; change `add-usage-extension`), инспектор (`InspectorProjection`), диагностика (`WorkspaceDiagnostic`, `describeFailure`), чтение папки проекта для панели Files (`lib/src/files/`: порт `ProjectFiles` и модели, чистые правила `normalizeRelativePath`, `classifyPreview`, `isMaybeSecretFileName`, `relativeToRoot`, `sortProjectEntries`; реализация на `dart:io` — `IoProjectFiles` в `codelab_client_io`; change `add-file-preview-and-tree`), восстановление после перезапуска хоста (`WorkspaceRestorer`, `WorkspaceSnapshot`), порты хранилищ (`ProfileStore`, `RecentProjectsStore`, `WorkspaceSnapshotStore`). Его используют `apps/codelab_desktop` (через Cubit-ы рабочего места и фасад `CodeLabShellCubit`) и `apps/codelab_cli`. Хосты только отображают `WorkspaceState` и `SessionView`; политика — когда слать, как реагировать на сбой, что считать «сессия занята» — живёт здесь.

## 2. Границы

* Пакет — чистый Dart и web-безопасен: `lib/**` НЕ ДОЛЖЕН импортировать `dart:io`, `dart:isolate`, `dart:ffi`, `dart:html`, `dart:js_interop`, `package:web`, `package:flutter`, `package:codelab_acp_transports/io.dart` (правило в `codelab_architecture_tests/test/support/rules.dart`, design D11).
* `dependencies` — только подмножество `{codelab_client_acp, codelab_acp_protocol, codelab_acp_transports, freezed_annotation, meta, collection, async}` (`pubspec_allowlist_test.dart`, design D2). Расширение — через OpenSpec change.
* Kit не открывает процессы и сокеты: транспорт из профиля строит `TransportResolver`, который регистрирует composition root. `dart:io`-адаптеры клиента — в `codelab_client_io`.
* Секреты не хранятся в профилях и состоянии: у `WebSocketProfile` только ссылка `tokenRef` (`ProfileTokenRef`: `env:<NAME>` — `EnvTokenRef`, `secret:<имя>` — `SecretTokenRef`; голое имя и `secret:` с недопустимым именем — `UnsupportedTokenRef` с маскированным `toString()`), значение даёт `SecretSource` — общий `ProfileSecretSource(environment, stored:)` для CLI и app, без кэша (design.md change `add-app-settings-shell`, D13, D15; change `add-provider-setup-ui`, D13).
* Хранилище секретов профилей — порт `ProfileSecrets` (бэкенд, `names`, `isSet`, `store`, `delete`, `read`; результаты `Stored`/`Exists`/`ReadOnly`/`Failed`/`Deleted`/`NotSet` без значений): kit не зависит от `codelab_setup` и пакетов агента, реализацию даёт composition root хоста. Значение нового токена хранится только в черновике и состоянии и только как `SecretText` (`toString()` и JSON — `***`); `reveal()` вызывается лишь в адаптере хранилища; печатать и сохранять его иначе ЗАПРЕЩЕНО.
* `ProfileCommitter` — единственное место политики «токен ↔ профиль»: `save` — перечитать id → `store` секрета `codelab/profiles/<id>/token` (`Exists` → `tokenSecretExists` без записи) → `ProfileStore.save` → при отказе удалить созданный секрет; `remove` — сначала профиль, затем (только после успеха, только собственный `codelab/profiles/<id>/token` и только если на него не ссылается другой профиль) секрет; ошибка удаления секрета профиль не восстанавливает (SETUP-19, SETUP-24; change `add-provider-setup-ui`, D13).
* Источник данных — порт `AgentBackend`; реализация `AcpClientBackend` поверх `AcpClientApplication`. Use case-ы `codelab_client_acp` kit не использует (design D3).
* Членов, помеченных в плане «после MVP», и заглушек для них в коде нет.

## 3. Модели и потоки

* Неизменяемые модели — freezed, как в `codelab_client_acp`; после изменения моделей — `fvm dart run build_runner build --delete-conflicting-outputs`, сгенерированные `*.freezed.dart` в git не хранятся (`.gitignore`), CI создаёт их шагом `Generate code` (`.github/actions/prepare`).
* Состояние соединения — закрытая иерархия `ConnectionView`, а не набор флагов (`AGENTS.md` §8).
* Поздние события старого соединения не меняют состояние: их отбрасывает бэкенд, kit на это опирается и проверяет тестом (`AGENTS.md` §9).
* `ClientWorkspace.dispose` отписывается от бэкенда и закрывает потоки kit; бэкенд и `AcpClientApplication` закрывает их владелец.
* Список сессий проекта — часть `WorkspaceState`: открытые сессии, затем сессии агента со статусом `notLoaded`; курсор `session/list` живёт только в kit и не сохраняется (ACP), следующую страницу даёт `loadMoreSessions` (design D3 `add-session-list-and-reload`).
* `reconnect` загружает открытые сессии через `session/load`, сначала активную; без `loadSession` или при ошибке загрузки сессия становится `detached` с уведомлением, а не подменяется новой (design D5). `session/cancel` перед заменой транспорта kit не шлёт.
* **Темы (`src/themes/`, change `add-app-appearance-page`, D2, D3).** Формат пользовательской темы, разбор (`ThemeFile.parse`, нестрогий: предупреждения не отменяют тему, ошибки отменяют), закрытый набор ролей `ThemeRole`, значения цвета `ThemeColorValue`, читатель JSON с позициями `json_spans.dart` и порт каталога `ThemeLibrary` (`list`, `read`, `import`) с `InMemoryThemeLibrary`. Результат разбора ЯЗЫКОНЕЗАВИСИМ: `ThemeIssue` — код (`ThemeIssueCode`), позиция (строка и колонка с 1, UTF-16) и аргументы (`key`, `value`, `hint`), без английской строки; текст строит клиент (app — по ARB, CLI — своими строками). Файлов пакет не читает: `dart:io`-адаптер — `IoThemeLibrary` в `codelab_client_io`. Применять роли к виджетам ядро не умеет и не должно: это дело app.

## 4. Восстановление и снимок

* Восстановление включает `ClientWorkspace(snapshots: …)`; алгоритм — `WorkspaceRestorer` в `lib/src/restore/`, его закрытые операции — через внутренний `RestoreHost`, не экспортируемый из бареля (design D6).
* Снимок содержит только проект, активную сессию и открытые сессии `(id, cwd)`. Курсоры, транскрипты, очереди, профили и секреты в снимок НЕ ДОЛЖНЫ попадать; тест `test/restore/workspace_snapshot_test.dart` это проверяет.
* Формат снимка кодирует и разбирает kit (`WorkspaceSnapshot.encode`/`decode`, `version`); хранилище видит только строку. Изменение формата — новая версия и OpenSpec change.
* Порядок: `restoreProject()` при старте хоста, шаги восстановления — внутри первого успешного `connect()` и один раз за запуск. До `restoreProject()` снимок не пишется.
* Снимок, дочитанный после первого успешного подключения запуска (`_connectedOnce`), отдаёт проект хосту, но его сессии не восстанавливаются — ни сейчас, ни при reconnect — и не попадают в следующую запись снимка: иначе reconnect отправил бы `session/load` без действия пользователя.
* Старт без восстановления: `startWithoutRestore()` — альтернатива `restoreProject()` для хоста, который не хочет открывать проект прошлого запуска (в desktop — настройка «Reopen the last project», D9 `add-app-general-page`). Снимок не читается, проект не выбирается, первое подключение ничего по снимку не восстанавливает, но запись снимка разрешена, и первая запись заменяет прошлый снимок текущим. Хост вызывает при старте ровно один из двух методов; повторный и одновременный вызов `restoreProject()` возвращает результат первого без повторного чтения, повторный `startWithoutRestore()` и вызов второго метода после первого — пустая операция (`restoreProject()` после `startWithoutRestore()` возвращает `null`).
* Записи не накладываются и идут без таймера: серия синхронных изменений — одна запись, изменения во время записи — одна следующая; `dispose` и `flushSnapshot()` дожидаются последней. Ошибка чтения или записи — `WorkspaceDiagnostic`, а не отказ операции.
* Восстановление ничего не отправляет агенту само: ни промптов, ни ответов на одобрения.
* Сессии снимка принадлежат его проекту: если хост выбрал другой проект (через `selectProject` или папку в `connect`), восстановление отменяется, а неоткрытые сессии снимка в следующую запись не попадают.

## 5. Расширения `_meta.codelab.*`

* Разбор `_meta.codelab.*` — только здесь и в `codelab_client_acp`; виджеты и app (`apps/codelab_desktop`, `apps/codelab_cli`) `_meta` НЕ ПАРСЯТ и берут готовые поля `ToolCallView`, `PlanEntryView`, `SubagentRowView` и `ApprovalRequest` (корневой `AGENTS.md` §7; design.md change `add-subagents-and-tasks`, D51 Т7).
* `codelab_client_acp`, `domain/domain_models.dart`: `subagentMetaOf` (`_meta.codelab.subagent` кадра вызова как есть → `ToolCallRecord.subagentMeta`; запрос потомка идёт в `ApprovalRequest.subagentRequester`), `outcomeOf` (`outcome`), `parentToolCallIdOf` (`parentToolCallId` кадров `tool_call`/`tool_call_update`). Слияние поздних кадров, не стирающее известные `outcome`, `parentToolCallId` и `subagentMeta`, — в `domain/state_machines.dart`. Согласованные при `initialize` расширения — `CodelabExtensions.parse` в `domain/codelab_extensions.dart`.
* `codelab_client_core`: `parseSubagentCall`, `parseSubagentSummary`, `parseSubagentFailure`, `parseSubagentRequester` (`transcript/subagent_views.dart`) строят `ToolCallView.subagentCall`, `subagentSummary` и представление спрашивающего; `taskChangeOf` (`plan._meta.codelab.taskChange`, `transcript/task_ops.dart`) даёт операции над задачами; `taskMetaOf` и `PlanEntryView.of` (`session/session_views.dart`) читают `_meta.codelab.task` пункта плана (`id`, `owner`, `blockedBy`).
* Разбор терпимый: неизвестные ключи и неверная форма значения означают «данных нет», а не ошибку обработки обновления; поздний кадр без поля не стирает известное значение.
* Usage (change `add-usage-extension`, D8, D21): `codelab_client_acp` маршрутизирует `_codelab/session/usage` в поток `usageNotifications` (`sessionId`, сырые `params`, поколение соединения) и читает `_meta.codelab.budgetExceeded` ответа `max_turn_requests` в `PromptTurn.budgetExceeded`; здесь `UsageDecoder` (`usage/usage_decoder.dart`) — единственный разбор формы (деньги — целые микроединицы, без `double`), `UsageFold` — чистая свёртка по `seq` и поколению, `ClientWorkspace` применяет снимок в `SessionView.usage` одной ревизией и сбрасывает его при `session/load` и смене соединения (не по `suspend()`). Записи журнала kit — `usage.stale`, `usage.decode_failed` (не чаще раза на сессию и поле), `usage.unknown_session`; сумм и текста уведомления в них нет. Бюджет хода (change `add-desktop-usage-pane`, D7, D9): `UsageDecoder` разбирает необязательное поле `budget` снимков `step`/`turn` (`UsageBudget`: `steps`, `tokens`, `cost`, `duration`; неверное подполе отбрасывается с `usage.decode_failed` `field: budget.<подполе>`), `UsageFold.apply(..., receivedAt:)` кладёт его в `UsageView.budget` (`TurnBudgetView`: `turnId`, `receivedAt` по часам рабочего пространства, `ended` — итог хода) и стирает при новом ходе без `budget`; снимки без `turnId` бюджет не меняют, сброс — тот же `UsageFold.initial`. Заметка хода с причиной бюджета — `_stoppedNoticeText` в `transcript/transcript_projector.dart`.
* Журнал usage сессии (change `add-usage-ledger`, D6, D9, D10): `codelab_client_acp` объявляет признак `CodelabExtensions.usageLedger` (только целое `version: 1`; клиент ключ НЕ объявляет) и `AcpClientApplication.requestUsageLedger` — сырой результат `_codelab/session/usage/ledger` и поколение отправки; здесь `UsageLedgerDecoder` (`usage/usage_ledger_decoder.dart`) — единственный разбор ответа, а деньги, валюта и причины разбираются общими функциями `usage/usage_parsing.dart` вместе с `UsageDecoder`. `SessionView.usageLedger` — закрытая иерархия `UsageLedgerState` (`unavailable`, `idle`, `loading`, `loaded`, `failed`), ведёт её `ClientWorkspace.refreshUsageLedger` (один запрос в полёте на сессию, вызовы во время полёта сливаются в один следующий, `rebuild` побеждает; ответ старого соединения или до `session/load` отбрасывается с `usage.ledger.stale`). Kit журнал со снимками не складывает: когда обновлять, решает хост по `usageLedger.view.seq` и `usage.lastSeq`. Снимок `trigger: "load"` (`UsageTrigger.load`): usage и журнал сбрасываются В НАЧАЛЕ `session/load`, а снимок для загружаемой, но ещё не зарегистрированной сессии ждёт регистрации (при сбое загрузки — `usage.unknown_session`). Записи kit: `usage.ledger.requested|received|stale`, `usage.ledger.failed {session_id, code}`, `usage.ledger.decode_failed` (не чаще раза на сессию и поле); сумм и payload в них нет.
* Панель Agents — не отдельный разбор, а обход транскрипта: `subagentRowsOf` с памятью `SubagentRowMemory` (`session/subagent_rows.dart`) строит `SubagentRowView` по дереву вызовов (`transcript/tool_call_tree.dart`) (D49 Т2).
