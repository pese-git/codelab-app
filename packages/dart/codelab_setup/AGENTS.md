## 1. Назначение

Мост между клиентами (`apps/codelab_cli`, позже `apps/codelab_desktop`) и настройкой Dart-агента. Клиентам нельзя импортировать `package:codelab_agent_*` (`AGENTS.md` §5), поэтому нужные типы и подкоманды приходят отсюда.

Состав (по итерациям change `add-provider-setup-ui`; итерация 2 — страница Providers, итерация 3 — мастер провайдера и готовность):
- `lib/codelab_setup.dart` — основной барель, чистый Dart и web-безопасный (`melos run web-compile` собирает его в JS и Wasm точкой входа `test/web_smoke/main.dart`):
  - `SecretValue` — значение секрета, `toString()`/JSON дают `***`, значение только через `reveal()` (SETUP-1);
  - `resolveSettingsAccess` и `SettingsAccess` (`EditableSettings`, `RemoteReadOnly`, `NotManaged`, `ConfigPaths`, `AgentLaunchKind`) — чьи настройки читать и писать (D5); цели записи — только `user` и `projectLocal`;
  - порт `AgentConfigStore`, `AgentConfigSnapshot` (слои, итог загрузки, источники ключей `ConfigSourceView`, бэкенд секретов) и исходы `ConfigSaveOutcome` (`ConfigSaved`, `ConfigConflict`, `ConfigRejected`, `ConfigInlineSecret`) (D6);
  - модели представления: `providerEntriesOf` строит `ProviderEntryView` со статусом ключа `KeyStatusView` по именам, без чтения значения (D10);
  - `ProviderCheck`, `HttpProviderCheck` (только `package:http/http.dart`, без редиректов, тело ошибки не читается; D8), `ProviderRemover` с `SecretDeleter` — одна запись конфига, секрет удаляется только после `ConfigSaved` (SETUP-24);
  - реэкспорт только типов, которые нужны потребителям: `ConfigLayer`, `ConfigTarget`, `ConfigSnapshot`, `ConfigEdit`, `SetValue`, `UnsetValue`, `RemoveTable`, `ConfigConflictException`, `ConfigIssue`, `ConfigIssueKind`, `ConfigLoadResult`, `SecretNames`, `SecretBackendInfo`, `CancelToken`, `CancelTokenSource` (владелец отмены проверки), `SettingsRegistry`, `SettingDescriptor`, `SettingScope`, `SettingType`, `ConfigValueException` (реестр настроек для `/settings`, D17) и строка о 1.0 `before1Note` для справки `codelab` (R8-7, D13 change `add-config-literal-secrets-and-migrate`); остальное (`UpsertMcpServer`, `RemoveMcpServer`) приходит с потребителем — MCP;
  - `SettingFieldView` и `settingFieldsOf(AgentConfigSnapshot)` (`lib/src/views/`) — строки `/settings`: ключи реестра `scope: shared`, `providers.*` раскрыты по id провайдеров снимка, значение и источник `default|user|project|local|config|env` (D17, Q15); значения карт не раскрываются, `toString()` без значений (SETUP-1); значения строк маскирует `displaySafeConfigValue` ядра (R0-2) — то же правило, что у `provider list`/`config get`, поэтому `SettingFieldView.value` уже замаскирован и для правки его подставлять нельзя: сырое значение берётся из снимка (`AgentConfigSnapshot.leaves`);
  - `SettingFieldView.masked` — `true`, если маскирование изменило значение или элемент списка (`value` не равно сырому); клиент по нему запрещает правку строкой `Use codelab secret set <name>` (сырое значение такого ключа в поле правки не открывается), сравнивать со строкой `<redacted>` не нужно (D17);
  - `displayBaseUrl(String? url)` — адрес без userinfo, query и fragment; единственная реализация для `ProviderDraft`, `ProviderEntryView`, мастера и CLI;
  - MCP-серверы (change `add-provider-setup-ui`, D11, итерация 5a; `lib/src/mcp/`, `lib/src/views/mcp_server_entry_view.dart`):
    - `McpServerDraft` (+ `McpValueDraft`: `McpTextValue`, `McpNewSecret`, `McpStoredSecret`) — форма сервера: `validate({existingNames})`, `toEdits()` (одна `UpsertMcpServer`, элемент целиком, неизвестные ключи сохраняются), `secretsToWrite()` (имя `SecretNames.forMcp` → значение); правка строится из СЫРОГО элемента слоя (`McpServerDraft.fromElement`), а не из вида; имя — `isValidMcpServerName` ядра (реэкспорт моста);
    - `McpServerEntryView`, `mcpServerEntriesOf(snapshot)`, `mcpServerElementOf(snapshot, name)` — строка страницы по элементу слоя-источника: `args` — `maskMcpArgs`, `headers` — только чистая ссылка `${…}`, иначе `<redacted>` и `masked`; `env`/`command`/`url` — `displaySafeConfigValue` (URL — `maskUrl`) ядра, то же правило, что у `provider list`/`config get`; `masked` — признак моста (клиент не сравнивает значения с литералом маски); «disabled here» (Q21) — `disabledHere`;
    - `McpServerCommitter` (`commit`, `setEnabled`, `disableHere`) и `McpServerRemover` (`remove`, `enableHere`) на порте `ProviderKeys` (второго порта секретов нет): порядок «секрет → конфиг → откат», из секретов, на которые ссылался удалённый сервер, удаляются только секреты пространства `codelab/mcp/<name>/`, только после `ConfigSaved` и только если по свежему снимку на них нет ссылок `${secret:…}` (SETUP-24, Q22); остальные имена остаются, исход `SecretCleanup.kept`; имена ссылок разбирает `secretReferencesIn`/`soleSecretReference` ядра; `disableHere(snapshot, name, access:)` отказывает без цели `projectLocal` у профиля (`noProjectTarget`, D5) и при нечитаемом `config.local.yaml` (`layerUnreadable`); переименование при правке запрещено (`validate()`), `secretsToWrite()` и проверка берут только таблицу активного типа; переключатель и правка пишут сырой элемент слоя целиком; `UpsertMcpServer`, `RemoveMcpServer` реэкспортируются мостом;
  - мастер провайдера (итерация 3; D2, D7, D9, D26): `ProviderSetupFlow` — автомат, который строит composition root с портами `ProviderCheck`, `ProviderKeys`, `ProviderSetupCommitter`, снимком, `EditableSettings`, окружением агента, `Logger` (из `io.dart` или ядра: основной барель его не реэкспортирует, иначе имя конфликтует с `codelab_client_acp`), обязательный `entry: ProviderWizardEntry` (wire-значения D18) и `isLocalHost` kit (параметром: правило «локальный хост» одно, в `codelab_client_core`, моста не касается; мост не импортирует `package:codelab_client_*`); состояния и события (`ChoosingPreset` … `Done`, `PresetChosen` … `Cancel`), `ProviderDraft`, `ProviderSetupPlan` (`toEdits()` — листовые `SetValue`/`UnsetValue`), `KeyChoice`, `ProviderPreset`/`ProviderPresets.all`; окно контекста автомат берёт из ответа `/models`, затем из `builtinModelInfo` ядра (`safeDefaultContextWindow` — 32000), клиентам они не реэкспортируются; `ProviderKeys` с исходами `ProviderKeyWrite` — всё, что мастеру нужно от хранилища секретов (`providerKeysOf` в `io.dart`); `ProviderSetupCommitter` с `ProviderCommitOutcome` — «секрет → конфиг», откат только созданного секрета, исключение `apply` приносит имя типа, а не текст; `providerEditRefusal(snapshot, id)` — единое правило «можно ли править/удалять провайдера» для `ProviderRemover` и режима правки мастера; `providerSetupNeeded(snapshot)` и `checkProviderReadiness(snapshot, keys, env)` с `ProviderReadiness` — признак «нет провайдера» по типизированным проблемам загрузчика, без разбора текста;
  - `supportsProviderCheck(kind)` и `defaultProviderBaseUrl(kind)` — какие виды проверяются и адрес по умолчанию (SETUP-8: знание вида не в app); `ProviderEntryView.displayBaseUrl` — адрес для показа без userinfo, query и fragment;
  - `AgentConfigSnapshot.issues` — проблемы чтения конфига (`Unreadable`), `startProblems` — проблемы запуска из-за отсутствующего ключа (`agent.default_model` вида `value` с событием `config.model.none` на новой установке); `providerSetupNeeded` — все проблемы `value` ключа `agent.default_model` и (событие `config.model.none` или нет провайдеров), `checkProviderReadiness` берёт модель из `CoreConfig.defaultModel` (change `optional-default-model`, D12): страница показывает пустое состояние; ключи недоверенного проекта (`config.project.untrusted_key`) не попадают ни в список, ни в источники.
- `lib/io.dart` — реэкспорт `ConfigCommands`, `CheckOptions`, `ConfigCommandResult` и кодов выхода `configValidExit`, `configInvalidExit`, `configUsageExit` из `codelab_agent_io`. Логика `config check` не дублируется (D13);
- `lib/io.dart` также реэкспортирует подкоманды записи и чтения конфига (change `add-config-writer-and-reload`, D6): `ConfigCommands` получает `path`, `get`, `set`, `unset` с опциями `ConfigPathOptions`, `ConfigGetOptions`, `ConfigSetOptions`, `ConfigUnsetOptions` и слоем чтения `ConfigGetLayer`; `ProviderCommands` (`add`, `list`, `remove`) с `ProviderAddOptions`, `ProviderListOptions`, `ProviderRemoveOptions`; `McpServerCommands` (`add`, `list`, `remove`) с `McpAddOptions`, `McpListOptions`, `McpRemoveOptions`. Результат — тот же `ConfigCommandResult`; логика, маскирование вывода и запись через `ConfigWriter` живут в `codelab_agent_io` и здесь не дублируются.
- `lib/io.dart` также реэкспортирует подкоманду `secret`: `SecretCommands`, `SecretCommandResult`, `SecretSetOptions`, `SecretDeleteOptions`, `SecretListOptions`, `SecretInput`, `StdinSecretInput`, `MultilineSecretException`, а для страницы настроек — `SecretAdmin` с результатами (`SecretWriteOutcome`, `SecretDeleteOutcome`, `SecretListOutcome` и их ветки) и фабрика `openSecretStore`; для её вызова и типизации из ядра реэкспортируются `DescribedSecretStore`, `SecretStoreUnavailableException`, `Logger`, `LogLevel`. Классы `EnvSecretStore`/`FileSecretStore` и `openHostSecrets` НЕ экспортируются (`add-agent-secret-store`, D8, D15). Логика секретов живёт в `codelab_agent_io`.
- `lib/io.dart` также содержит реализации портов основного бареля (change `add-provider-setup-ui`, D6, D8, D10): `FileAgentConfigStore` (поверх `ConfigWriter` и `ConfigLoader`; каждое исключение писателя — свой исход, `ConfigInlineSecretException` раньше `ConfigException`, конфликт не перезаписывает файл и не повторяется), `ioProviderCheck()` (`HttpProviderCheck` на `IOClient`, единственное место создания `IOClient`) и `secretDeleterOf(ClientSecretAccess)` для `ProviderRemover`.
- `lib/io.dart` также реэкспортирует клиентский доступ к секретам (change `add-provider-setup-ui`, D3, D4): `ClientSecretAccess` (`open`, `backend`, `admin`, `isSet`, `read` без кэша) и `secretReadOnlyHint(SecretReadOnly, home)` — одну подсказку про бэкенд только для чтения для `SecretCommands`, мастера и app; из ядра — `SecretBackendInfo`. Клиент читает секреты только так, прямой `openSecretStore` в клиентах не нужен. Логика — в `codelab_agent_io`.
- `lib/io.dart` также содержит `providerKeysOf(ClientSecretAccess, home:)` — реализацию порта `ProviderKeys` (D7): `stored` по `admin.list()` без `CODELAB_SECRET_*`, `read` через `access.read`, `write` через `admin.store` с переводом исходов (значение раскрывается только внутри), `readOnlyHint` — `secretReadOnlyHint` с учётом `configProblem`.
- `lib/io.dart` также реэкспортирует `secret migrate` (change `add-config-literal-secrets-and-migrate`, D7): `SecretMigrateOptions`, движок `SecretMigrator` с `SecretMigrationOptions`, отчёт `SecretMigrationReport`, `SecretMigrationAction` и пункты (`SecretPlanItem`, `SecretMovedItem`, `SecretReusedItem`, `SecretReplacedItem`, `SecretActionRequiredItem`, `SecretNotMigratedItem`, `SecretMigrationItem`); флаги `mcp add --header-stdin|--env-stdin|--header-scheme` — поля `McpAddOptions` (D11); там же — `before1Note` (тот же, что в основном бареле).

## 2. Границы

* `lib/` вне `lib/io.dart` и `lib/src/io/` НЕ ДОЛЖЕН импортировать `dart:io`, `dart:isolate`, `dart:ffi`, `dart:html`, `dart:js_interop`, `package:web/`, `package:flutter/`, `package:codelab_acp_transports/io.dart`, `package:codelab_agent_io/`, `package:codelab_acp_*`, `package:codelab_client_*` и ссылаться на `lib/io.dart` и `lib/src/io/`.
* `lib/io.dart` и `lib/src/io/` НЕ ДОЛЖНЫ импортировать `package:flutter/`, `package:codelab_acp_*` и `package:codelab_client_*`.
* `lib/` вне `lib/io.dart` и `lib/src/io/` НЕ ДОЛЖЕН импортировать `package:http/io_client.dart` и `package:http/browser_client.dart`: основной барель использует только `package:http/http.dart` и принимает клиент снаружи; `IOClient` создаёт `ioProviderCheck()` в `lib/src/io/`.
* Для `apps/codelab_desktop` (правило сторожа, SETUP-9): `lib/features/settings/presentation` НЕ ДОЛЖЕН импортировать `package:codelab_setup/io.dart` и `dart:io`, а остальной `lib/` app — `package:codelab_setup/io.dart` вне `lib/app/`; правила уже в `rules.dart`.
* `dependencies` — только `codelab_agent_core`, `codelab_agent_io`, `http`, `meta` (`setupAllowlist`; `http` — проверка `/models`, D8, D20). Расширение — только через OpenSpec change. Проверка — `melos run guard`.
* `lib/io.dart` импортирует только composition root клиента.

## 3. Что придёт позже (§12.4.2)

Приходит со своими потребителями, без абстракций «на вырост»:
- основной барель: реэкспорт `SecretStore` и `DescribedSecretStore`, если их потребуют мастер и готовность;
- `io.dart`: пути `$CODELAB_HOME` вне уже реэкспортированных подкоманд (по потребности мастера CLI);
