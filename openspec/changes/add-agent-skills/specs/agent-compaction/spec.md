## ADDED Requirements

### Requirement: Навыки после сжатия
Сжатие SHALL сохранять в контексте модели инструкции активных навыков (design.md change `add-agent-skills`, D15; решение пользователя Q6; руководство Agent Skills, «Protect skill content from context compaction»):
1. Запись `compaction` SHALL получать необязательное поле `skills` — список `{name, fingerprint}`, вычисленный по снимку **до** новой записи: элементы `activeSkills` (capability `agent-skills`, «Активные навыки») в их порядке (от новой активации к старой), кроме навыков, чья последняя активация лежит после нового `firstKeptId` (их тело и так остаётся в контексте). Поэтому навык, приложенный прошлым сжатием целиком или усечённым, SHALL переноситься в новый список и прикладываться снова; навык, выпавший по общему бюджету прошлого приложения или отсутствующий в каталоге, в `activeSkills` не входит и SHALL NOT переноситься — вернуть его может только новая активация. `fingerprint` — SHA-256 обрезанного при разборе тела навыка (capability `agent-skills`, «Обрезка тела»; не усечение бюджетом) из снимка каталога сессии в шестнадцатеричной записи (нижний регистр), и для активации командой. Ни тела, ни аргументов команды в записи НЕ SHALL быть. Поле пишется и при `0` в бюджетах (п. 3): запись фиксирует активные навыки, а бюджеты действуют при приложении (design.md change `add-agent-skills`, D20); пустой список — поля нет.
2. `buildLlmContext` SHALL после сообщения-резюме последней записи `compaction` добавлять одно сообщение пользователя (один текстовый блок) по `prompts/skills/reattached.md` с блоком каждого приложенного навыка из `skills` (capability `agent-skills`, «Блок навыка») в порядке записи, блоки — через пустую строку (`\n\n`); если приложить нечего, сообщения нет. Каталог и бюджеты проекция получает от сессии; без каталога сообщения нет. Сообщение — производное: в журнал НЕ SHALL писаться. Тело берётся из снимка каталога по имени без подстановки аргументов. Результат приложения (целиком, усечённым или выпал) — функция только этой записи, каталога и бюджетов; её же использует `activeSkills`.
3. Бюджеты (оценка §9.3, `ceil(символов / 4)`): тело длиннее `skills.reattach.per_skill_tokens` SHALL усекаться до наибольшего префикса целых строк в пределах бюджета; следующей строкой тела, внутри блока перед `</skill>`, идёт пометка `[skill truncated: load it again with the skill tool for the full text]`, если навык входит в `modelVisible`; иначе, если навык вызываемый (`user-invocable`), — `[skill truncated: the user can run /skill:<name> for the full text]`; иначе — `[skill truncated]`; общий бюджет `skills.reattach.total_tokens` считается по блокам целиком (тело или усечённое тело с пометкой, строка о путях, список файлов) в порядке записи: первый непомещающийся блок и все после него SHALL выпадать (самые давние активации). `0` в любом ключе — сообщения нет.
4. Навыка нет в снимке (удалён, отключён, сессия загружена без навыков) — он выпадает без лога и в `dropped` не входит. Отпечаток не совпал (файл изменён между сохранением и загрузкой сессии) — прикладывается текущее тело, лог `skills.reattach.changed {session_id, name}` (warning).
5. `tokensAfter` записи и проверка CMP-5 SHALL учитывать приложенное сообщение. Одинаковые снимок и каталог SHALL давать побайтово одинаковое сообщение.
6. Лог `skills.reattached {session_id, names, dropped, truncated}` (info) пишет сжатие, если поле `skills` новой записи не пусто и оба бюджета больше `0`: `names` — приложенные навыки в порядке сообщения (с усечёнными), `dropped` — число выпавших по общему бюджету, `truncated` — число усечённых; тела в логе нет. `skills.reattach.changed` пишет проекция, получившая логгер, — по одному на навык за вызов.

7. Бюджеты `skills.reattach.*`, которыми пользуются проекция, сжатие и `activeSkills` сессии, SHALL браться из конфигурации на момент открытия сессии (`session/new`, `session/load`) и НЕ SHALL меняться до её закрытия, в том числе при перезагрузке конфигурации (capability `agent-skills`, «Конфигурация навыков»; design.md change `add-agent-skills`, D20, «M1»).
8. Повторное имя в `skills` записи SHALL пропускаться: действует первое вхождение. Элемент без строковых `name` и `fingerprint` SHALL пропускаться при приложении. Неизвестные ключи элемента SHALL сохраняться при чтении и записи без потери (§8.2.2).

9. Окно модели (решение Q49 (б); design.md change `add-agent-skills`, D20, «M2»): если после прохода сжатия оценка проекции с сообщением навыков больше порога CMP-5, а без сообщения не больше, новый проход НЕ SHALL запускаться. Вместо этого из нового списка `skills` SHALL выбрасываться элементы с конца (самые давние активации), пока оценка не уложится в порог или список не опустеет; в запись идут только уместившиеся, `tokensAfter` — оценка с ними, выброшенные не переносятся. Если оценка без сообщения навыков тоже выше порога, действует обычный CMP-5. Лог `skills.reattached` SHALL содержать `dropped_window` — число выброшенных по окну.

Запись без поля `skills` SHALL читаться как раньше; ядро, не знающее поля, сохраняет его без потери (совместимость вперёд §8.2.2). Суммаризатору тела навыков отдельно НЕ SHALL передаваться: регион сериализуется как прежде.

#### Scenario: Навык переживает сжатие
- **WHEN** модель загрузила навык `release-notes` инструментом `skill`, затем ручное сжатие убрало этот вызов в резюме
- **THEN** запись `compaction` содержит `skills: [{"name":"release-notes","fingerprint":…}]`, следующий запрос к модели содержит после резюме сообщение с блоком `<skill name="release-notes" …>`; журнал не содержит тела навыка (`core/skill-reattached-after-compaction`)

#### Scenario: Общий бюджет
- **WHEN** активны три навыка по 10 000 токенов, `per_skill_tokens: 16384`, `total_tokens: 25000`
- **THEN** приложены два последних по активации, самый давний выпал; лог `skills.reattached` с `dropped: 1`; выпавший навык не активен

#### Scenario: Навык в хвосте не дублируется
- **WHEN** навык активирован в последнем ходе, который остаётся в хвосте после сжатия
- **THEN** поле `skills` записи его не содержит, блока навыка после резюме нет

#### Scenario: Усечённый навык при следующем сжатии
- **WHEN** навык приложен прошлым сжатием усечённым и больше не активировался, затем происходит новое сжатие
- **THEN** новая запись `compaction` снова содержит этот навык, после резюме он снова приложен усечённым; повторный вызов `skill` вернул бы полный блок

#### Scenario: Выпавший навык не возвращается сам
- **WHEN** прошлое сжатие выронило навык по общему бюджету, затем происходит новое сжатие без его активации
- **THEN** новая запись `compaction` его не содержит

#### Scenario: Пометка усечения
- **WHEN** тело навыка из модельного каталога больше `per_skill_tokens: 100`
- **THEN** после резюме блок навыка содержит целые первые строки тела не длиннее 400 символов, затем строку `[skill truncated: load it again with the skill tool for the full text]` перед `</skill>`; у навыка только для пользователя пометка — `[skill truncated: the user can run /skill:<name> for the full text]`, у навыка без обоих способов вызова — `[skill truncated]`

#### Scenario: Бюджет ноль
- **WHEN** `skills.reattach.total_tokens: 0`, и сжатие убирает активацию навыка в резюме
- **THEN** запись `compaction` содержит поле `skills` с этим навыком, сообщения после резюме нет, лога `skills.reattached` нет; навык не активен

#### Scenario: Файл навыка изменён
- **WHEN** запись `compaction` несёт отпечаток прежнего тела, а сессия загружена после правки `SKILL.md`
- **THEN** приложено текущее тело, лог `skills.reattach.changed` (warning) с именем, без тела и отпечатка

#### Scenario: Перезагрузка не меняет бюджеты живой сессии
- **WHEN** сжатие с `per_skill_tokens: 100` приложило навык усечённым, затем пользователь поднял `per_skill_tokens` до 16384 и перезагрузил конфигурацию, и модель вызывает `skill` с этим навыком
- **THEN** результат — полный блок, а не строка повтора: в живой сессии навык по-прежнему усечён и не активен; новая сессия и `session/load` используют новый бюджет

#### Scenario: Подложенная запись
- **WHEN** поле `skills` записи содержит одно имя дважды и элемент с неизвестным ключом `x`
- **THEN** навык приложен один раз, элемент с `x` читается, а при повторной записи `x` сохранён

#### Scenario: Малое окно: давние навыки выброшены, нового прохода нет
- **WHEN** окно модели 8192 токена (порог 6144), после сжатия хвост и резюме занимают около 4000 токенов, а активны два навыка по 2000 токенов, загруженные в разное время
- **THEN** второго прохода сжатия нет (суммаризатор вызван один раз); запись `compaction` содержит в `skills` только более свежий навык, `tokensAfter` не выше порога; лог `skills.reattached` с `dropped_window: 1`; более давний навык не активен

#### Scenario: Сжатие без навыков
- **WHEN** в сессии не было активаций
- **THEN** поле `skills` отсутствует, контекст побайтово такой же, как до этого change
