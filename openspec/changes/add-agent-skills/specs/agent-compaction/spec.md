## ADDED Requirements

### Requirement: Навыки после сжатия
Сжатие SHALL сохранять в контексте модели инструкции активных навыков (design.md change `add-agent-skills`, D15; решение пользователя Q6; руководство Agent Skills, «Protect skill content from context compaction»):
1. Запись `compaction` SHALL получать необязательное поле `skills` — список `{name, fingerprint}`, вычисленный по снимку **до** новой записи: элементы `activeSkills` (capability `agent-skills`, «Активные навыки») в их порядке (от новой активации к старой), кроме навыков, чья последняя активация лежит после нового `firstKeptId` (их тело и так остаётся в контексте). Поэтому навык, приложенный прошлым сжатием целиком или усечённым, SHALL переноситься в новый список и прикладываться снова; навык, выпавший по общему бюджету прошлого приложения или отсутствующий в каталоге, в `activeSkills` не входит и SHALL NOT переноситься — вернуть его может только новая активация. `fingerprint` — SHA-256 обрезанного тела навыка (capability `agent-skills`, «Обрезка тела») из снимка каталога сессии в шестнадцатеричной записи. Ни тела, ни аргументов команды в записи НЕ SHALL быть.
2. `buildLlmContext` SHALL после сообщения-резюме последней записи `compaction` добавлять одно сообщение пользователя по `prompts/skills/reattached.md` с блоком каждого навыка из `skills` (capability `agent-skills`, «Блок навыка») в порядке записи. Сообщение — производное: в журнал НЕ SHALL писаться. Тело берётся из снимка каталога по имени без подстановки аргументов. Результат приложения (целиком, усечённым или выпал) — функция только этой записи, каталога и бюджетов; её же использует `activeSkills`.
3. Бюджеты (оценка §9.3): тело длиннее `skills.reattach.per_skill_tokens` SHALL усекаться по последней границе строки с пометкой `[skill truncated: load it again with the skill tool for the full text]`, если навык входит в `modelVisible`; иначе, если навык вызываемый (`user-invocable`), — `[skill truncated: the user can run /skill:<name> for the full text]`; иначе — `[skill truncated]`; навыки сверх `skills.reattach.total_tokens` SHALL выпадать начиная с последнего в списке (самая давняя активация). `0` в любом ключе — сообщения нет.
4. Навыка нет в снимке (удалён, отключён, сессия загружена без навыков) — он выпадает. Отпечаток не совпал (файл изменён между сохранением и загрузкой сессии) — прикладывается текущее тело, лог `skills.reattach.changed {session_id, name}` (warning).
5. `tokensAfter` записи и проверка CMP-5 SHALL учитывать приложенное сообщение. Одинаковые снимок и каталог SHALL давать побайтово одинаковое сообщение.
6. Лог `skills.reattached {session_id, names, dropped, truncated}` (info) — при каждом сжатии с непустым списком; тела в логе нет.

Запись без поля `skills` SHALL читаться как раньше; ядро, не знающее поля, сохраняет его без потери (совместимость вперёд §8.2.2). Суммаризатору тела навыков отдельно НЕ SHALL передаваться: регион сериализуется как прежде.

#### Scenario: Навык переживает сжатие
- **WHEN** модель загрузила навык `release-notes` инструментом `skill`, затем ручное сжатие убрало этот вызов в резюме
- **THEN** запись `compaction` содержит `skills: [{"name":"release-notes","fingerprint":…}]`, следующий запрос к модели содержит после резюме сообщение с блоком `<skill name="release-notes" …>`; журнал не содержит тела навыка (`core/skill-reattached-after-compaction`)

#### Scenario: Общий бюджет
- **WHEN** активны три навыка по 10 000 токенов, `per_skill_tokens: 16384`, `total_tokens: 25000`
- **THEN** приложены два последних по активации, самый давний выпал; лог `skills.reattached` с `dropped: 1`; выпавший навык не активен

#### Scenario: Навык в хвосте не дублируется
- **WHEN** навык активирован в последнем ходе, который остаётся в хвосте после сжатия
- **THEN** поле `skills` записи его не содержит, блока навыка после резюме нет

#### Scenario: Усечённый навык при следующем сжатии
- **WHEN** навык приложен прошлым сжатием усечённым и больше не активировался, затем происходит новое сжатие
- **THEN** новая запись `compaction` снова содержит этот навык, после резюме он снова приложен усечённым; повторный вызов `skill` вернул бы полный блок

#### Scenario: Выпавший навык не возвращается сам
- **WHEN** прошлое сжатие выронило навык по общему бюджету, затем происходит новое сжатие без его активации
- **THEN** новая запись `compaction` его не содержит

#### Scenario: Сжатие без навыков
- **WHEN** в сессии не было активаций
- **THEN** поле `skills` отсутствует, контекст побайтово такой же, как до этого change
