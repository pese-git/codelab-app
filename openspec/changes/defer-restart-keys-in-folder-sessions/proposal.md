## Why

В desktop после «Open folder…» встроенный агент не перезапускается (design.md change `require-project-folder`, D11, D15): корень процесса остаётся первым проектом, а сессии новой папки получают конфигурацию своей папки через `ProjectConfigLoader.loadForProject` (D21). Ручной smoke 2026-11-16 показал два расхождения.

1. **Лог читается неверно.** `config.session.project {session_id, cwd, config_root, trusted}` пишет в `config_root` корень процесса (`start.config.projectRoot`). Конфигурацию сессия при этом берёт из своей папки. В логе это выглядит как «сессия взяла конфиг прошлого проекта», хотя это не так.
2. **R0-4 обходится для сессий других папок.** Правка глобального `$CODELAB_HOME/config.yaml` (смена `providers.openrouter.api_key_env`) даёт `config.reload.restart_required: [providers.openrouter]`. Это правило R0-4: правку, способную направить секрет на другой адрес, применяет только перезапуск (archive `2026-11-03-add-config-writer-and-reload`, D8, таблица R0). Сессии корня так и работают: до перезапуска они ходят со старой группой. Но сессия **другой** папки на каждом `session/new` и `session/load` читает файлы заново, без `withDeferred`, и сразу получает новые `api_key_env` и `base_url`. Тот же обход есть у R0-1: глобальные `permissions.*` и новые stdio-серверы попадают в новую сессию другой папки без перезапуска. D21 об этом прямо ничего не говорит. Строка `Restart required` и подсказки desktop («The new key is used after Restart agent») поэтому верны только для сессий корня.

Решение пользователя 2026-11-16 — «A вместе с B»: (A) сделать лог и тексты однозначными и (B) распространить отложенные до перезапуска правки на сессии других папок. Провайдер, которого задаёт доверенная папка, при этом должен по-прежнему работать сразу (D21, Q11).

## What Changes

- **Отложенные правки в сессиях других папок** (`agent-runtime`, MODIFIED «Сессии других папок при перезагрузке корня»). При открытии сессии другой папки рантайм сравнивает снимок без проекта загрузки папки с применённым снимком процесса тем же планом `planConfigReload`. Части, которые план откладывает (группа провайдера с ключом и новый провайдер с ключом, R0-4; HTTP-серверы с подстановкой, R0-4; stdio-серверы, R0-1; ссылки на модели нового отложенного провайдера), берутся из применённого снимка через `CoreConfig.withDeferred`. Исключение — часть, которую перекрыл проектный слой папки. Перекрытие определяется по паре снимков самой загрузки (полный и без проекта), без второго чтения файлов. Совпадение значений считается неперекрытием: часть берётся из применённого снимка (fail closed). То же правило действует для провайдера, ключ которого даёт только проектный слой папки (`config.local.yaml`): секрет проекта не уходит на глобальный адрес, изменённый после старта (design.md, D3). Хост без `ConfigSource` подстановки не делает: перезагрузки у него нет и ничего не отложено.
- **Глобальные права после старта** (R0-1, если пользователь подтвердит Q1). Если у папки нет проектных слоёв, сессия получает раздел `permissions` применённого снимка. Если проектные слои есть, сессия не открывается до перезапуска: `ProjectConfigException` с понятным текстом.
- **Лог** (`agent-runtime`, MODIFIED «Конфигурация сессии вне корня запуска»). В `config.session.project` поле `config_root` переименовано в `process_root`. Новое событие `config.session.restart_pending {session_id, cwd, keys}` (`warning`) называет ключи, которые сессия получила из применённого снимка, без значений.
- **Ключи процесса из папки сессии.** `config.session.process_keys_ignored` теперь называет только ключи, которые задают проектные слои папки (полный снимок папки против снимка без проекта). Правка глобального файла после старта больше не даёт ложного предупреждения (если пользователь подтвердит Q2).
- **Состояние перезапуска.** `restartRequiredKeys`, `pendingRestartKeys` и строка `Restart required` описывают применённый снимок процесса. После этого change они верны для сессий всех папок. Открытие сессии их не меняет (если пользователь подтвердит Q3).
- **Документы.** Документы ядра (`10-core-assembly-and-profiles.md`, `17-5-agent-setup.md`, `12-observability-and-errors.md`) и пользовательские (`docs/user/configuration.md`, `apps/codelab_desktop/doc/user-guide.md`): выбор проекта агента не перезапускает, а правки с пометкой «после перезапуска» действуют для всех папок только после «Restart agent».

## Не входит

- Перезапуск встроенного агента при смене проекта (вариант C разбора; меняет D15 change `require-project-folder`).
- Живая перезагрузка проектных слоёв других папок у открытых сессий и наблюдатель за ними (Q12 change `require-project-folder`, отложено до 1.0).
- «Строжайшее из двух» для раздела `permissions` при проектных слоях папки (design.md, D4, альтернатива): отдельный change, если отказ окажется неудобен.
- Привязка ссылок проектного провайдера по условию (b) D23 к применённому, а не текущему глобальному слою (design.md, Q4): для этого загрузчик должен отдавать происхождение привязки, это отдельный change.
- Поле `session_id` в `config.session.project_invalid` (изменение контракта лога; design.md, Risks).
- Новые методы, поля и состояния ACP. Отказ идёт существующим `-32603` с `data.codelab.reason: "projectConfigInvalid"`.
- Изменения UI desktop и CLI: тексты подсказок после этого change становятся верными без правок кода.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `agent-runtime`: «Конфигурация сессии вне корня запуска» (порядок шагов, ключи процесса, лог `process_root`); «Сессии других папок при перезагрузке корня» (отложенные правки, отказ по правам, лог `restart_pending`, смысл состояния перезапуска).

## Impact

- `codelab_agent_core`: новая внутренняя чистая функция подстановки отложенного для сессии папки (`lib/src/config/`), вызов из `AgentRuntime._projectScope`, переименование поля лога, новое событие, правило `process_keys_ignored`. Публичный API, барель и allowlist зависимостей ядра (PKG-2) не меняются; `CoreConfig.withoutNestedProject` — `@internal`. Публичный `CoreConfig.withDeferred` уточняется только для случая, который раньше давал отказ `validateSnapshot`: модель базы вне каталога прежних провайдеров считается неявной (design.md, D5).
- `apps/codelab_agent`, `codelab_embedded`: только тесты с настоящим `FileConfigSource`; код не меняется.
- ACP, клиентский слой, desktop и CLI: код не меняется. Меняются только документы.
- Конфликт с активным change `add-agent-skills`: он тоже правит требование «Конфигурация сессии вне корня запуска» (пункт `skills.*` и сценарии навыков). Тот change, который архивируется вторым, переносит в свой текст правки первого (design.md, «Связь с активными changes»).
