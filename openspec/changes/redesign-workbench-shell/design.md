## Context

**Каркас сейчас.** `CodeLabShell` собирает `CodeLabWorkbenchLayout` из четырёх слотов:

| Слот | Содержимое |
|---|---|
| `commandBar` | `WorkbenchCommandBar`: «CodeLab», статус, профиль, путь к бинарю, шестерёнка, Connect |
| `sessionsPane` | `CodeLabProjectPicker` и `CodeLabSessionSidebar` |
| `mainPane` | `WorkbenchMainPane`: панель текущей сессии, лента, activity bar, композер |
| `inspectorPane` | `InspectorPane` и `DebugLogPane` колонкой |

Раскладку выбирает приватный `_AcpWorkbenchLayoutMode` по ширине области: ≥ 1100 — три колонки, ≥ 720 — средняя, ниже — узкая. Ширину сайдбара и инспектора хранит `LayoutCubit` и только в памяти.

**Каркас макета.** Описан в `dart-agent-and-clients` §12.3 A13, шаг 0; классы по ширине — в §12.8.3. На артбордах Main и Turn:

- **App bar.** Слева «CodeLab», в центре поле «Search or run a command Ctrl+K», справа переключатели панелей и бейдж соединения.
- **Сайдбар.** New session, поиск, Pinned, «Projects» с группами по проектам, Settings внизу.
- **Панель сессии.** Своя шапка: название, проект, режим, Rename/Fork/Split. Под ней лента и композер.
- **Док справа.** Вкладки панелей Files, Plan, Agents и других, вертикальное разбиение.

**Ограничения.**

- `codelab_ui` не содержит логики и не знает `codelab_client_core`: модели — свои, данные готовит app.
- Новых зависимостей нет (§4): навигация и раскладка — на `fluent_ui` и существующих Cubit-ах.
- Пустые абстракции запрещены (§13).

## Goals / Non-Goals

**Goals:**

- Каркас окна совпадает с A13, шаг 0 по зонам и их поведению по ширине (§12.8.3).
- Док панелей инструментов готов принять Files и Terminal из уже написанных change без новой раскладки.
- Сайдбар показывает сессии по проектам и переключает проект без выпадающего списка.
- Состояние сайдбара и дока переживает перезапуск.

**Non-Goals** (каждый пункт — отдельный change или уже есть в плане):

- Markdown в ленте — `add-transcript-markdown`.
- Блок мыслей модели — `add-agent-thought-block`.
- Страница выбора проекта (артборд Projects) и `NavigationCubit` с `AppDestination` — отдельный change вместе с первой второй страницей; см. D1.
- Pinned — нет хранения закреплённых сессий в kit.
- Полнотекстовый поиск по сессиям (A12) — здесь только фильтр по названию.
- Сессии всех проектов сразу (S-18): kit держит один проект на рабочее пространство. Здесь показываются группы недавних проектов, а их сессии — после выбора.
- Rename, Fork, Split view (29) и статус-строка под композером: нет поддержки в kit или данных usage.
- Тёмная тема; экраны телефона — этап 10.

## Decisions

### D1. `NavigationCubit` откладывается; раскладкой владеет `LayoutCubit`

A13 вводит `NavigationCubit` над `AppDestination` (Boot, Onboarding, ProjectPicker, Workbench, Settings). Сейчас есть только один экран — рабочее место. Cubit с одним вариантом — пустая абстракция (§13).

Состояние каркаса добавляется в существующий `LayoutCubit`:

- `sidebarCollapsed`;
- `openPanes` — упорядоченный список `ToolPane`;
- `activePane`;
- `dockWidth`;
- `dockOpenInOverlay` — выдвинут ли док в узких классах.

`NavigationCubit` появится вместе со второй страницей (Projects или Settings), и `WorkbenchDestination` возьмёт эти поля.

Альтернатива — ввести `NavigationCubit` сразу. Отклонено: он дублировал бы `LayoutCubit` и ничего не переключал бы.

### D2. Класс раскладки — публичный enum в `codelab_ui`, только по ширине окна

`CodeLabLayoutClass { phone, narrow, medium, wide }` с функцией `CodeLabLayoutClass.of(double windowWidth)`:

| Класс | Ширина окна |
|---|---|
| `phone` | < 641 |
| `narrow` | 641–899 |
| `medium` | 900–1279 |
| `wide` | ≥ 1280 |

Класс считается от ширины всего окна (`MediaQuery.sizeOf`), а не области `LayoutBuilder`, как в §12.8.3. Тогда отступы и сайдбар не сдвигают порог.

Класс `phone` в этом change раскладывается как `narrow`, отдельные экраны — этап 10. Enum его уже содержит, чтобы этапу 10 не менять сигнатуры.

| Класс | Сайдбар | Док |
|---|---|---|
| `wide` | открыт | колонка справа с границей |
| `medium` | открыт или свёрнут в иконки (Cmd/Ctrl+B) | выдвигается поверх ленты |
| `narrow`, `phone` | скрыт, открывается кнопкой меню поверх контента | выдвигается поверх ленты |

**MOB-3.** Лента, композер и док остаются в одном месте дерева при любом классе, меняются только обёртки. Для этого у них стабильные `GlobalKey`. Тест проверяет, что смена класса не сбрасывает текст композера и прокрутку.

### D3. Сайдбар — собственный организм в визуальном языке `NavigationView`, не сам `NavigationView`

`NavigationView` из `fluent_ui` владеет телом страницы: у каждого `PaneItem` свой `body`, а отображение выбирается своими порогами (640 / 1008). У нас тело — одна панель сессии, а пункты сайдбара — динамический список сессий и проектов.

Если подчинить каркас `NavigationView`, придётся:

- держать фиктивные `body`;
- синхронизировать `selected` с `SessionsCubit`;
- обходить его пороги, которые не совпадают с §12.8.3.

Поэтому `CodeLabSessionSidebar` переписывается собственным организмом из примитивов `fluent_ui`: `PaneItem`-подобных строк, `Expander`-групп и `InfoBadge`, с теми же метриками и состояниями, что у `NavigationPane` (`open` / `compact`). A13 называет `NavigationView` как источник вида; от виджета отказываемся из-за владения телом и чужих порогов, вид сохраняется.

Альтернатива — `NavigationView` с `PaneDisplayMode`, выставленным вручную по нашему классу. Отклонено по причинам выше.

**Итог спайка 1.1 (`fluent_ui` 4.16.1).**

- `NavigationView` получил `paneBodyBuilder`: тело можно подменить. Но выбор по-прежнему задаётся индексом пункта в `NavigationPane.items`, поэтому синхронизация с `SessionsCubit` остаётся.
- `PaneDisplayMode.auto` переключается при ≤ 640 и ≥ 1008 px, это не пороги §12.8.3.
- Метрики для своего сайдбара:
  - ширина `open` — 320 (`kOpenNavigationPaneWidth`), `compact` — 50 (`kCompactNavigationPaneWidth`);
  - `iconPadding` — 12 по горизонтали, `labelPadding` — 10 справа, `headerPadding` — 8 по вертикали (`NavigationPaneThemeData.standard`).

Решение D3 остаётся в силе.

### D4. Группы по проектам из уже имеющихся данных

- **Группа текущего проекта.** Раскрыта, в ней сессии из `SessionsState.sessions` с их статусами и «Load more sessions».
- **Остальные недавние проекты.** Это `RecentProjectsStore`. Показываются свёрнутыми группами с именем папки; полный путь — в подсказке. Раскрытие группы выбирает проект: тот же `selectProject`, что был у `CodeLabProjectPicker`. Её сессии появятся из `session/list` после выбора.
- **«Open folder…»** — нативный диалог, как раньше.
- **Фильтр по названию** — локальный, по уже загруженным строкам.

Группа называется по имени папки, а не полному пути. Это отвечает и на старое замечание, что в сайдбаре виден домашний путь.

### D5. `CodeLabToolDock`: вкладки панелей, ширина, поведение по классу

`ToolPane` в `codelab_ui` — enum с полным списком A13: files, diff, terminal, plan, timeline, agents, usage, branches, protocol. Док показывает только переданные ему панели. В этом change app передаёт две:

- **Plan** — полный `CodeLabProgressChecklist` текущего плана. Компактная сводка над композером остаётся.
- **Protocol** — бывший Inspector (записи протокола, одобрения, вызовы) и Debug log с поиском, фильтром уровня и Expand. Это два раздела одной панели.

Остальные значения enum ждут своих change, без заглушек в UI.

**Переключатели в app bar** — `ToggleButton` на каждую доступную панель:

- нажатие открывает панель, а если она уже активна — закрывает;
- вкладка закрывается крестиком;
- без открытых панелей дока нет, лента занимает ширину.

**По классу раскладки.** В `wide` док — колонка справа с `CodeLabResizeHandle` от 280 до 560 px. В остальных классах — выдвижная панель поверх ленты справа, закрывается Esc и кликом мимо.

**Сохранение.** Открытые панели, активная панель и ширина хранятся в `shared_preferences` под ключами `codelab.dock.*`, по образцу `SharedPreferencesRecentProjectsStore`. Вертикальное разбиение дока (A13: `lower`) — не в этом change: двух панелей мало, чтобы его оправдать.

Альтернатива — оставить Inspector и Debug log колонкой и добавить вкладки сверху. Отклонено: A13, шаг 6 прямо заменяет инспектор доком, и Files/Terminal уже на это рассчитывают.

### D6. App bar и бейдж соединения

`CodeLabAppBar` — организм с тремя слотами: заголовок, поиск, действия. Поиск — не настоящее поле ввода, а кнопка в виде поля «Search or run a command» с подсказкой Ctrl+K (⌘K на macOS): нажатие открывает существующую палитру. Двух полей поиска нет.

Бейдж соединения повторяет артборд States:

| Состояние | Бейдж |
|---|---|
| `connected` | «Connected» |
| `connecting`, `reconnecting` | «Connecting…» / «Reconnecting…» с индикатором |
| `lost`, `failed` | «Connection lost» / «Connection failed» и кнопка Retry, вызывающая Reconnect |
| `disconnected` | «Disconnected» и Connect |

Профиль и транспорт уходят в подсказку бейджа. Путь к бинарю из шапки убирается, он остаётся в диалоге подключения. Шестерёнка уходит в «Settings» внизу сайдбара: открывает тот же диалог подключения, что и раньше. Баннер над лентой из `add-connection-and-error-states` не меняется.

### D7. Шапка панели сессии

`CodeLabSessionPaneHeader` заменяет `CurrentSessionPanel`:

- название сессии;
- чип проекта — имя папки, полный `cwd` в подсказке;
- чип режима из config options, если агент его публикует;
- справа слот действий — в этом change пустой.

Режим берётся из опции категории `mode` (`SessionConfigOption.category` в ACP). Для этого `ConfigOptionView` в `codelab_client_core` получает поле `category`, которого раньше не было; угадывать опцию по `id` нельзя — `id` выбирает агент.

Rename, Fork, Split не рисуются недоступными кнопками: в палитре уже есть пометки «Coming soon», дублировать их в шапке незачем.

## Risks / Trade-offs

- **[Риск] Переписанный сайдбар расходится с нативным видом `NavigationView` по мелочам.**
  → Метрики (высота строки 36, отступы, иконки) берутся из `fluent_ui` `NavigationPaneTheme`. Превью сравнивается с артбордом Main.
- **[Риск] Удаление постоянной колонки Debug log ломает привычный путь к логам и e2e-тесты, которые ищут карточку.**
  → `/logs` в палитре открывает панель Protocol; ключи тестов обновляются вместе с тестами; полноэкранный log viewer остаётся.
- **[Риск] Смена класса при перетаскивании окна дёргает раскладку.**
  → Класс считается только от ширины окна, пороги жёсткие, гистерезиса нет: так задано в §12.8.3. Тест MOB-3 следит, что текст и прокрутка не теряются.
- **[Компромисс] Сессии других проектов не видны, пока проект не выбран.**
  → Это ограничение kit, не UI. S-18 — отдельная работа в `codelab_client_core`.
- **[Риск] Существующие widget- и e2e-тесты завязаны на ключи `acp-workbench-inspector-pane` и `WorkbenchCommandBar`.**
  → Задачи группы 5 переводят их на новые ключи A13, шаг 8: `tool-pane-<pane>`, `tool-toggle-<pane>`, `sidebar-project-<project>`.

## Migration Plan

- Ключи `shared_preferences` новые; старых значений ширины инспектора не было: ширины хранились только в памяти.
- Откат — revert ветки, данные пользователя не затрагиваются.

## Open Questions

- Нужен ли в `medium` режим сайдбара «только иконки» (`compact`) по Cmd/Ctrl+B или достаточно скрыть сайдбар целиком? Предлагается `compact`, как в A13. Если спайк 1.1 покажет, что без `NavigationView` он стоит заметно дороже, — скрывать целиком и записать решение в D3.
