## Decisions

### D1. Где публикуется политика заморозки

Политика — раздел «Поддержка Python-агента» в `docs/user/migrating-from-python-agent.md`, рядом с остальным, что нужно пользователю Python-агента. Внешний шаг E.1 — короткий баннер со ссылкой на этот раздел в README Python-репозитория. Раздел содержит:
1. с какого момента действует заморозка (D3);
2. что принимается (D2) и как сообщить об уязвимости — через приватный канал Python-репозитория (GitHub Security Advisories), не публичным issue;
3. что не принимается: новые функции, обычные дефекты, совместимость с новыми версиями ACP и CodeLab;
4. условие удаления и кто решает (D4);
5. что будет с алиасом `codelab serve` (D11).

Правила для сопровождающих (метка трекера, запись решения) — в D4 и в плане 9.9. Отдельного документа в `docs/architecture/` нет: политика относится к одному внешнему продукту, и её единственный читатель-сопровождающий уже читает план этапа 9.

*Альтернативы:*
- отдельный `docs/user/python-agent-support.md` — ещё одна страница с теми же ссылками; раздел в документе перехода находится там, где пользователь уже ищет;
- только README Python-репозитория — тогда ворота MVP ссылались бы на документ вне репозитория, который этот репозиторий не контролирует.

### D2. Что считается исправлением безопасности

Принимаются исправления, без которых установленный Python-агент:
- выполняет действие вне рабочей папки или без одобрения, которое требовалось бы по его политике;
- раскрывает секрет (ключ API, токен) в лог, вывод или сеть;
- запускает код с машины пользователя по данным из сети или от модели в обход одобрения;
- зависит от библиотеки с опубликованной уязвимостью, достижимой из кода агента.

Исправление выходит patch-версией — тегом в Python-репозитории с записью в его журнале изменений (на PyPI агент не публикуется, Q8). Всё остальное — «не исправляется, переходите на Dart-агента» со ссылкой на `docs/user/`. Сопровождающий Python-репозитория МОЖЕТ отказать в исправлении, если уязвимость требует переписать подсистему. Тогда он публикует рекомендацию отключить затронутую функцию или перейти на Dart-агента.

*Альтернатива:* «критические и высокие по CVSS». Оценка CVSS для локального агента субъективна и требует отдельного процесса; перечень по последствиям проверяется на конкретном отчёте.

### D3. С какого момента действует заморозка

С публикации политики, то есть с merge итерации 0 в `develop`, а не с подписи ворот MVP. Профиль по умолчанию в app и CLI уже встроенный Dart-агент (change `add-app-settings-shell`, D5, D21), поэтому развитие Python-агента уже не нужно продукту. Ворота MVP (задача 4.6 `switch-default-agent-to-dart`) фиксируют переключение формально, но новых функций Python-агента между двумя датами всё равно бы не было.

*Альтернатива:* с подписи ворот. Тогда политика «вступает в силу в будущем», а задача 4.4 закрывалась бы документом без даты.

### D4. Условие удаления и запись решения

Условие (план 9.9, без изменений по сути): после переключения опубликована хотя бы одна версия канала `stable` (первая — веха «продукт 1.0», 9.4), и на дату решения в трекере `codelab-app` нет открытого issue с меткой `parity-regression`.

Метка `parity-regression` ставится на дефект, где поведение Dart-агента или клиентов хуже Python-агента по строке Must матрицы (§3, §4.1). Id строки пишется в заголовок issue (`[R-03] …`), чтобы запрос по метке сразу давал строки. Метку ставит любой участник, снимает — закрытие issue исправлением или решение владельца продукта «не регрессия» с комментарием.

Решение об удалении принимают вместе владелец продукта и ответственный за релиз. Запись — таблица «Условие удаления» в `proposal.md` change `remove-python-agent`:
- тег и дата `stable`-версии;
- ссылка на запрос трекера `label:parity-regression is:open` с датой и результатом «0»;
- две подписи.

Пока таблица не подписана, change удаления не реализуется.

*Альтернативы:*
- искать регрессии по тексту — неповторяемо;
- ввести метки по строкам (`parity:R-03`) — 77 меток (по строке Must) ради одного запроса.

### D5. Связь с воротами MVP

Задача 4.4 `switch-default-agent-to-dart` («политика заморозки опубликована») закрывается двумя шагами:
- merge итерации 0 этого change в `develop` (задачи 0.1–0.6);
- внешний шаг E.1 — баннер в README Python-репозитория.

Ссылки на раздел документа и на коммит README записываются в `proposal.md` того change. Итерация 1 (алиас) в ворота не входит: по Q3 алиас нужен до первого выпуска с установщиком (9.4, M4), а не до MVP.

*Альтернатива:* закрывать 4.4 только документом в monorepo. Пользователь Python-агента читает README своего репозитория, и «опубликовано» без него было бы формальностью.

### D6. Алиас — запуск отдельного бинаря, а не встроенный сервер

`codelab` запускает найденный `codelab-agent` процессом `Process.start(…, mode: ProcessStartMode.inheritStdio)` и ждёт его `exitCode`. Дочерний процесс получает те же файловые дескрипторы. CLI не копирует байты, поэтому кадры ACP, буферизация и порядок stderr совпадают с прямым запуском `codelab-agent serve`. Это единственный вариант, при котором алиас гарантированно ведёт себя как `codelab-agent` по ACP: протокольного кода в алиасе нет.

*Альтернативы:*
- **Встроенный сервер в процессе `codelab`.** Пришлось бы вынести хост `serve` (`apps/codelab_agent/lib/src/serve/`: stdio и WebSocket, сигналы, логи, MCP, конфиг, `--llm-script`) в пакет, потому что пакеты не зависят от приложений. Затем — открыть его клиентам через мост `codelab_embedded`: allowlist `apps/codelab_cli` не допускает `codelab_agent_*`. Это новый публичный API моста и дублирование поведения `agent-binary` ради команды на один релиз. Плюс — работа без `codelab-agent` (установка `--cli-only`); его закрывает понятная ошибка D9.
- **Проксирование stdin/stdout через pipe.** Лишний код на границе ACP: чтение строк, отмена и обратное давление без выгоды перед `inheritStdio`.
- **Настоящий `exec`.** В Dart его нет без FFI (`execv`), а на Windows его нет вовсе.

Решение пользователя — Q1 (а), 2026-11-10.

### D7. Поиск бинаря

Чистая функция `locateAgentExecutable` в `lib/src/serve_alias.dart` получает:
- путь `Platform.resolvedExecutable` (ссылки уже раскрыты);
- значение `PATH` и разделитель ОС;
- признак Windows (имя `codelab-agent.exe`);
- проверку «исполняемый файл существует» и канонизацию пути — функциями, а не через `dart:io` внутри.

Порядок поиска:
1. каталог `codelab`;
2. записи `PATH` по порядку, только абсолютные — пустая запись и `.` пропускаются, чтобы текущая папка (например, клонированный репозиторий) не подставила свой `codelab-agent`;
3. кандидат, канонический путь которого совпадает с путём `codelab`, отбрасывается — иначе ссылка `codelab-agent → codelab` дала бы бесконечную цепочку процессов.

**Защита от рекурсии через обёртку** (решение пользователя Q10). Сравнение путей не ловит скрипт-обёртку `codelab-agent`, который сам вызывает `codelab serve …`. Поэтому алиас ставит дочернему процессу внутреннюю переменную-маркер окружения. Вход в алиас при заданном маркере даёт одну строку в stderr без argv — `codelab: "codelab serve" cannot run itself; check that codelab-agent is not a wrapper around codelab serve, or run "codelab-agent serve" directly.` — и код `1`; агент не запускается. Имя переменной — деталь реализации, в пользовательский контракт оно не входит. Сейчас это `CODELAB_SERVE_ALIAS_ACTIVE=1` (`serveAliasMarker` в `lib/src/serve_alias.dart`).

**Побочный эффект.** Маркер наследуют все потомки агента, запущенного через алиас: команды инструмента `exec`, терминалы, stdio-серверы MCP. Поэтому `codelab serve …`, вызванный изнутри такой сессии, тоже получает отказ с кодом `1`, хотя рекурсии нет. Выход указан в самом сообщении: запустить `codelab-agent serve` напрямую — без алиаса маркера нет. Случай редкий, ведь агент внутри агента через устаревшую команду почти не нужен. Отличить его от обёртки по одному окружению нельзя, а очищать маркер у агента значило бы менять `codelab-agent` ради алиаса на один релиз.

**Ограничения поиска** (решение пользователя Q11):
- выбирается первый найденный кандидат. Исполняемость проверяется по битам режима файла (любой `x`), а не по правам текущего пользователя. Если запуск этого кандидата не удался, следующий не пробуется: сбой запуска — код `1` (D9). Перебор скрыл бы, какой файл на самом деле сломан;
- на Windows окружающие кавычки записи `PATH` (`"C:\Program Files\x"`) снимаются до проверки абсолютности. Записи `PATH` в кавычках на Windows допустимы, и без этого каталог с пробелом был бы пропущен.

Порт и класс для поиска не вводятся (`AGENTS.md` §13): функция тестируется подстановкой двух функций — швов `isExecutableFile` и `canonicalize`.

*Альтернатива:* передать имя `codelab-agent` в `Process.start` и положиться на поиск ОС. Тогда пустая запись `PATH` означает текущую папку (POSIX `execvp`), а сравнить кандидата с самим `codelab` невозможно.

### D8. Где распознаётся алиас

`parseCliArgs` до `ArgParser` проверяет `args.firstOrNull == 'serve'` и возвращает `CliOptions(command: CliCommand.serveAlias, positional: args.skip(1))`. Ни один флаг `codelab` к алиасу не применяется: `--help`, `--stdio`, `--port` и остальные принадлежат `codelab-agent`. `run.dart` в ветке `serveAlias` вызывает `runServeAlias` и больше ничего не открывает: ни домашний каталог, ни профили, ни логгер.

Только первое слово, а не «`serve` где угодно». Python-агент тоже принимал `serve` первым словом. А `codelab -v serve` и `codelab -- serve` остаются способами отправить слово `serve` первым сообщением REPL.

`codelab serve` без флагов — тоже алиас (решение Q2 (а)): всё после `serve`, даже пустой список, уходит `codelab-agent`, и тот отвечает `64` со своей справкой.

### D9. Вывод и коды выхода

- **Предупреждение** — одна строка в stderr до старта процесса, `flush` до `Process.start`, чтобы порядок строк в stderr был детерминирован. Версия снятия в тексте не называется («in a future release»): она зависит от того, когда выполнится условие D4. stdout алиас не трогает: для `--stdio` это канал ACP.
- **Код** — `exitCode` дочернего процесса. Отрицательный код (на POSIX Dart так отдаёт смерть от сигнала `N`) переводится в `128 + N`, как у оболочки.
- **Бинарь не найден** — `failureExit` (`1`): в `exit_codes.dart` это «агент не запустился». `64` означал бы ошибку в аргументах пользователя, а `127` в кодах CLI не используется. Текст называет оба места поиска, но не печатает `PATH`.
- **Сбой `Process.start`** (нет прав и т. п.) — `1` и `codelab: cannot start codelab-agent: <ProcessException.message>`, без аргументов, по правилу change `redact-cli-stdio-profile-args` (D9 там). Ранний `SIGTERM` или `SIGHUP` (D10), пришедший до неудачного запуска, кода не меняет (решение пользователя Q12): итог — `1` (сбой запуска), а не `143`/`129`. Пересылать сигнал некому, а скрипту важнее узнать, что агент не запустился.

*Альтернатива:* выводить предупреждение только на TTY. Скрипты и редакторы, которым оно и адресовано, запускают агента без TTY.

### D10. Сигналы и жизненный цикл

`runServeAlias` подписывается на сигналы через существующий `SignalSeam` (`lib/src/signals.dart`) до `Process.start` и снимает подписки после `exitCode`:
- **`SIGTERM`** — `process.kill(ProcessSignal.sigterm)`. Если сигнал пришёл до старта процесса, он запоминается и пересылается сразу после старта. Повторный `SIGTERM` пересылается тоже: «повторный — немедленный выход» решает сам агент.
- **`SIGHUP`** — пересылается так же, как `SIGTERM`, включая ранний сигнал (решение пользователя Q9). Закрытие терминала или сеанса SSH шлёт `SIGHUP` процессу `codelab`; без пересылки `codelab` умер бы по умолчанию, а агент `--ws` остался бы без владельца. Код выхода — код агента.
- **`SIGINT`** — перехватывается, чтобы `codelab` не умер раньше агента, но не пересылается. Терминал доставляет Ctrl+C всей группе переднего плана, куда входит и агент: пересылка дала бы агенту второй сигнал, то есть немедленный выход без дописанного журнала. Цена: `kill -INT <pid codelab>` до агента не дойдёт. ACP-клиенты останавливают агента закрытием stdin или `SIGTERM`.
- **`SIGKILL` `codelab`** перехватить нельзя (без FFI). С `--stdio` агент выходит по EOF stdin, когда клиент закрывает свой конец канала, с кодом `0`. С `--ws` агент остаётся работать: клиенты подключаются по сокету, а stdin агента с ними не связан, и EOF не наступает. Такого агента останавливают `SIGTERM` или `SIGHUP` по его собственному pid. Ограничение записано в документе перехода.
- **Windows** — только `SIGINT`: консоль рассылает Ctrl+C всем процессам консоли. `SIGTERM` и `SIGHUP` не отслеживаются.

`dart:io` в `serve_alias.dart` — процесс и сигналы. Это новое место в списке мест `dart:io` `apps/codelab_cli/AGENTS.md` §2: оно дописывается, а правило сторожа не меняется, потому что `dart:io` в `apps/codelab_cli` сторож разрешает. Чистые части (`locateAgentExecutable`, перевод кода выхода, текст сообщений) — функции без `dart:io`, их проверяют модульные тесты.

### D11. Срок жизни алиаса и semver

Алиас появляется в итерации 1 этого change и живёт до change `remove-python-agent`, который начинается только после условия D4. Тем самым выполняется «в течение одной `stable`-версии» плана 9.9: первая `stable` (1.0.0) содержит алиас.

Конфликт: §12.7.8 считает ломающее изменение CLI поводом для major-версии, а снятие команды — ломающее изменение. Решение Q3 (а): в §12.7.8 дописано исключение. Переходный алиас, помеченный в `CHANGELOG.md` первой `stable` как «deprecated, will be removed», в контракт стабильного CLI не входит. Он снимается в первой minor-версии после выполнения условия D4, но не в patch-версии. Текст исключения — задача 0.5.

### D12. Режим `python` e2e рядом с алиасом

Правило обнаружения Python-агента не ломается алиасом. `codelab serve --help` у Dart CLI с алиасом уходит в `codelab-agent serve --help`, а это код `64`, справка в stderr и пустой stdout. Признака Python-агента (код `0` и `--stdio` в stdout) нет, тесты пропускаются с прежней причиной. Требование testing-quality «PTY-e2e терминального клиента» не меняется.

Эту зависимость от того, что у `codelab-agent serve` нет `--help` с кодом `0`, закрепляет модульный тест `e2e_agent_test.dart`: фальшивый `codelab`, ведущий себя как алиас, — причина пропуска (задача 1.9). Если `codelab-agent` когда-нибудь получит `serve --help` с кодом `0`, тест покажет, что обнаружение нужно сузить.

Режим `python` остаётся до change `remove-python-agent` (решение Q5 (а)).

### D13. Распределение по changes: удаление — отдельным change

План 9.9 и решение Q3 change `switch-default-agent-to-dart` относили удаление к этому change. Решение Q6 (а) разделило его:
- **`retire-python-agent`** (этот) — политика заморозки, условие удаления, алиас. Архивируется после итерации 1.
- **`remove-python-agent`** — создаётся после подписи таблицы D4:
  - REMOVED «Алиас codelab serve» в `codelab-cli`;
  - режим `python`, тег `python-agent` и скрипт `test:e2e:cli:python-agent` — MODIFIED в `testing-quality`;
  - упоминания Python-агента в `docs/user/`, плане, матрице и `AGENTS.md`;
  - внешние шаги E.4–E.6 (E.5 — завершающий тег в Python-репозитории).

Почему отдельный change: требование алиаса должно попасть в `openspec/specs/codelab-cli` и действовать там весь срок жизни алиаса — месяцы между 1.0 и условием D4. Изменение, которое и добавляет, и удаляет одно требование, после архивирования не оставило бы его в спецификации ни на день. Пока такой change активен, спецификация не описывала бы работающий алиас (`AGENTS.md` §3.1). Кроме того, change удаления зависит от календаря и подписей, как итерация 4 `switch-default-agent-to-dart`, и держать ради этого открытым change с уже работающим кодом нет смысла.

*Альтернатива:* один change с итерацией 2 «удаление» и архивированием после неё — проще по числу changes, но с разрывом между кодом и спецификацией на время жизни алиаса. Отклонена решением Q6 (а).

### D14. Пакеты, зависимости, сторож, граф

- Затронуто только приложение `apps/codelab_cli` (сторона `client`, ADR-0002). Новых пакетов нет. `codelab-agent`, `codelab_embedded`, `codelab_setup` не меняются.
- Новых зависимостей нет: `Process`, `ProcessSignal` из `dart:io`, `path` уже в `cliAllowlist`.
- Нового правила в `test/support/rules.dart` нет (D10). Направление зависимостей не меняется: CLI не импортирует `package:codelab_agent_*`, связь с агентом — только процесс.
- Граф `README.md` не меняется. Web-безопасные пакеты не затронуты, `web-compile` не нужен. Allowlist ядра (PKG-2) не затрагивается.

### D15. Итерации

- **0 — политика и документы.** D1–D5, D11, D13: раздел политики, план, дорожная карта, риски, допущение 5, §12.7.8. Закрывает задачу 4.4 `switch-default-agent-to-dart` вместе с E.1.

## Risks / Trade-offs

- **Python-агент и Dart CLI под одним именем `codelab`.** Если у пользователя стоят оба, побеждает первый в `PATH`. Алиас конфликт не устраняет, а делает безвредным для скриптов `codelab serve --stdio`: оба варианта запускают агента. Документ перехода объясняет `which codelab`.
- **Нет `codelab-agent` (`--cli-only`, только `build:cli`).** Алиас отвечает кодом `1` с подсказкой. Встроенный сервер (D6, альтернатива) закрыл бы этот случай ценой нового API моста.
- **`SIGINT`, присланный только процессу `codelab`, до агента не доходит** (D10) — осознанная цена против двойного сигнала.
- **Предупреждение в stderr попадает в журналы редакторов** (Zed «ACP logs» показывает stderr агента). Это и есть цель, но строка повторяется при каждом запуске.
- **Метка `parity-regression` работает, только если её ставят.** Шаблон issue с полем «строка матрицы» — внешний шаг E.2; без него условие D4 проверяет лишь то, что отмечено.
- **Срок удаления неизвестен заранее.** Он зависит от 9.4 и трекера, поэтому версия снятия в предупреждении не называется (D9).

## Migration Plan

1. Итерация 0 → merge → E.1 → ссылки в `proposal.md` `switch-default-agent-to-dart`, задача 4.4.
2. Итерация 1 → merge → архивирование этого change по просьбе пользователя. Требование «Алиас codelab serve» переходит в `openspec/specs/codelab-cli`.
3. Первая `stable` (9.4) выходит с алиасом и записью «deprecated» в `CHANGELOG.md` (задача ветки `release/<version>`, E.3).
4. Условие D4 выполнено → таблица подписана → change `remove-python-agent` (D13) → внешние шаги E.4–E.6.

Откат итерации 1 — revert: без алиаса `codelab serve` снова даёт `64` (`--stdio`) или REPL (без флагов). Данных пользователя алиас не пишет.

## Решения пользователя 2026-11-10

- **Q1** — (а): алиас запускает отдельный бинарь `codelab-agent` (рядом с `codelab` или в `PATH`) с общим stdio; встроенный сервер в процессе `codelab` не делается (D6).
- **Q2** — (а): `codelab serve` без флагов — тоже алиас; `codelab-agent serve` отвечает `64` со своей справкой, слово `serve` первым сообщением REPL — `codelab -- serve` (D8; BREAKING в `proposal.md`).
- **Q3** — (а): исключение в §12.7.8 — переходный алиас, помеченный deprecated в `CHANGELOG.md` первой `stable`, не входит в контракт стабильного CLI и снимается первой minor-версией после выполнения условия D4, не patch-версией (D11, задача 0.5).
- **Q4** — (а): алиас — итерация 1 сразу после итерации 0, независимо от 9.4 (D15).
- **Q5** — (а): режим `python` e2e, тег `python-agent` и `test:e2e:cli:python-agent` остаются до change `remove-python-agent`; дельты `testing-quality` нет (D12).
- **Q6** — (а): удаление — отдельный change `remove-python-agent`; этот change архивируется после итерации 1 (D13).
- **Q7** — (а): алиаса `codelab connect` нет; `codelab connect` по-прежнему открывает REPL с первым сообщением `connect`.
- **Q8** — внешние шаги E.1–E.6 выполняет пользователь — владелец репозитория `pese-git/codelab-agent`. Python-агент ставится из исходников или через `uv`/`pip` из репозитория и на PyPI не публикуется, поэтому последнего выпуска пакета нет: E.5 — завершающий тег в репозитории перед архивированием.

**Дополнения по двойному ревью итерации 1 (одобрены пользователем 2026-11-10):**

- **Q9** — `SIGHUP` пересылается агенту так же, как `SIGTERM`, включая ранний; на Windows не отслеживается. `SIGKILL` процессу `codelab` не перехватывается: агент `--stdio` завершится по EOF stdin, агент `--ws` продолжит работать. Ограничение записано в документе перехода (D10).
- **Q10** — защита от рекурсии внутренней переменной-маркером окружения: повторный вход в алиас — код `1` с подсказкой запустить `codelab-agent serve` напрямую. Принятый побочный эффект: `codelab serve` изнутри сессии агента, запущенного через алиас, тоже получает отказ, потому что маркер наследуют потомки — команды и MCP (D7).
- **Q11** — выбирается первый найденный кандидат (исполняемость — по битам режима). Если его запуск не удался, следующий не пробуется, код `1`. На Windows окружающие кавычки записей `PATH` снимаются (D7).
- **Q12** — ранний `SIGTERM`/`SIGHUP` вместе со сбоем запуска даёт код `1` (сбой запуска), а не код сигнала (D9).
