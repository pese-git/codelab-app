## ADDED Requirements

### Requirement: Сайт вне pub workspace и Melos
Сайт CodeLab SHALL быть статическим сайтом на Astro в каталоге `site/` monorepo (ADR-0003; design.md change `add-astro-site`, D1, D2):
- `site/` SHALL иметь собственные `package.json` (`"private": true`) и закоммиченный `package-lock.json`;
- версии зависимостей в `package.json` SHALL быть точными — без диапазонов `^`, `~`, `*`, `x`;
- версия Node SHALL быть закреплена в `site/.nvmrc`;
- установка зависимостей SHALL выполняться `npm ci`.

`site/` НЕ SHALL входить в `workspace:` корневого `pubspec.yaml` и в Melos. Node, npm и JavaScript-зависимости НЕ SHALL появляться вне `site/`. Сайт собирается только на русском языке.

#### Scenario: Сторож не видит сайт
- **WHEN** в `site/` установлены зависимости (`site/node_modules/` существует) и выполняется `fvm dart run melos run guard`
- **THEN** сторож проходит так же, как без `site/`, и не сообщает о файлах `site/`

#### Scenario: Dart-проверки не обходят сайт
- **WHEN** в `site/` установлены зависимости и выполняются `fvm dart run melos run check-format` и `fvm dart analyze` из корня
- **THEN** обе команды проходят, а анализатор не анализирует файлы `site/`

#### Scenario: Воспроизводимая установка
- **WHEN** в чистом checkout выполняется `npm ci` в `site/` на версии Node из `site/.nvmrc`
- **THEN** устанавливаются ровно версии из `package-lock.json`, а при расхождении `package.json` и lock-файла команда завершается ошибкой

#### Scenario: Диапазон версии отклоняется
- **WHEN** в `site/package.json` появляется зависимость с диапазоном версии, например `^5.0.0`
- **THEN** проверка сайта (`npm run verify`) завершается ошибкой с именем зависимости

### Requirement: Публикуемые источники документации
Сайт SHALL строить страницы документации из Markdown-файлов репозитория на месте, без копий в `site/` (design.md, D3). Публикуются только файлы из закрытого списка:
- `docs/user/**/*.md`, `docs/ops/**/*.md`;
- `apps/*/README.md`, `apps/*/doc/**/*.md`;
- `packages/*/*/README.md`, `packages/*/*/doc/**/*.md`.

Файл вне списка НЕ SHALL становиться страницей сайта, в том числе файлы `openspec/`, `docs/architecture/`, `docs/protocols/`, `docs/backlog/`, `docs/design/` и любой `AGENTS.md`.

Адрес страницы SHALL выводиться из пути файла (D4): `<путь без .md>/` под префиксом `docs/`; `README.md` даёт адрес своего каталога. Заголовок страницы SHALL браться из первого заголовка первого уровня файла; файл без такого заголовка SHALL ломать сборку с путём файла в сообщении.

#### Scenario: Страница собирается из файла репозитория
- **WHEN** собирается сайт, а в репозитории есть `docs/user/configuration.md` с заголовком `# Настройка агента`
- **THEN** в сборке есть страница `<base>docs/user/configuration/` с заголовком «Настройка агента» и текстом этого файла, а в `site/` копии файла нет

#### Scenario: README даёт адрес каталога
- **WHEN** собирается сайт, а в репозитории есть `apps/codelab_cli/README.md`
- **THEN** страница доступна по адресу `<base>docs/apps/codelab_cli/`

#### Scenario: Новый документ появляется без правки сайта
- **WHEN** `docs-writer` добавляет `apps/codelab_desktop/doc/terminal.md`, а файлы `site/` не меняются
- **THEN** следующая сборка содержит страницу `<base>docs/apps/codelab_desktop/doc/terminal/` в навигации раздела CodeLab app

#### Scenario: Неопубликованный файл не становится страницей
- **WHEN** собирается сайт, а в репозитории есть `docs/architecture/testing.md`, `docs/backlog/smoke-2026-10-30.md` и `apps/codelab_cli/AGENTS.md`
- **THEN** в сборке нет страниц и файлов с их содержимым

#### Scenario: Документ без заголовка
- **WHEN** опубликованный файл не содержит заголовка первого уровня
- **THEN** сборка завершается ошибкой с путём файла от корня репозитория

### Requirement: Перевод относительных ссылок документации
Ссылки и изображения в опубликованных документах SHALL оставаться в репозитории относительными путями, которые работают на GitHub. При сборке сайт SHALL переводить их так (design.md, D5):
- ссылка на опубликованный файл — в адрес его страницы на сайте с учётом `base`, якорь сохраняется;
- ссылка на существующий неопубликованный файл или каталог — в адрес на GitHub (`<репозиторий>/blob/<ref>/<путь>` для файла, `<репозиторий>/tree/<ref>/<путь>` для каталога), якорь сохраняется. `<ref>` — параметр конфигурации сайта `SITE_GITHUB_REF`; по умолчанию — коммит сборки: `GITHUB_SHA` в CI, локально — текущий `HEAD`;
- относительное изображение — в файл изображения в сборке сайта;
- внешние ссылки (`http:`, `https:`, `mailto:`) и якоря внутри страницы не меняются.

Сборка SHALL завершаться ошибкой с путём исходного файла и номером строки, если относительная ссылка или изображение указывают на несуществующий файл или за пределы репозитория, если ссылка — абсолютный путь файловой системы или `file:`, а также если у изображения пустой `alt`.

#### Scenario: Ссылка на опубликованный файл ведёт на страницу сайта
- **WHEN** `docs/user/README.md` содержит `[Настройка](configuration.md#шаг-2-задайте-ключ-api)`, а сайт собирается с `base` `/codelab-app/`
- **THEN** на странице `/codelab-app/docs/user/` ссылка ведёт на `/codelab-app/docs/user/configuration/#шаг-2-задайте-ключ-api`

#### Scenario: Ссылка на файл приложения из сквозного документа
- **WHEN** `docs/ops/README.md` содержит ссылку `../../apps/codelab_cli/doc/operations.md`
- **THEN** ссылка на сайте ведёт на страницу `<base>docs/apps/codelab_cli/doc/operations/`

#### Scenario: Ссылка на непубликуемый файл ведёт на GitHub
- **WHEN** опубликованный документ ссылается на `../architecture/testing.md#74-ci-levels`
- **THEN** ссылка на сайте ведёт на `<репозиторий>/blob/<ref>/docs/architecture/testing.md#74-ci-levels`

#### Scenario: Ссылка на каталог ведёт на GitHub
- **WHEN** опубликованный документ ссылается на `../../packages/dart/codelab_setup/`
- **THEN** ссылка на сайте ведёт на `<репозиторий>/tree/<ref>/packages/dart/codelab_setup`

#### Scenario: Ссылка на GitHub ведёт на коммит сборки
- **WHEN** сайт собирается в CI с `GITHUB_SHA=abc123…` без `SITE_GITHUB_REF`
- **THEN** ссылки на неопубликованные файлы имеют вид `<репозиторий>/blob/abc123…/<путь>`

#### Scenario: Цель ссылок задана явно
- **WHEN** сайт собирается с `SITE_GITHUB_REF=master`
- **THEN** ссылки на неопубликованные файлы имеют вид `<репозиторий>/blob/master/<путь>`

#### Scenario: Битая ссылка ломает сборку
- **WHEN** `apps/codelab_cli/doc/user-guide.md` ссылается на несуществующий `operation.md`
- **THEN** `astro build` завершается ошибкой, в сообщении — `apps/codelab_cli/doc/user-guide.md`, номер строки и `operation.md`

#### Scenario: Изображение из каталога приложения
- **WHEN** `apps/codelab_desktop/doc/user-guide.md` содержит `![Палитра команд](images/command-palette.png)`
- **THEN** страница показывает изображение из сборки сайта с тем же `alt`, а в `site/` копии файла нет

#### Scenario: Внешняя ссылка не меняется
- **WHEN** документ содержит `[FVM](https://fvm.app)`
- **THEN** ссылка на сайте ведёт на `https://fvm.app`

### Requirement: Проверка внутренних ссылок собранного сайта
После сборки проверка ссылок SHALL убеждаться, что каждая внутренняя ссылка (`href`, `src`) каждой страницы ведёт на существующий файл сборки, а якорь — на существующий `id` целевой страницы (design.md, D6). Нарушение SHALL завершать проверку ошибкой со списком «страница → ссылка». Внешние ссылки проверка НЕ SHALL запрашивать по сети.

#### Scenario: Ссылка на несуществующий якорь
- **WHEN** документ ссылается на `configuration.md#нет-такого-раздела`, а такого заголовка в `configuration.md` нет
- **THEN** проверка ссылок завершается ошибкой, в сообщении — страница-источник и ссылка

#### Scenario: Ссылка страницы сайта
- **WHEN** страница возможностей `codelab` ссылается на руководство пользователя CLI
- **THEN** проверка ссылок находит целевую страницу, и ошибки нет

### Requirement: Mermaid-схемы в браузере
Блок кода с языком `mermaid` в опубликованном документе SHALL отрисовываться на сайте как схема средствами `mermaid.js` в браузере (design.md, D7). Отрисовки при сборке нет. Скрипт mermaid SHALL загружаться только на страницах, где есть такие блоки, и только из сборки сайта, без запросов к сторонним серверам. Схема SHALL перерисовываться при смене темы сайта. Без JavaScript SHALL оставаться видимым исходный текст схемы.

#### Scenario: mermaid-блок отрисовывается
- **WHEN** открыта страница документа с блоком ```` ```mermaid ```` и `flowchart LR`
- **THEN** вместо исходного текста показана SVG-схема с узлами этого блока

#### Scenario: Тёмная тема
- **WHEN** на странице со схемой пользователь переключает сайт на тёмную тему
- **THEN** схема перерисована в тёмной теме mermaid без перезагрузки страницы

#### Scenario: Страница без схем
- **WHEN** открыта страница без блоков mermaid
- **THEN** скрипт mermaid не загружается

#### Scenario: Без JavaScript
- **WHEN** страница со схемой открыта с отключённым JavaScript
- **THEN** виден исходный текст схемы в блоке кода

### Requirement: Разделы сайта
Сайт SHALL содержать разделы (design.md, D9):
- главную с описанием трёх продуктов — CodeLab app, терминального клиента `codelab` и агента `codelab-agent` — и ссылками на их страницы;
- страницу возможностей каждого продукта;
- «Установку и быстрый старт» — страницу документа `docs/user/run-from-source.md`, без копии его команд на страницах сайта;
- документацию с навигацией по группам «Пользователю», «Эксплуатация», «CodeLab app», «`codelab`», «`codelab-agent`», «Пакеты»;
- новости выпусков;
- страницу 404.

Каждая страница SHALL объявлять `lang="ru"`. Тексты страниц сайта SHALL описывать только существующее поведение продуктов, проверяемое по коду и документации (`.claude/skills/codelab-docs/SKILL.md` §4, §8), без обещаний будущих возможностей.

#### Scenario: Главная ведёт к продуктам и установке
- **WHEN** открыта главная страница
- **THEN** на ней три продукта со ссылками на их страницы возможностей и ссылка «Установка», которая ведёт на `<base>docs/user/run-from-source/`

#### Scenario: Документ попадает в группу по расположению
- **WHEN** собирается сайт с файлом `apps/codelab_cli/doc/operations.md`
- **THEN** его страница находится в группе навигации «`codelab`»

#### Scenario: Скриншот на странице возможностей
- **WHEN** страница возможностей CodeLab app показывает снимок экрана
- **THEN** снимок взят из `apps/codelab_desktop/doc/images/`, а не из копии в `site/`

### Requirement: Новости выпусков
Новость SHALL быть файлом коллекции `site/src/content/news/`, одним на выпуск (design.md, D10). Frontmatter новости SHALL содержать `title`, `date` (`YYYY-MM-DD`), `version` и `summary`. Сборка SHALL завершаться ошибкой, если поле отсутствует или имеет неверный формат, или если две новости объявляют одну версию. Новости SHALL выводиться от новой к старой. Без новостей страница новостей SHALL показывать пустое состояние.

#### Scenario: Новость выпуска
- **WHEN** в `release/<version>` добавлен файл новости с корректным frontmatter
- **THEN** новость есть в списке новостей первой и на своей странице

#### Scenario: Неполная новость
- **WHEN** у файла новости нет поля `version`
- **THEN** сборка завершается ошибкой с путём файла и именем поля

#### Scenario: Повтор версии
- **WHEN** два файла новостей объявляют одну и ту же `version`
- **THEN** сборка завершается ошибкой с путями обоих файлов

#### Scenario: Новостей нет
- **WHEN** коллекция новостей пуста
- **THEN** страница новостей собирается и сообщает, что выпусков пока нет

### Requirement: Оформление и темы
Сайт SHALL использовать визуальные токены приложения — цвета, шрифты, радиусы и тени Fluent из `docs/design/claude-design/fluent.css` и `packages/flutter/codelab_ui` (skill `codelab-site`; design.md, D8). Сайт SHALL иметь светлую и тёмную темы. По умолчанию тема SHALL следовать системной настройке (`prefers-color-scheme`). Выбор пользователя SHALL сохраняться в браузере и применяться до первой отрисовки страницы. Сайт НЕ SHALL загружать шрифты, скрипты, стили и изображения со сторонних серверов.

#### Scenario: Системная тёмная тема
- **WHEN** сайт открыт в браузере с системной тёмной темой и без сохранённого выбора
- **THEN** страница отрисована в тёмной теме сразу, без вспышки светлой

#### Scenario: Выбор темы сохраняется
- **WHEN** пользователь переключает тему и переходит на другую страницу
- **THEN** новая страница открывается в выбранной теме

#### Scenario: Нет сторонних запросов
- **WHEN** открыта любая страница сайта
- **THEN** браузер не обращается к хостам, кроме хоста самого сайта

### Requirement: Безопасность публикации
Сборка SHALL завершаться ошибкой с путём исходного файла (design.md, D11), если опубликованный документ содержит:
- сырой HTML-элемент вне списка допустимых (`details`, `summary`, `br`, `kbd`, `sub`, `sup`); HTML-комментарии допустимы и в сборку не попадают;
- абсолютный путь домашнего каталога (`/Users/<имя>/`, `/home/<имя>/`, `C:\Users\<имя>\`) с именем, отличным от масок `user` и `me` (`.claude/skills/codelab-docs/SKILL.md` §7).

Сайт НЕ SHALL содержать аналитики и сторонних счётчиков.

#### Scenario: Скрипт в документе
- **WHEN** опубликованный документ содержит `<script>`
- **THEN** сборка завершается ошибкой с путём файла и строкой

#### Scenario: Личный путь в документе
- **WHEN** опубликованный документ содержит `/Users/alice/projects/demo`
- **THEN** сборка завершается ошибкой с путём файла и строкой

#### Scenario: Замаскированный путь
- **WHEN** снимок вывода в документе содержит `/home/me/.codelab/config.yaml`
- **THEN** сборка проходит

#### Scenario: Маркер скриншота
- **WHEN** документ содержит `<!-- screenshot: палитра команд -->`
- **THEN** сборка проходит, а текста маркера нет в HTML страницы

### Requirement: Конфигурация под будущий хостинг
Адрес сайта и префикс путей SHALL задаваться при сборке переменными окружения `SITE_URL` и `SITE_BASE`. По умолчанию `SITE_BASE` — `/`, а без `SITE_URL` абсолютные адреса (canonical, карта сайта) не формируются. Все внутренние ссылки, скрипты, стили и изображения SHALL учитывать `SITE_BASE` (design.md, D12).

#### Scenario: Сборка под подкаталог
- **WHEN** сайт собирается с `SITE_BASE=/codelab-app/`
- **THEN** каждая внутренняя ссылка и каждый ресурс сборки начинаются с `/codelab-app/`, и проверка ссылок проходит

### Requirement: Проверка сайта в CI
CI SHALL проверять сайт отдельным джобом `site` в `.github/workflows/ci.yml` (design.md, D13):
- `npm ci`;
- `astro check`;
- тесты плагинов сайта;
- `astro build` с `SITE_BASE`, отличным от `/`;
- проверка внутренних ссылок.

Джоб `site` SHALL быть обязательным: итоговый джоб `ci` SHALL ждать его и SHALL быть красным, если `site` завершился не `success` и не `skipped`. Джоб `site` НЕ SHALL публиковать сайт и НЕ SHALL получать секреты.

Решение о запуске принимает джоб `scope` (`tool/ci/ci_scope.dart`):
- в суженном прогоне `site` запускается, если изменён хотя бы один файл `site/**`, `docs/**`, `openspec/**`, `apps/*/README.md`, `apps/*/doc/**`, `packages/**/README.md` или `packages/**/doc/**`;
- в полном прогоне `site` запускается всегда.

Изменение файлов только в `site/` НЕ SHALL запускать Dart-джобы.

#### Scenario: Изменение сайта запускает джоб сайта
- **WHEN** pull request из `feature/*` в `develop` меняет только `site/src/pages/index.astro`
- **THEN** `scope` выдаёт `site=true` и пустую матрицу Dart-джобов, запускается только джоб `site`

#### Scenario: Изменение опубликованной документации запускает джоб сайта
- **WHEN** pull request меняет только `docs/user/configuration.md`
- **THEN** `scope` выдаёт `site=true` и пустую матрицу Dart-джобов

#### Scenario: Архивирование change запускает джоб сайта
- **WHEN** pull request переносит `openspec/changes/<id>/` в `openspec/changes/archive/<дата>-<id>/`
- **THEN** `scope` выдаёт `site=true`, и если опубликованный документ ссылается на прежний путь, джоб `site` красный

#### Scenario: Красный site блокирует merge
- **WHEN** в pull request джоб `site` завершился ошибкой, а все Dart-джобы зелёные
- **THEN** итоговый джоб `ci` красный

#### Scenario: Пропущенный site не блокирует merge
- **WHEN** pull request меняет только код пакета, и джоб `site` пропущен (`skipped`)
- **THEN** итоговый джоб `ci` зелёный, если зелёные остальные джобы

#### Scenario: Изменение кода без документации не запускает сайт
- **WHEN** pull request меняет только `packages/dart/codelab_agent_core/lib/src/loop.dart`
- **THEN** `scope` выдаёт `site=false`, а матрица Dart-джобов — как без этого change

#### Scenario: Полный прогон включает сайт
- **WHEN** CI запускается push в `develop`, ночью или по `workflow_dispatch`
- **THEN** `scope` выдаёт `site=true` вместе с полной матрицей

#### Scenario: Битая ссылка делает джоб красным
- **WHEN** pull request добавляет в `docs/ops/codelab-home.md` ссылку на несуществующий файл
- **THEN** джоб `site` красный, в журнале — путь документа и ссылка
