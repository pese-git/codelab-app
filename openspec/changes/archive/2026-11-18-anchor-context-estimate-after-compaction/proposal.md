## Why

Change `fix-compaction-estimate-and-no-gain` (влит в `develop`, коммит `e954ee24`; ещё не архивирован) сделал согласованными числа самого сжатия: `tokensAfter = tokensBefore + H(после) − H(до)`, где `H` — эвристика `chars/4` без якоря. Но между сжатием и следующим ответом модели с usage оценка контекста осталась чистой эвристикой:

- проекция после сжатия обнуляет usage всех ответов (§8.7 `buildLlmContext`), поэтому `estimateContextTokens` не находит якоря и считает `chars/4` по системному промпту, схемам инструментов и всем сообщениям;
- эту эвристику видят проверка `preflight` цикла (`lib/src/loop/agent_loop.dart`, шаг 4 §5.2), `ModelRequested.estimatedTokens`, `StepEnded.context.used` ответа без usage и проверка `afterTurn` (`_compactAfterTurn` в `lib/src/runtime/agent_runtime.dart`);
- эвристика завышает постоянную часть: системный промпт и схемы профиля `agent-serve` — около 2 670 оценочных токенов против реальных ~1 500–1 700 у `gpt-4o`.

Чтобы аварийный путь не терял ход из-за расхождения шкал, предшественник ввёл временную меру D9: компактор сравнивает с порогом `max(after, H(после))`. Цена:
- у провайдеров с компактным токенайзером CMP-5 идёт по завышенной эвристике — лишние проходы суммаризатора (до трёх вызовов);
- если эвристика проекции после сжатия выше окна, а сжимать уже нечего (хвост — последний ход), три прохода её не уложат: следующий запрос режет `preflight`, аварийный вызов хода использован (CMP-8), ход заканчивается `context window exhausted`, хотя реальный контекст далеко от окна;
- первый `ModelRequested.estimatedTokens` после сжатия и `/compact`, вызванный сразу после другого сжатия, показывают эвристику, несопоставимую с `tokensAfter` записи.

Предшественник вынес исправление в отдельный change (его design.md: D1 (в), D9 (б), R1, Q2). Это он.

## What Changes

- **Якорь оценки на последнее сжатие** (design.md, D1–D2). Пока в оцениваемых сообщениях нет ответа модели с ненулевым `input + cacheRead + cacheWrite`, оценка контекста опирается на `tokensAfter` последней записи `compaction` активной ветки: `E = max(0, tokensAfter + H(контекст) − r)`, где `r` — эвристика той же проекции в момент фиксации якоря (системный промпт, схемы, сообщение-резюме, сообщение навыков, сохранённые сообщения). Пока промпт, схемы и покрытые записью сообщения не менялись, это ровно `tokensAfter + H(хвоста после записи)`; если они изменились, эвристикой оценивается только разница. Первый ответ с usage снова становится якорем, как сейчас.
- **Одна шкала для компактора и цикла** (D3, D8). Якорь — состояние сессии, которое меняется только вместе с транскриптом из журнала: после записанного сжатия (все триггеры) и при загрузке сессии. Им пользуются оценщики цикла (`estimateTokens`, `contextEstimator`), проверка `afterTurn` и «до» первого прохода компактора. Сразу после записи оценка контекста равна `tokensAfter` (новый инвариант CMP-11).
- **D9 предшественника снимается** (D8). Все сравнения компактора с порогом (CMP-5, выброс навыков по окну) идут по согласованному `after`: цикл после сжатия видит то же число. Лишние проходы и `context window exhausted` из-за завышающей эвристики уходят.
- **Загрузка и ветки** (D5). Якорь берётся из последней записи `compaction` активной ветки (`pathToLeaf`, `keptPath`); несколько сжатий подряд — последняя. При загрузке он фиксируется по проекции журнала и промпту, схемам после восстановления агента.
- **Некорректные значения** (D6). `tokensAfter ≤ 0` — якоря нет, чистая эвристика. Записи до предшественника (`tokensAfter` = эвристика своего времени) дают смещение около нуля, то есть прежнее поведение; миграции нет.
- **Формат наружу не меняется** (D9). `/compact` отвечает `Compacted: X → Y tokens.` прежним текстом; `ModelRequested.estimatedTokens` после сжатия — `tokensAfter` плюс оценка нового хвоста. Снимок `_codelab/session/usage` прежней формы.
- Документы ядра: `agent-core/09-compaction.md` §9.2, §9.3, §9.8, §9.9 (CMP-5, CMP-11), §9.10, §9.11; `agent-core/08-sessions.md` §8.7; `agent-core/17-13-session-scale.md` (шаги 2, 9, 11 и 12 структурного прохода); `agent-core/05-agent-loop.md` (шаг 4 §5.2).

## Не входит

- ACP: ни методов, ни полей, ни кадров; форма `_codelab/session/usage` не меняется.
- Формат журнала: в запись `compaction` ничего не добавляется (сохранение `r` в записи отклонено, Q2).
- Точность самой эвристики `chars/4`, стоимость картинок, токенайзеры провайдеров.
- Калибровка по ошибке `overflow` (поднять «до» аварийного сжатия до размера окна) и сохранение `max(after, H(после))` для `overflow` — отклонены (Q1).
- Учёт usage суммаризатора, порог минимального выигрыша, текст ответа `/compact` (как у предшественника).
- Смена ветки и откат к метке внутри открытой сессии (D29–D31 change `add-subagents-and-tasks`) — не реализованы; правило для них записано в D5, вводит его тот change, который добавит операцию.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `agent-compaction`:
  - ADDED «Якорь оценки на последнее сжатие»;
  - MODIFIED «Оценка токенов с якорем на usage» — порядок якорей (usage, затем сжатие, затем эвристика), сценарий обнулённого usage уточнён;
  - MODIFIED «Согласованная оценка после сжатия» (требование предшественника) — «до» первого прохода с якорем сжатия, сравнения с порогом по `after` вместо `max(after, H(после))`;
  - MODIFIED «Запись сжатия и пересборка» (в редакции предшественника) — шаг 10 по `after`, CMP-11.

`agent-loop` не меняется: требование «Оценка в ModelRequested» уже говорит «результат оценщика для payload», меняется только оценщик, который передаёт рантайм. `agent-slash-commands` и `agent-acp-server` не меняются.

## Impact

- Код: только `packages/dart/codelab_agent_core` — `lib/src/compaction/estimate.dart` (якорь сжатия в `estimateContextTokens`, фиксация якоря), `lib/src/session/projections.dart` (число сообщений, покрытых последним сжатием), `lib/src/compaction/compactor.dart` (якорь для «до», снятие D9), `lib/src/runtime/agent_runtime.dart` (состояние якоря сессии, оценщики цикла, `afterTurn`, загрузка). Публичный барель, `pubspec.yaml`, граф пакетов, правила сторожа не меняются.
- Тесты ядра: новые в `test/compaction/estimate_test.dart`, `compactor_test.dart`, `preflight_after_compaction_test.dart`, `after_turn_test.dart`, `skills_reattach_test.dart`, тесте проекций и загрузки сессии; переписываются тесты, закрепившие D9 (второй проход по эвристике).
- `codelab_agent_acp`, фикстуры ACP, клиенты: кода нет; проверки прогоняются (`fvm dart test`, `conformance:agent`).
- Зависит от `fix-compaction-estimate-and-no-gain` (влит в `develop`, tasks.md, 0.1); его требования «Согласованная оценка после сжатия» и «Запись сжатия и пересборка» должны быть в `openspec/specs/agent-compaction` до архивации этого change.
