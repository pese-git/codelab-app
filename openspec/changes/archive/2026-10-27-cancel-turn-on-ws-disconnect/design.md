## Context

`AcpAgentServer` при закрытии транспорта переводит сессии в `detached` на `config.detachGrace`. При нуле ход отменяется сразу (`SessionBridge.detach` → `_expire`). Бинарь сейчас задаёт ноль для stdio и 30 с для WebSocket (`agent_host.dart`).

Клиент при замене транспорта проваливает ожидающие запросы. Ответ на старый `session/prompt` устаревшего поколения ход не меняет, и тот остаётся `running` до `session/load`. `loadSession` заменяет сессию результатом `SessionStateMachine.replayHistory`: все ходы реплея `completed` без `stopReason`. Поэтому прерванный ход без ответа агента показан как «Completed with stopReason unknown.».

Файлы и команды исполняет клиент (`AcpClientExecutionEnv`, §13.9): ход без соединения получает `ClientDisconnected` на каждый `fs/*` и `terminal/*`, а ждёт переподключения только вопрос о разрешении.

## Goals / Non-Goals

**Goals:**
- Одинаковое и предсказуемое поведение stdio и WebSocket: обрыв соединения отменяет ход.
- Пользователь видит, что ход прерван, а не «завершён неизвестно как».
- Сессия после Reconnect свободна и принимает следующий промпт.

**Non-Goals:**
- Возобновление хода после переподключения и чтение `_meta.codelab.turnEnded` клиентом — после MVP.
- Изменения `codelab_agent_acp`: сервер уже поддерживает нулевой grace.
- `session/cancel` перед заменой транспорта: агент отменяет ход сам.

## Decisions

### D1. `detachGrace` бинаря — ноль для обоих транспортов

`AgentHost` передаёт `Duration.zero` и для `--ws`.

Отклонённые альтернативы:
- Возобновление хода (клиент читает `turnEnded`, агент держит `fs/*`/`terminal/*` до переподключения). Отложено: две доработки на двух сторонах ради сценария, который в MVP с loopback-WebSocket редок.
- Отмена хода клиентом через `session/cancel` перед заменой транспорта. Отклонено: при обрыве сети отправить её некуда, а явный Reconnect и так закрывает соединение, после чего сервер с нулевым grace отменяет ход.
- Флаг `--detach-grace`. Отклонено: конфиг бинаря — этап 8 (§15.6), а значение для MVP одно.

### D2. Клиент помечает прерванный ход после `session/load`

`_replaceTransport` до сброса подписок запоминает id сессий с активным ходом (`_interruptedTurns`). Успешный `loadSession` такой сессии после `replayHistory` переводит последний ход реплея в `cancelled` со `stopReason: cancelled` и снимает отметку. Ошибка `session/load` отметку сохраняет: следующая загрузка той же сессии её применит. Новый `sendPrompt` снимает отметку: дальнейшие ходы уже не прерванные.

Почему последний ход: агент записывает реплику пользователя в журнал в начале хода (§8), поэтому прерванный ход в реплее последний. Пометка — знание клиента о собственном соединении, ACP его не передаёт. Для агента CodeLab с нулевым grace оно совпадает с правдой: ход действительно отменён. Для стороннего агента по stdio процесс умер вместе с ходом.

Отклонённые альтернативы:
- Помечать ход отменённым сразу при замене транспорта. Отклонено: существующий контракт держит ход устаревшего поколения нетронутым (`SendPrompt does not overwrite turn state with a stale failure…`), а реплей всё равно заменит ходы при загрузке.
- Отдельный статус «прерван» или текст в ленте. Отклонено для MVP: `cancelled` уже есть в домене и UI, новый статус затронул бы `codelab_client_core` и app.

### D3. Поздние обновления после `session/load` не меняются

Они по-прежнему отбрасываются (`session has no active prompt turn`). С нулевым grace агент CodeLab их не шлёт.

## Risks / Trade-offs

- [Обрыв сети по WebSocket теряет идущий ход] → Принято для MVP: WebSocket loopback, Reconnect явный. Возобновление — после MVP.
- [Гонка: агент завершил ход до обрыва, но ответ не дошёл] → Ход будет помечен `cancelled`, хотя завершился. Ответ агента в реплее виден, итог показан неточно. Принято: окно гонки — один кадр.
- [Механизм `reattach` сервера не используется бинарём и может устареть] → Он покрыт тестами `codelab_agent_acp` и остаётся основой для возобновления после MVP.

## Migration Plan

Миграция не нужна: значение задаётся при старте процесса, состояние клиента в памяти.
