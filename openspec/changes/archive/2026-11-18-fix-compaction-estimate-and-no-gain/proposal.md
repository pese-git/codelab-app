## Why

Ручная проверка `/compact` с реальной моделью (OpenRouter `openai/gpt-4o-mini`, `compaction.keep_recent_tokens: 100`, три хода пользователя по ~150 слов) дала ответ `Compacted: 3043 → 3567 tokens.`: после сжатия оценка контекста выросла.

Причина разобрана по коду (`codelab_agent_core/lib/src/compaction/compactor.dart`, `estimate.dart`, `session/projections.dart`):

1. **«До» и «после» считаются разными методами.** `tokensBefore` — `estimateContextTokens` с якорем на точном `usage` последнего ответа провайдера (`input + cacheRead + cacheWrite + output` = 3043, токенайзер провайдера). После сжатия весь сохранённый хвост лежит в пути до новой записи `compaction`, поэтому `buildLlmContext` обнуляет usage всех ответов (§8.7) — якоря нет. `tokensAfter` получается чистой эвристикой `chars/4` по всему контексту, включая системный промпт и схемы инструментов. На настоящем ядре (профиль `agent-serve`, 11 инструментов) промпт и схемы — около 10 700 символов, то есть ≈ 2 670 оценочных токенов, тогда как у токенайзера o200k весь контекст с тремя ходами — 3 043. Завышение постоянной части примерно на тысячу токенов попадает только в «после».
2. **На маленьком регионе выигрыш мал.** При `keep_recent_tokens: 100` сжимаются два хода (~800 токенов), а резюме с обязательными разделами плюс обёртка `summary_wrapper` (~90 токенов) занимают 400–500. Реальная экономия — несколько сотен токенов, её перекрывает ошибка п. 1.

Последствия, кроме вводящего в заблуждение ответа:
- проверка CMP-5 «после прохода оценка не выше порога» идёт по завышенной оценке и может запускать лишние проходы (до трёх вызовов суммаризатора);
- второй и третий проходы берут «до» тоже чистой эвристикой, поэтому их записи несут несопоставимые числа;
- сжатие без выигрыша всё равно пишет запись `compaction` и заменяет транскрипт;
- снимок `_codelab/session/usage` с `trigger: "compaction"` (change `add-usage-extension`) берёт `context.used` из `tokensAfter`, и индикатор заполнения контекста после сжатия прыгает вверх.

## What Changes

- **Согласованная оценка после сжатия** (design.md, D1). `tokensAfter = tokensBefore + H(после) − H(до)`, где `H` — `estimateTokens` без якоря (системный промпт, схемы и все сообщения проекции) по проекции до сжатия и по проекции с ещё не записанной записью и приложенными навыками. Общая часть (промпт, схемы, хвост) взаимно сокращается, эвристикой оценивается только разница: убранный регион против резюме, обёртки и сообщения навыков. Без якоря `tokensBefore == H(до)` и результат совпадает с прежним. Нижняя граница — 0. Эта оценка — всё, что компактор сообщает и записывает: `tokensAfter` записи, `ContextCompacted`, логи `compaction.done` и `compaction.skipped`, проверка выигрыша CMP-10.
- **Порог — по тому, что увидит цикл** (D9, по итогам ревью безопасности). После сжатия якоря в проекции нет, и `preflight` цикла и `afterTurn` считают чистую эвристику `H(после)`. Если бы проходы CMP-5 останавливались по согласованному «после», аварийное сжатие у реального провайдера могло закончиться, когда `preflight` всё ещё видит превышение окна, а второго аварийного вызова в ходе нет (CMP-8) — ход терялся бы. Поэтому все сравнения компактора с порогом (CMP-5, выброс навыков по окну D20 change `add-agent-skills`) идут по `max(after, H(после))`, для всех триггеров.
- **Цепочка проходов** (D2). «До» второго и третьего прохода — «после» предыдущего прохода, а не новая оценка проекции без якоря.
- **Сжатие без выигрыша не применяется** (D3). Если согласованное «после» не меньше «до», запись не пишется, транскрипт не меняется, `ContextCompacted` нет; исход — `NothingToCompact('no reduction')` или `Compacted` прошлого прохода. Лог `compaction.skipped` (`info`) с полем `reason`; тот же лог с `reason: "no cut point"` пишется и при отсутствии среза. Новый инвариант **CMP-10**: записанное сжатие уменьшает оценку контекста, `tokensAfter < tokensBefore`.
- **`/compact` без выигрыша** отвечает, как на любой `NothingToCompact`, — `Nothing to compact.` (D4); текст ответа не меняется, причина — в логе.
- Документы ядра: `agent-core/09-compaction.md` (§9.2, §9.3, §9.8, §9.9, §9.10, §9.11), `agent-core/13-acp-adapter.md` (ответ `/compact`), `agent-core/17-13-session-scale.md` (шаги 9 и 12 структурного прохода — та же оценка и тот же порог), `agent-core/12-observability-and-errors.md` (каталог событий области `compaction` приведён к коду: `compaction.done`, `compaction.skipped`, `compaction.failed`). Документы обновлены архитектором в составе change (задачи 0.1, 0.2).

## Не входит

- ACP: ни методов, ни полей, ни кадров. Форма `_codelab/session/usage` не меняется: снимок `compaction` по-прежнему идёт после `ContextCompacted`, просто его `used` теперь согласован с последним снимком хода, а при сжатии без выигрыша снимка нет.
- Оценка между сжатием и следующим ответом модели (проверка `preflight`, `ModelRequested.estimatedTokens`, `afterTurn` до нового ответа): там по-прежнему чистая эвристика проекции без якоря — завышение в безопасную сторону, прежнее поведение; компактор согласуется с ней порогом D9. Якорь на `tokensAfter` записи `compaction` — отдельный change (design.md, D9 (б), R1, Q2).
- Устранение лишних проходов CMP-5 у провайдеров, чей токенайзер компактнее `chars/4`: по D9 их число остаётся прежним; уходит вместе с якорем Q2.
- Порог минимального выигрыша (проценты, абсолютное число токенов) и ключ конфигурации для него (D3).
- Текст ответа `/compact` с причиной (D4, Q1).
- Учёт usage суммаризатора: в v1 он в сумму сессии не входит (design.md change `add-usage-extension`, D4 п. 6, R2) и этот change его не меняет (D7).
- Промпты сжатия, длина резюме, алгоритм точки среза.
- Структурный движок (§17.13.4) — после MVP; его документ только ссылается на ту же оценку.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `agent-compaction`:
  - ADDED «Согласованная оценка после сжатия»;
  - ADDED «Сжатие без выигрыша не применяется»;
  - MODIFIED «Запись сжатия и пересборка» — `tokensAfter` по согласованной оценке, шаг «нет выигрыша», лог `compaction.skipped` для обеих причин, «до» следующего прохода, CMP-5 по `max(after, H(после))`.

`agent-slash-commands` не меняется: требование «Встроенные команды MVP» уже отвечает на любой `NothingToCompact` текстом `Nothing to compact.`. `agent-loop` не меняется: `ContextCompacted` по-прежнему означает «сжатие записано», `null` от `emergencyCompact` — «сжатие не помогло».

## Impact

- Код: только `packages/dart/codelab_agent_core` — `lib/src/compaction/estimate.dart` (функция согласованной оценки, внутренняя), `lib/src/compaction/compactor.dart`. Публичный барель, `pubspec.yaml`, граф пакетов, правила сторожа не меняются.
- Тесты ядра: новые в `test/compaction/compactor_test.dart`, `test/compaction/estimate_test.dart`, `test/compaction/overflow_then_compact_test.dart`, `test/runtime/builtin_slash_commands_test.dart`, интеграционный тест аварийного пути с малым окном и длинным промптом (D9); переписываются тесты, где проход не даёт выигрыша, — по CMP-10 такой проход больше не записывается:
  - `compactor_test.dart` «a second pass runs while the estimate is above the threshold» и `skills_reattach_test.dart` «without the skills message above the threshold…» — резюме специально длиннее региона;
  - `overflow_then_compact_test.dart` «core/overflow-triggers-compaction: overflow → compaction → retry» — исходный регион из двух ходов (в резюме уходило одно короткое сообщение пользователя) выигрыша не давал; тест переведён на три хода: срез проходит внутри предыдущего хода, регион — первый ход целиком, начало хода резюмируется вторым запросом суммаризатора (§9.6), проверяемое поведение «overflow → сжатие → повтор» сохраняется.
- Фикстуры ACP: не меняются; числа `Compacted: X → Y` нормализуются, неравенство `context.used` в `usage_projection_test.dart` (`codelab_agent_acp`) сохраняется (design.md, D8).
- Клиенты, desktop, CLI: без изменений кода; пользователь видит согласованные числа в ответе `/compact` и в индикаторе контекста.
