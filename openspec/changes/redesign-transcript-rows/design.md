## Context

Лента сейчас — `CodeLabTranscriptPanel` над списком `CodeLabTranscriptEntry` с пятью видами (`user`, `agent`, `toolCall`, `approval`, `diagnostic`). Каждая запись рисуется одной и той же строкой `_AcpTranscriptEntryRow`: цветной фон по виду, иконка, заголовок, тело. Маппер `transcriptEntriesOf` в `ui_mappers.dart` сводит `ThoughtItem` в тот же вид `agent`, что и ответ, поэтому мысли неотличимы от ответа. Вызов инструмента показывает заголовок агента и вложенный `CodeLabToolCallSummary` с сырым `kind.wireName` и словом статуса.

Целевая модель уже описана в документах:

- `dart-agent-and-clients` §12.1.2 и §12.1.6 — поля вызова в модели ядра и `ToolRowFormatter`;
- §12.3.2 — запечатанная модель строк ленты (`AcpTranscriptRow` и наследники) и `TranscriptViewCubit`;
- §12.3.3 A1 и A6 — маппинг с переиспользованием строк и блок мыслей;
- §12.3.5 DSK-1, DSK-4, DSK-10.

Документ называет компоненты с префиксом `Acp`; в `codelab_ui` после переименования пакетов принят префикс `CodeLab` (ADR-0002).

Сверка с артбордами Main, Turn, States и Ask 27 октября 2026 года — источник визуальных решений: колонка 760 px, пузырь пользователя, строка вызова, карточка одобрения.

## Goals / Non-Goals

**Goals:**

- Лента читается как переписка: пузырь пользователя, ответ без карточки, колонка по центру.
- Мысли — отдельный сворачиваемый блок по DSK-10.
- Вызов инструмента — одна строка без сырого JSON по §12.1.6; статус «Awaiting approval», пока вызов ждёт одобрения.
- Карточка одобрения по макету без изменения поведения одобрений и сочетаний клавиш.
- Заметки по тяжести; информационные заметки не выглядят ошибкой.
- Чип состояния хода в шапке; пустая сессия при соединении без карточки подключения.
- Модель строк, на которую следующие change положат markdown и diff, не переделывая ленту.

**Non-Goals:**

- Markdown, блоки кода и «Copy reply» (D-06) — change `add-transcript-markdown`. Здесь ответ агента остаётся простым текстом в строке `CodeLabAgentTextRow`.
- Diff в строке правки и в карточке одобрения (D-07) — этап 9+.
- Время в строке вызова и в блоке мыслей («Done · 0.1 s», «Thoughts · 6 s»). Время ставилось бы по часам клиента при инкрементальной проекции, а проекция с нуля его не знает — это ломает свойство «инкрементально = с нуля» (`acp-client-kit`). Нужно отдельное решение о времени в модели.
- Уточнение статуса по `_meta.codelab.outcome` (`rejected`, `interrupted`, §12.1.2 шаг 1) — отдельный change вместе с расширением фикстур.
- Метка `Task` для `think` с `rawInput.agent` — вместе с доской субагентов (A15).
- Скрытие вызова `update_plan` из ленты: в ACP нет признака «вызов публикует план»; угадывать по имени инструмента нельзя (AGENTS.md §3.4).
- Композер, строка состояния, полоса плана над композером — change `redesign-prompt-composer`.
- Steer и пузырь «during turn» — нет метода в ACP, нужна спецификация.
- Разделитель компактизации — клиент не получает события компактизации.

## Decisions

### D1. Запечатанная модель строк в `codelab_ui` вместо `CodeLabTranscriptEntry`

`codelab_ui` получает `sealed class CodeLabTranscriptRow { String get id; }` и наследников:

| Строка | Поля | Из чего строится |
|---|---|---|
| `CodeLabUserRow` | `text` | `UserItem` |
| `CodeLabAgentTextRow` | `text` | `AgentTextItem` |
| `CodeLabThoughtRow` | `text`, `streaming` | `ThoughtItem` |
| `CodeLabToolCallRow` | `status`, `label`, `detail`, `secondary`, `output`, `approval` | `ToolCallItem` + `ToolRowView` |
| `CodeLabNoticeRow` | `severity`, `title`, `body`, `details`, `action` | `NoticeItem` |

`CodeLabTranscriptEntry` и `CodeLabTranscriptEntryKind` удаляются. Существующие `CodeLabTranscriptApproval`, `CodeLabApprovalOutcome` и `CodeLabTranscriptEntryAction` (переименуется в `CodeLabTranscriptAction`) остаются.

Почему не расширять `CodeLabTranscriptEntry` полями: пять видов с разными полями в одном классе дают невозможные сочетания (одобрение у заметки, `streaming` у пользователя). Запечатанная иерархия — то, что зафиксировано в §12.3.2, и markdown change заменит `CodeLabAgentTextRow` на блоки, не трогая остальные строки.

Альтернатива — переходный конструктор `CodeLabTranscriptPanel.entries` из §12.3.2. Отклонена: потребители ленты — только desktop и превью, их проще перевести за один change, чем держать два входа.

### D2. `ToolRowFormatter` — в ядре клиента, без времени

`ToolRowFormatter.format(ToolCallItem item, {required String cwd}) → ToolRowView` живёт в `codelab_client_core` (VIEW-2: модели отображения общие для app и CLI). Правила метки и детали — таблица §12.1.6 без поля `elapsed` (Non-Goals).

`ToolCallView` получает поля:

- `rawInput` — `Map<String, Object?>?` как пришёл;
- `paths` — `List<String>` из `locations[].path`;
- `textOutput` — `List<String>`: тексты элементов `content` с текстовым блоком в порядке прихода.

Маскирование секретов — существующий `SecretRedactor` из `codelab_client_acp`. Путь внутри `cwd` — относительный; замена домашнего каталога на `~` из §12.1.2 шаг 3 откладывается: kit не знает домашний каталог, а composition root его пока не передаёт.

### D3. Состояние раскрытия — в `TranscriptViewCubit`, а не в `State` виджета

Строки ленты виртуализированы и уничтожаются при уходе с экрана, поэтому выбор пользователя в `State` теряется (§12.3.2). `TranscriptViewCubit` в desktop хранит `Map<String, bool> expansionOverrides` по сессиям; ключ — id строки. Раскрытие по умолчанию вычисляет лента:

| Строка | `summary` | `normal` | `verbose` |
|---|---|---|---|
| мысли во время стрима | заголовок | раскрыт | раскрыт |
| мысли после стрима | заголовок | свёрнут | раскрыт |
| вызов с ожидающим одобрением | раскрыт | раскрыт | раскрыт |
| остальные вызовы | свёрнут | свёрнут | раскрыт |

Ручной выбор из `expansionOverrides` побеждает всё, кроме ожидающего одобрения: карточку одобрения свернуть нельзя, иначе пользователь потеряет кнопки решения.

`viewMode` остаётся там, где он сейчас; `TranscriptViewCubit` не забирает его — это отдельная правка без пользы для этого change.

### D4. «Мысли стримятся» — вычисляется маппером

Ядро не публикует флаг «элемент открыт». Маппер считает `ThoughtItem` стримящимся, если это последний элемент транскрипта и сессия в статусе `running`. Как только после мыслей приходит ответ, вызов или ход заканчивается, флаг снимается, и блок сворачивается (DSK-10). Отдельное поле в модели ядра не вводится: условие выводится из уже опубликованных данных.

### D5. Строка вызова и карточка одобрения

Строка — один `Row`: значок статуса (`ProgressRing` для `running`, галочка, крестик, отмена, точка для `queued`), метка жирным, деталь моноширинным с многоточием, тег статуса справа и шеврон, если есть что раскрывать. Тег «Awaiting approval» вычисляет маппер: у вызова есть ожидающее одобрение — статус вызова не важен.

Карточка одобрения — переработанный `CodeLabApprovalPanel` в режиме «в строке вызова»:

- заголовок по виду вызова — таблица из спецификации;
- риск — тегом в заголовке карточки, а не отдельным чипом под строкой;
- команда — моноширинный блок на тёмном фоне, `cwd` — подписью под ним;
- `allow_once` — `FilledButton`, остальные варианты — `Button`; подсказки сочетаний — подписью на кнопках, как сейчас.

Поведение одобрений (`onOptionSelected`, сочетания, автопрокрутка к новому одобрению, «View raw input») не меняется. Тест сочетаний переносится без изменения ожиданий.

### D6. Заметки по тяжести

`NoticeKind` → `CodeLabNoticeSeverity`:

| `NoticeKind` | Вид |
|---|---|
| `error` | InfoBar ошибки с заголовком класса сбоя, Details и Retry (без изменений) |
| `detached` | InfoBar предупреждения |
| `reconnected`, `emptyTurn` | нейтральная строка с иконкой info |

Тон определяется видом заметки, а не текстом.

### D7. Пустая сессия и шапка

`main_pane.dart` показывает `CodeLabConnectionScreen`, только пока соединение не `connected`. При соединении и пустой ленте — пустое состояние ленты с подсказкой «Send a message to start», фокус в композере.

Чип состояния хода в `CodeLabSessionPaneHeader` строится из `SessionView.status` и наличия ожидающих одобрений: `running` → «Turn running» или «Waiting for approval», `cancelling` → «Cancelling…».

## Risks / Trade-offs

- **Объём переноса тестов.** `widget_test.dart` и e2e ищут записи по тексту «Agent», «You» и по ключам `CodeLabTranscriptEntry`. → Новые ключи строк по id (`transcript-row-<id>`), перенос — отдельная группа задач; e2e на устройстве не запускаются в `feature/*` (§21), их правка проверяется компиляцией и Dart VM.
- **Пузырь пользователя и длинный текст.** Многострочный промпт в пузыре 78 % хуже читается в узком классе. → В классах `narrow` и `phone` пузырь занимает до 90 %; тест 390 px без переполнения.
- **Свёртывание мыслей у читающего пользователя.** Высота строки меняется, когда ответ начинается. → Без анимации (DSK-10, §12.3.6), и следование за хвостом уже держит низ ленты.
- **Нет времени в строке.** Строка беднее макета («Done · 0.1 s»). → Записано в Non-Goals с причиной; добавится вместе с решением о времени в модели.

## Migration Plan

Одним change, без флага: старая лента удаляется вместе с введением новой. Сохранённого состояния нет — `expansionOverrides` живут в памяти до закрытия окна. Откат — revert merge-коммита.
