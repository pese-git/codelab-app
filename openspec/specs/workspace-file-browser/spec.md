# workspace-file-browser Specification

## Purpose
Браузер файлов проекта в десктопном app: панель Files в доке инструментов, ограниченная рабочей папкой сессии, с ленивым перечислением папок, просмотром файла только для чтения и предупреждением для файлов, похожих на секреты. Требования введены change `add-file-preview-and-tree`.
## Requirements
### Requirement: Панель Files в доке инструментов
CodeLab SHALL предлагать панель Files в доке инструментов справа (`dart-agent-and-clients` §12.3 A13, шаг 0) только когда папка сессии находится на этой машине: подключение — встроенный агент или stdio-профиль, и хост предоставил порт `ProjectFiles`. Для WebSocket-профилей, в web и на устройствах без локальной папки панель НЕ SHALL предлагаться: у неё нет переключателя в app bar, пункта палитры и сочетания. Корень дерева SHALL быть папкой сессии в фокусе (`cwd` сессии), а без сессии и для сессии, не загруженной в текущем соединении (`detached` или `notLoaded`), — папкой выбранного проекта. Если `cwd` сессии вне папки проекта — по realpath: realpath корня не равен realpath папки проекта и не начинается с него и разделителя, либо папка проекта не разрешается, — дерево SHALL работать от `cwd`, а над ним SHALL показываться абсолютный корень с пометкой «outside the project folder»; абсолютный путь НЕ SHALL попадать в логи выше уровня debug. Отказ корня SHALL различать «The project folder does not exist.» (нет папки) и «The project folder cannot be read.» (прочие отказы). Пока панель недоступна, браузер НЕ SHALL обращаться к диску (ни корень, ни перечисление, ни чтение) и НЕ SHALL писать событий отказа корня; при возврате доступности корень SHALL перечитываться. Панель SHALL открываться и закрываться переключателем Files в app bar, сочетанием Cmd/Ctrl+Shift+E и пунктом «Files» палитры, который есть, только когда панель доступна. Внутри панели сверху SHALL быть дерево, снизу — просмотр выбранного файла; сайдбар сессий слева при этом НЕ SHALL меняться (design.md change `add-file-preview-and-tree`, D6, D7, Q8, Q10, Q13, Q17–Q19).

#### Scenario: Открытие панели для встроенного агента
- **WHEN** окно подключено к встроенному агенту, в фокусе сессия с `cwd` `/work/app`, и пользователь нажимает Cmd/Ctrl+Shift+E
- **THEN** в доке открывается и становится активной вкладка Files с деревом `/work/app`, а сайдбар сессий остаётся на месте

#### Scenario: Повторное сочетание закрывает панель
- **WHEN** панель Files активна, и пользователь снова нажимает Cmd/Ctrl+Shift+E
- **THEN** вкладка Files закрывается

#### Scenario: Нет панели для WebSocket-агента
- **WHEN** текущий профиль окна — WebSocket-профиль
- **THEN** переключателя Files в app bar и пункта «Files» в палитре нет, а Cmd/Ctrl+Shift+E не открывает панель

#### Scenario: Корень без сессии
- **WHEN** выбран проект `/work/app`, но ни одной сессии ещё нет
- **THEN** панель Files показывает дерево `/work/app`

#### Scenario: Сессия из прежнего соединения
- **WHEN** выбран проект `/work/app`, а в фокусе сессия в состоянии `detached` с `cwd` `/srv/remote/app`, оставшаяся от прежнего WebSocket-соединения, и окно теперь подключено к встроенному агенту; либо в фокусе сессия `notLoaded` с тем же `cwd`
- **THEN** в обоих случаях панель Files показывает дерево `/work/app`

#### Scenario: Корень вне папки проекта
- **WHEN** выбран проект `/work/app`, а агент объявил для сессии в фокусе `cwd` `/work/other`
- **THEN** панель показывает дерево `/work/other`, над ним — `/work/other` с пометкой «outside the project folder», а журнал выше уровня debug не содержит `/work/other`

#### Scenario: Путь проекта с `..` или ссылкой наружу
- **WHEN** выбран проект `/work/app`, а `cwd` сессии — `/work/app/../other` или `/work/app/link`, где `link` — ссылка на `/work/other`
- **THEN** в обоих случаях над деревом показана пометка «outside the project folder»

#### Scenario: Одна папка под двумя путями
- **WHEN** выбран проект `/tmp/w`, а `cwd` сессии — `/private/tmp/w` (на macOS это одна папка)
- **THEN** пометки «outside the project folder» нет

#### Scenario: WebSocket: никакого обращения к диску
- **WHEN** текущий профиль окна — WebSocket-профиль, затем окно переключается на встроенного агента
- **THEN** пока профиль WebSocket, порт `ProjectFiles` не вызывается и событий `project_files.root_unavailable` нет, а после переключения корень читается заново

#### Scenario: Папка проекта не читается
- **WHEN** корень существует, но `canonicalRoot` отказывает по правам доступа
- **THEN** панель показывает «The project folder cannot be read.», а не «The project folder does not exist.»

#### Scenario: Смена сессии в фокусе
- **WHEN** панель Files открыта для сессии с `cwd` `/work/a`, и фокус переходит на сессию с `cwd` `/work/b`
- **THEN** панель показывает дерево `/work/b`, а результаты чтения `/work/a`, пришедшие позже, состояние не меняют

### Requirement: Граница рабочей папки браузера
Каждая операция браузера SHALL проверять путь до чтения содержимого или перечисления папки: относительный путь с `\0`, абсолютный или с `..`, поднимающимся выше корня, SHALL отклоняться как `invalidPath` ещё до обращения к диску; путь, чей realpath не равен realpath корня и не лежит внутри него, SHALL отклоняться как `outsideRoot`. Если цель не разрешается (любая ошибка разрешения), путь SHALL проходиться от корня без перехода по ссылкам: ссылка, чей realpath не разрешается или разрешается вне корня, либо ближайший разрешимый предок вне корня SHALL давать `outsideRoot`, иначе — исходную ошибку; ответ НЕ SHALL раскрывать, существует ли и доступен ли файл вне корня (Q16). Символическая ссылка с целью вне корня SHALL показываться строкой с пометкой ↗ и НЕ SHALL раскрываться, открываться в просмотре или служить целью «Open file». Чтение браузера — действие клиента, а не агента: оно НЕ SHALL запрашивать одобрение и НЕ SHALL идти через ACP `fs/*` (design.md change `add-file-preview-and-tree`, D3, Q2, Q16; UX-15).

#### Scenario: Ссылка наружу видна, но не открывается
- **WHEN** в корне лежит символическая ссылка `secrets` на `/etc`, и пользователь выбирает её и нажимает Enter или →
- **THEN** строка `secrets` показана с ↗, папка не раскрывается, просмотр не открывается, а `/etc` не перечисляется и не читается

#### Scenario: Выход через `..` отклоняется до чтения
- **WHEN** порт `ProjectFiles` получает запрос чтения `../outside.txt`
- **THEN** результат — `ProjectFilesFailure` вида `invalidPath`, и файл вне корня не открывается

#### Scenario: Битая ссылка наружу неотличима от рабочей
- **WHEN** в корне ссылка `gone` на несуществующий путь вне корня и ссылка `real` на существующий файл вне корня
- **THEN** обе показаны с ↗ и не открываются, а порт на чтение обеих отвечает одинаковым `outsideRoot`

#### Scenario: Ссылка внутри корня работает
- **WHEN** в корне лежит ссылка `docs` на папку `doc` того же корня
- **THEN** `docs` раскрывается как обычная папка

### Requirement: Ленивое перечисление папок
Браузер SHALL читать только корень и раскрытые папки, по одному уровню, без рекурсии. Записи SHALL идти сначала папками, затем файлами, по имени без учёта регистра. Записей больше 5000 в одной папке НЕ SHALL показываться: вместо них — строка «… N more». Запись `.git` НЕ SHALL показываться никогда, остальные скрытые записи SHALL показываться. Дерево SHALL быть виртуализированным: строятся только видимые строки и запас. Ошибка чтения папки SHALL показываться строкой под этой папкой, не ломая остальное дерево. Кнопка «Refresh» SHALL перечитывать раскрытые папки и выбранный файл (design.md change `add-file-preview-and-tree`, D6, Q4, Q9; UX-16).

#### Scenario: Раскрытие папки читает один уровень
- **WHEN** пользователь раскрывает папку `lib`
- **THEN** выполняется ровно одно перечисление `lib`, вложенные папки `lib` не читаются

#### Scenario: `.git` скрыт, скрытые файлы видны
- **WHEN** в корне лежат `.git`, `.github` и `.env`
- **THEN** дерево показывает `.github` и `.env`, а `.git` нет

#### Scenario: Большая папка
- **WHEN** в папке 10 000 файлов
- **THEN** показано 5000 записей и строка «… 5000 more», а построено не больше видимых строк и запаса

#### Scenario: Refresh показывает новый файл
- **WHEN** агент создал `lib/b.dart` в раскрытой папке `lib`, и пользователь нажимает «Refresh»
- **THEN** строка `lib/b.dart` появляется, раскрытые папки остаются раскрытыми

### Requirement: Просмотр файла только для чтения
Выбор файла в дереве (клик или Enter) SHALL открывать его просмотр внизу панели: текст UTF-8 с номерами строк, неверные байты — символом замены. Файл с байтом NUL в первых 8 КиБ SHALL показываться пометкой «Binary file (N KB)», файл больше 1 МиБ — пометкой «File too large to preview (N MB)» вместо содержимого. Просмотр НЕ SHALL позволять редактировать или сохранять файл. Результат чтения файла, который уже не выбран, SHALL отбрасываться. HTML SHALL показываться исходным текстом. Над просмотром SHALL показываться относительный путь выбранного файла от корня (POSIX-разделители) и действие «Copy path», которое SHALL копировать в буфер обмена этот относительный путь и НЕ SHALL копировать содержимое файла или абсолютный путь (design.md change `add-file-preview-and-tree`, D4, D6, D13, Q5, Q14).

#### Scenario: Текстовый файл
- **WHEN** пользователь выбирает `lib/a.dart` из трёх строк
- **THEN** просмотр показывает три строки с номерами 1–3, а поля ввода и действия записи нет

#### Scenario: Двоичный файл
- **WHEN** пользователь выбирает файл, в первых 8 КиБ которого есть байт NUL
- **THEN** просмотр показывает «Binary file» с размером и не показывает содержимое

#### Scenario: Слишком большой файл
- **WHEN** пользователь выбирает текстовый файл размером 3 МиБ
- **THEN** просмотр показывает «File too large to preview (3 MB)» и не показывает содержимое

#### Scenario: Copy path копирует относительный путь
- **WHEN** открыт просмотр `lib/src/a.dart` в корне `/work/app`, и пользователь выбирает «Copy path»
- **THEN** над просмотром показан путь `lib/src/a.dart`, а буфер обмена содержит ровно `lib/src/a.dart` — без `/work/app` и без текста файла

#### Scenario: Поздний результат чтения
- **WHEN** пользователь выбирает `a.txt`, затем, до окончания чтения, `b.txt`, и чтение `a.txt` завершается последним
- **THEN** просмотр показывает `b.txt`

### Requirement: Предупреждение для файлов с секретами
Просмотр файла, имя которого без учёта регистра совпадает с шаблонами `.env*`, `*.pem`, `*.key` или `id_*` (правило `isMaybeSecretFileName` kit, Q15), SHALL показывать содержимое как есть вместе с предупреждением «This file may contain secrets.». Содержимое любого просматриваемого файла НЕ SHALL попадать в логи, диагностику, события и снимок рабочего места (design.md change `add-file-preview-and-tree`, D5, Q3).

#### Scenario: Открытие `.env`
- **WHEN** пользователь выбирает `.env` со строкой `API_KEY=test-marker`
- **THEN** просмотр показывает строку и предупреждение «This file may contain secrets.», а журнал и диагностика окна не содержат `test-marker`

#### Scenario: Имя секрета без учёта регистра
- **WHEN** пользователь выбирает `Server.PEM`
- **THEN** просмотр показывает предупреждение «This file may contain secrets.»
