# Сайт CodeLab

Сайт — статический Astro-проект в `site/` (ADR-0003, `docs/architecture/adr/0003-build-project-site-with-astro-in-monorepo.md`). Решения и их обоснование — `openspec/changes/archive/2026-11-18-add-astro-site/design.md`, витрина и демо — `openspec/changes/archive/2026-11-26-redesign-site-showcase/design.md`, и спецификация `project-site`. Этот skill — рабочие правила; при расхождении с design.md правда за design.md, а skill исправляется.

Язык текстов и проверка фактов — по `.claude/skills/codelab-docs/SKILL.md` §4 и §8. Здесь они не пересказываются.

## 1. Разделы и адреса (D4, D9)

| Адрес | Что | Источник текста |
|---|---|---|
| `/` | главная, секции по порядку (redesign-site-showcase D1): первый экран с бейджами и живым макетом → «Один агент — три клиента» → «Как это работает» → продукты → возможности → «Ваш код и ключи» → снимки → установка → новости | `site/src/pages/`, `src/components/showcase/`, данные `src/lib/showcase/` |
| `/features/app/`, `/features/cli/`, `/features/agent/` | возможности CodeLab app, `codelab`, `codelab-agent`; в начале — одно демо (макет, клавиши ответа, режимы разрешений), ниже список `Feature` | `site/src/pages/` + снимки из `apps/*/doc/images/` |
| `/og.png`, `/apple-touch-icon.png` | картинка для ссылок 1200×630 и значок 180×180, растеризуются при сборке из `docs/design/brand/` | `src/pages/*.png.ts` |
| `/docs/` | оглавление документации по ролям (improve-docs-navigation D6) | `src/lib/nav.ts`, `src/lib/docs-index.ts` |
| `/docs/<путь>/` | документ из репозитория | коллекция `docs` |
| `/news/`, `/news/<version>/` | новости выпусков | коллекция `news` |
| `/404.html` | «не найдено» | `site/src/pages/404.astro` |

- Адрес документа выводится из пути файла механически: префикс `docs/` у `docs/*` не дублируется, `README.md` даёт адрес каталога, регистр и подчёркивания сохраняются, конечный слэш всегда. `apps/codelab_cli/doc/user-guide.md` → `<base>docs/apps/codelab_cli/doc/user-guide/`.
- Все внутренние адреса строятся через `withBase` (`src/lib/urls.ts`). Жёстко прописанный `/docs/…` ломает сборку в подкаталоге.
- «Установка и быстрый старт» — пункт меню на страницу `docs/user/run-from-source.md`. Своей копии команд у сайта нет.
- Группы навигации — по пути (`docs/user/**` → «Пользователю», `docs/ops/**` → «Эксплуатация», `apps/codelab_desktop/**` → «CodeLab app», `apps/codelab_cli/**` → «`codelab`», `apps/codelab_agent/**` → «`codelab-agent`», `packages/**` → «Пакеты»). Неизвестный каталог приложения получает группу с именем каталога, а не ошибку. Пустая группа не показывается.
- **Секции и списки внутри группы** (improve-docs-navigation D2, D3) — тоже по пути, без ручных списков:
  - приложение: вход (`README.md`, `doc/README.md`) → «Руководство» (`doc/user-guide.md`, `doc/user/**`) → «Эксплуатация» (`doc/operations.md`) → «Для разработчика» (остальное в `doc/`);
  - вложенный каталог в `doc/` — своя подгруппа с заголовком его `README.md` (без README — имя каталога);
  - пакет — отдельная секция, в меню страницы пакета только его документы;
  - слой пакета по имени (ADR-0002): `codelab_*_tests` → «Проверки» (раньше префиксов), `codelab_acp_*` → «Протокол ACP», `codelab_client_*` → «Клиент», `codelab_agent_*` → «Агент», остальные `packages/dart/*` → «Мосты и служебные пакеты», `packages/flutter/*` → «Интерфейс Flutter», прочее → «Другие пакеты» без ошибки.
- **Порядок в списке** (D1): входной документ → главы по префиксу `NN-` (числами, номер показывается в меню: «03 · Заголовок») → документы без номера по заголовку, затем по пути. Номер в `<h1>`, `<title>` и описании не появляется. Повторённый номер или документ без номера — не ошибка сборки.
- **Страница документа** (D4, D5): крошки «Документация › группа › пакет › подгруппа» (без ссылки на текущую страницу; «Пакеты» → `/docs/#packages`), «Назад / Далее» с `rel="prev|next"` только внутри одного списка. Меню выводится одним компонентом дважды: колонкой от 900 px и свёрнутым `<details>` «Документы раздела (N)» перед статьёй уже 900 px; на широком экране раскрыта только подгруппа текущего документа.
- **Оглавление `/docs/`** (D6) — по ролям: «Начать работу», «Пользоваться», «Развернуть и разрабатывать»; главы приложений свёрнуты в «Главы (N)»; пакеты — по слоям: ссылка на README с описанием; у пакета с `doc/` — ещё видимая ссылка на вход руководства и свёрнутые «Главы (N)» с документами `doc/` по D1, вложенные каталоги — вложенными `<details>` со своим «Обзором». Вход берётся только из основного списка: `doc/README.md` (подпись — его заголовок), иначе первая глава верхнего уровня (подпись «00 · Заголовок»); при пустом основном списке видимого входа нет. Пакет без README ведёт ссылкой карточки на вход руководства; пакет без `doc/` — одна ссылка. Каждый документ в оглавлении один раз. Якоря латиницей: `start`, `use`, `build`, `packages`, `packages-<слой>`. Путь страницы установки — одна константа `installDocPath` (`src/lib/nav.ts`).

## 2. Тон главной и страниц возможностей

Главная и страницы возможностей — витрина, но правила `codelab-docs` §4 (язык) и §8 (проверка фактов) действуют полностью.

- Каждое утверждение о продукте проверяемо по коду или документации. Нельзя проверить — не пишется.
- Описывается то, что есть в `develop` сейчас. Без «скоро», «будет», «в планах», «до выпуска 1.0 появится».
- Без оценочных слов: «мощный», «удобный», «революционный», «лучший», «молниеносный», «умный», «бесшовный».
- Возможность — это действие пользователя и результат: «Агент спрашивает разрешение перед записью файла, вы отвечаете одной клавишей», а не «продвинутая система разрешений».
- 3–6 возможностей на продукт, каждая со ссылкой на раздел руководства, где она описана подробно.
- Строки демо и фактов не набираются руками («один факт — одно место»): каждая строка — один из видов ниже, рассинхрон с источником ломает сборку (redesign-site-showcase D6). PNG берутся из `apps/*/doc/images/` через `astro:assets`, без копий.
- Внутренние имена пакетов и классов на витрине не используются: «встроенный агент», а не `codelab_embedded`.

| Вид | Что это | Источник |
|---|---|---|
| `ui(каталог, ключ)` | строка интерфейса app | ключ `*.arb` (`codelab_ui_ru.arb`, `app_ru.arb`) |
| `quote(документ, текст)` | короткая цитата: клавиша, имя режима, строка таблицы | опубликованный документ, совпадение с нормализацией пробелов |
| `snippet(документ#якорь, n)` | текстовый снимок терминала | n-й блок кода раздела, как есть |
| `example(текст)` | промпт, ответ модели, файл | пишется в данных; под демо подпись «пример» |
| `docRef(документ#якорь)` | «подробнее» | обязателен у каждого шага, факта и демо |

- Источники закрыты списком `showcaseSources` (`src/lib/showcase/sources.ts`): опубликованные документы, два каталога `*.arb`, изображения `apps/*/doc/images/**` и `docs/design/brand/**`. Исходники Dart в список не входят: строки, которой нет в каталоге или документе, сначала документирует `docs-writer`.
- **Гарантия — вместе с ограничением** тем же абзацем (D8): «файловые инструменты только в папке проекта» — рядом «для команд ограничен каталог запуска»; «без вопроса не правит» — рядом «`bypass` и `autopilot` не спрашивают».
- **Чужие интерфейсы не изображаются** (D4): вкладка Zed — нейтральная схема и ссылка на `docs/user/zed.md`, не макет Zed.
- Демо не отвечает за посетителя: автопроигрывание останавливается на запросе разрешения.

Факты витрины проверяет `docs-writer` (задача вида 6.1), правки страниц вносит `site-engineer`.

## 4. Загрузка документации (D3, D5, D11)

- **Allowlist, а не denylist.** Публикуется только то, что перечислено в одной константе `src/lib/publish.ts`: `docs/user/**/*.md`, `docs/ops/**/*.md`, `apps/*/README.md`, `apps/*/doc/**/*.md`, `packages/*/*/README.md`, `packages/*/*/doc/**/*.md`. `AGENTS.md` исключён везде. Не публикуются: `openspec/`, `docs/architecture/`, `docs/protocols/`, `docs/backlog/`, `docs/design/`, `docs/integrations/`, `docs/codelab-spec.md`, `CHANGELOG.md`. Новый источник добавляется осознанно: строка в константе + строка в спецификации `project-site`.
- **Документы не правятся под сайт.** Frontmatter не нужен. Заголовок страницы — первый `#` (нет — ошибка сборки с путём), описание — первый абзац.
- **Ссылки** в документах — относительные пути репозитория (`codelab-docs` §3). Плагин `repoLinks`:
  - опубликованный файл → адрес сайта (с якорем);
  - неопубликованный файл → `<repoUrl>/blob/<repoRef>/<путь>`, каталог → `tree`;
  - изображение остаётся относительным и обрабатывается `astro:assets`; пустой `alt` — ошибка;
  - несуществующий файл, выход за корень, абсолютный путь, `file:`, другой регистр имени — ошибка с путём документа и строкой;
  - `http(s):`, `mailto:`, чистый `#якорь` не меняются.
- **`repoRef`**: `SITE_GITHUB_REF` → `GITHUB_SHA` → `git rev-parse HEAD` → ошибка сборки. Окончательная цель выбирается вместе с хостингом.
- **Ошибки сборки, которые чинятся в документе, а не в сайте:** битая ссылка, якорь, регистр; сырой HTML вне `details`, `summary`, `br`, `kbd`, `sub`, `sup` или с атрибутами (кроме `open` у `details`); личный путь (`/Users/<имя>/`, `/home/<имя>/`, `C:\Users\<имя>\`, кроме масок `user` и `me`). Чинит `docs-writer` в том же pull request; отключать проверку ради merge нельзя.
- `vite.server.fs.allow` разрешает корень репозитория: публикацию ограничивает allowlist загрузчика, а не файловый доступ.

## 5. Новости выпусков (D10)

- Файл `site/src/content/news/<version>.md`. Схема: `title`; `date` (`YYYY-MM-DD`); `version` (`MAJOR.MINOR.PATCH[-pre]`); `summary` (до 200 символов). Неполная запись и повтор `version` — ошибки сборки.
- Порядок — по `date`, затем по `version`, от новой к старой; на главной три последние; без новостей — пустое состояние, а не ошибка.
- **Кто и когда:** `docs-writer` в ветке `release/<version>`, после того как написан раздел выпуска в корневом `CHANGELOG.md`. Источники фактов — этот раздел и `proposal.md` архивированных changes выпуска. `CHANGELOG.md` `docs-writer` читает, но не пишет.
- **Текст:** что изменилось для пользователя, 3–7 пунктов, у каждого — ссылка на документ сайта; ссылка на раздел `CHANGELOG.md` на GitHub. Правила раздела 2 действуют: без обещаний следующего выпуска.
- Ссылки в новости — адреса сайта от корня без `base`: `/docs/user/configuration/`. `base` добавляет плагин `news-base` (D10, D12); схемы — только `http:`, `https:`, `mailto:`. Итоговые адреса проверяет `check-links`, а не `repoLinks`. Локально проверяй при обоих base: `npm run verify` и `SITE_BASE=/codelab-app/ npm run verify`.
- Пример новости живёт только в фикстуре тестов, не в `src/content/news/`.

## 6. Производительность

- Статический HTML и CSS. UI-фреймворки (React, Vue, Svelte), CSS-фреймворки (Tailwind), интеграции Astro (MDX, sitemap) не добавляются.
- **Встроенный скрипт один** — тема в `<head>`, текст одинаков на всех страницах (под хэш CSP). Встраивание модулей Vite запрещено (`vite.build.assetsInlineLimit` функцией в `astro.config.mjs`); атрибутов `on*` нет. Проверяет `check-links`.
- `mermaid` грузится лениво (`import('mermaid')`) только на страницах с `[data-mermaid]`.
- **Скрипты витрины** (redesign-site-showcase D2) — `<script>` в компонентах `src/components/showcase/`, собираются Vite в `/_astro/*.js` и попадают только на страницы с демо. Логика — конечные автоматы в `src/lib/showcase/` без `document`, таймеры через переданный планировщик, покрыты vitest. DOM-слой `src/scripts/showcase/` только связывает автомат с разметкой (образец `theme.ts`/`theme-state.ts`). Без UI-фреймворков, без новых зависимостей, без `eval`, `new Function`, `innerHTML` со строками сценария.
- **Скрипты страниц документации** (improve-docs-navigation D7) — по тому же правилу: кнопка копирования кода (создаётся скриптом, без JS её нет; номер нажатия против позднего таймера) и подсветка «На этой странице» (`aria-current="location"`, от 1200 px). Логика — `src/lib/doc-page/`, DOM-слой — `src/scripts/doc-page/`.
- **Поиск** (D8, D13) — Pagefind: индекс строит `pagefind --site dist` после `astro build`, индексируется только `<article data-pagefind-body>` страниц документов; `data-pagefind-meta` несёт только `group:<название>` (для пакета — имя пакета). Следом шаг `scripts/prune-pagefind.mjs` удаляет неиспользуемые файлы готового UI Pagefind (`pagefind-ui.*`, `pagefind-modular-ui.*`, `pagefind-component-ui.*`, `pagefind-highlight.js`) — только по закреплённым именам внутри `dist/pagefind`. Интерфейс свой (`DocSearch`, `src/lib/doc-page/search.ts`): форма `hidden` в разметке, рантайм `pagefind/pagefind.js` грузится динамическим `import` по первому фокусу или вводу, `baseUrl` учитывает `SITE_BASE`, ответ устаревшего запроса не рисуется, подсветка фрагмента разбирается без `innerHTML`. Статических ссылок на `pagefind/` в HTML нет, отсутствие индекса — ошибка; проверяет `check-links`.
- **CSP:** Pagefind работает на WebAssembly, хостингу нужен `script-src 'self' 'sha256-<тема>' 'wasm-unsafe-eval'` (без `'unsafe-inline'` и `'unsafe-eval'`) и `worker-src 'self'`: рантайм создаёт воркер `<base>pagefind/pagefind-worker.js`. Воркер не наследует CSP страницы — его политику задают заголовки ответа на этот файл; если хостинг ставит CSP на все файлы, она обязана содержать `'wasm-unsafe-eval'`. Это принятый риск R1 и входное условие change хостинга; без директивы поиск показывает «Поиск недоступен».
- **Бюджет страницы:** JavaScript на странице — не больше 12 КБ gzip без темы, mermaid и рантайма поиска. `check-links` отличает чанки темы и mermaid по исходникам из `site/.astro/build-chunks.json` (плагин `src/plugins/build-chunks.ts`), а не по имени.
- Веб-шрифтов, CDN, аналитики и любых запросов к чужим хостам нет; `check-links` это проверяет.
- Изображения — через `astro:assets` (размеры, `loading="lazy"` ниже первого экрана).
- **Растеризация SVG** (redesign-site-showcase D10): `image.dangerouslyProcessSVG` глобально не включается. Флаг ставит только `src/lib/raster-svg.ts`, ровно для двух вызовов — `og.png.ts` и `apple-touch-icon.png.ts`, вход — только `?raw`-SVG из `docs/design/brand/`. Новый вызов `rasterizeSvg` — изменение решения D10, а не правка кода. Hex-цвета `og-card.ts` сверяются тестом с `tokens.css`.

## 7. Доступность

- `<html lang="ru">`, ссылка «к содержанию» первой в порядке фокуса.
- Контраст текста по токенам — не ниже WCAG AA (4.5:1 для обычного текста, 3:1 для крупного) в обеих темах. Новая пара цвет/фон проверяется до использования.
- Видимый фокус у всех интерактивных элементов (`:focus-visible`, цвет `--accent-text`, не убирается).
- Всё доступно с клавиатуры: меню, переключатель темы, оглавление.
- У каждого изображения смысловой `alt`; у декоративных — пустой `alt=""` и только для декоративных.
- Mermaid без JavaScript показывает исходный текст схемы (`pre[data-mermaid]`), а не пустое место.
- **Демо без JavaScript** показывают полное осмысленное состояние: сценарий целиком, оба исхода текстом, таблицы вместо вкладок. Скрипт ставит `data-live` и только тогда прячет лишнее. Кнопки, которые без скрипта ничего не делают, имеют `hidden` в разметке.
- **Движение.** При `prefers-reduced-motion: reduce` нет автопроигрывания и анимаций, состояния меняются только по действию посетителя. Автопроигрывание идёт, только пока демо видно; останавливается при наведении и фокусе; у него есть кнопка «Пауза» / «Продолжить» (WCAG 2.2.2). Анимации — только `opacity` и `transform` под `prefers-reduced-motion: no-preference`.
- **Переключатели** (клиенты, шаги, режимы) — вкладки WAI-ARIA: `role="tablist"`, стрелки, Home, End, роуминг `tabindex`.
- **Навигация документации:** меню раздела — `nav` с `aria-label`, подгруппы и мобильное меню — `<details>` (работают без JavaScript), текущий документ — `aria-current="page"`; крошки — `nav aria-label="Путь"` с `ol`; активный раздел оглавления — `aria-current="location"`. Поиск без JavaScript не показывается — остаётся ссылка на оглавление; итог поиска («Найдено: N», «Ничего не найдено», «Поиск недоступен») объявляется в `aria-live`, Esc очищает поле.
- **Меняющийся итог** (исход разрешения, ответ режима или клавиши) объявляется в `aria-live="polite"` готовой фразой, не по символам. Фокус не переносится скриптом без действия посетителя.

## 8. Зависимости и лицензии (D2)

- Markdown собирается конвейером unified (`@astrojs/markdown-remark`, `markdown.processor: unified(...)`), а не процессором Astro по умолчанию: на нём не работают плагины D5, D7, D11.
- Только npm. Точные версии (`save-exact`, проверка в `npm run verify`), `package-lock.json` коммитится вместе с `package.json`. Установка — только `npm ci`; в CI — `npm ci --ignore-scripts`.
- Прямые зависимости — минимум: `astro`, `@astrojs/check`, `typescript`, `mermaid`, `vitest`, `@types/node`, `pagefind` (devDependency, MIT; бинарь платформы приходит через `optionalDependencies`, install-скриптов нет — `npm ci --ignore-scripts` работает) и пакеты unified, которые плагины импортируют напрямую (объявляются явно). Новая зависимость — только по задаче `tasks.md`.
- Лицензии: MIT, BSD, ISC, Apache-2.0, BlueOak-1.0.0, CC0-1.0, Unlicense, 0BSD; двойная с разрешительным вариантом допустима (DOMPurify в mermaid — `MPL-2.0 OR Apache-2.0`). Проверяется при добавлении и при обновлении lock-файла.
- Copyleft без разрешительного варианта не попадает в `dist/`. Инструменты сборки, которые в `dist/` не попадают, допустимы: сейчас это `lightningcss` (MPL-2.0) и `@img/sharp-libvips-*` (LGPL-3.0) из зависимостей Astro.
- `elkjs` (`EPL-2.0 OR GPL-3.0`, из `mermaid`) из сборки исключён: раскладка ELK не регистрируется, `check-links` падает, если код `elkjs` оказался в `dist/` (D2, D7).
- Сторонний код, шаблоны и темы не копируются (`AGENTS.md` §5).
- **Исключения `--ignore-scripts`:** пока нет. Если зависимости нужен install-скрипт — запись здесь: пакет, причина, шаг `npm rebuild <пакет>` в джобе `site`.
